= adoc-epub
Paul Snow
:revnumber: 0.0.0
:description: EPUB export: a reflowable EPUB 3.3 publication written in process over the book model of adoc-ebook, with no PDF or Typst in between.

`adoc-epub` turns a rendered view tree into an EPUB publication.
It is at layer L2, beside `adoc-render` and `adoc-ebook`, which it reads.
The book model, its mapping, pictures and metadata live in xref:crates:adoc-ebook.adoc[adoc-ebook], which Kindle export writes too.
The specification is `docs/prd/PRD-AdocFoundry_EPUB_Export.md` in the repository, which is not part of this site.

NOTE: EPUB export is complete: the engine, the app, the command line and the MCP server all export it.
What remains is manual checks in reading applications, listed in `docs/qa/epub.md` in the repository.

== What it does

`write_epub(&Document, &EpubOptions)` maps the document through `Book::build` of `adoc-ebook` and writes the book with `write_book(&Book, Modified)`.
The result is an `EpubOutput`, or an `EpubError`.
Everything is written in memory.

The publication is an OCF container holding:

* `mimetype`, first and stored, with no extra field and exactly `application/epub+zip`;
* `META-INF/container.xml`;
* the package document `EPUB/package.opf`: EPUB 3 (`version="3.0"`), with `dc:identifier` as the unique identifier, `dc:title`, `dc:language`, a `dc:creator` for each author, the publisher and description where known, one `dcterms:modified`, the subjects and date (see below), the accessibility metadata (see below), a manifest with exactly one `nav` item, and a spine of the chapters;
* the navigation document `EPUB/nav.xhtml`, with the table of contents and the landmarks (see below);
* one XHTML content document for each chapter, `EPUB/text/c<n>.xhtml`;
* each picture, `EPUB/images/i<n>.<extension>`, and the cover document `EPUB/cover.xhtml` when there is a cover (see below);
* the stylesheet `EPUB/css/book.css`, and `EPUB/css/user.css` when a user stylesheet is given (see below).

The chapters are semantic XHTML, written by `xhtml.rs`.

* Each chapter is a `section` with `epub:type="chapter"`.
* Headings are `h1` to `h6`, with their ids.
* Paragraphs carry classes for captions (`caption`), attributions (`attribution`) and admonition labels (`label`).
* Listings are `pre class="listing"` holding `code`, and verses are `pre class="verse"`.
* Lists are `ul`, `ol` and `dl`, and quotations `blockquote`.
* Admonitions, sidebars and examples are a `div` with the class `admonition <kind>` (and `role="note"`), `sidebar` or `example`.
It is a `div` and not an `aside`, because some reading systems hide an `aside`, taking it for a note.
* Tables have `thead`, `tbody` and `tfoot`, `th scope="col"` in header rows, `colspan` and `rowspan`, and tables nested in cells are kept.
* Keys are `kbd`, and buttons and menus are `span class="button"` and `span class="menu"`.
* A page break is `hr class="page-break"`, a separator rather than a page.

A link is never written inside a link.
Pages are never split into several content documents.

== Navigation

`EPUB/nav.xhtml` holds two navigations.
No NCX is written.

The table of contents is the `nav` with `epub:type="toc"` and the id `toc`, and there is exactly one.
It is nested ordered lists that follow the book's plan.
Parts come first, then their pages and navigation headings, then each page's sections two levels deep, all in reading order.

The landmarks are a second `nav` with `epub:type="landmarks"`, hidden with `hidden="hidden"`.
`toc` leads to `nav.xhtml#toc`, and `bodymatter` leads to the first chapter.
When the book has a cover, a `cover` landmark leads to `cover.xhtml`.

== Links

* In a chapter, a reference to an id in the same chapter is a fragment, such as `#c1-a1`.
* A reference to another chapter is `c<n>.xhtml#...`, since the chapters share a folder.
* A reference to a page outside the book is its published address when `page_urls` gives one, and the engine fills it from the site's URL.
Otherwise it is text with a located warning.
* A reference to an id that nothing in the book defines is text with a located warning too.
* Other external links are as written.

The ids are generated by the shared book model of xref:crates:adoc-ebook.adoc[adoc-ebook] (`c<n>-a<m>`).
Two pages that define the same id each keep their own, and a page reached through an alias or across modules is linked like any other.

Footnotes are at the chapter's end, in a `section` with `epub:type="footnotes"`.
Each is an `aside` with `epub:type="footnote"` and a link back to its first mark.
Every mark is a `sup` holding an `a` with `epub:type="noteref"`, and a repeated mark has no id of its own.

Passthrough is shown as text with a located warning, never as markup.
An unsupported block is its source with a located warning.

== Pictures

Pictures come from the shared book model of xref:crates:adoc-ebook.adoc[adoc-ebook] (its `media.rs`), as they do for Kindle export.
They are read through the export's `FileAccess`, recognised by their bytes, and checked whole and within limits: 16 MiB a file, 40 megapixels and 256 MiB a book.
Each picture is kept once, however often it is shown.
PNG, JPEG and GIF are kept as they are.
SVG is drawn as a PNG at twice its size by `resvg`, with nothing loaded from outside the file, so no script, external reference or entity reaches the book.
A remote picture is never fetched.

Each picture is written once as `EPUB/images/i<n>.<extension>` and listed in the manifest with its media type.

In a chapter, a block picture is a `figure` with the class `image` holding an `img`, and an inline one is an `img` with the class `inline`.
Each has its description as `alt`.
No `width` or `height` is written, so the reading system's style sizes the picture to the screen with its proportions kept.
The stylesheet is described below.

Diagrams are embedded as the export's diagram workers drew them: Mermaid in process, and the other tools when they are on `PATH`, as for PDF, Word and Kindle export.
A diagram that was not drawn is its source, with a warning.

A formula is the drawing the engine's STEM provider made, with the formula's source as its description.
With no drawing, as when Typst is not built in, it is the source as code, with a warning.
MathML is not written yet.

=== The cover

The cover is the export's own picture, else the `front-cover-image` of the first page.
It is listed in the manifest with `properties="cover-image"` and shown alone in the cover document `EPUB/cover.xhtml`, which is first in the spine and has a `cover` landmark.

=== Pictures that cannot be shown

A picture is its description in the text, with a warning at its line, when it cannot be shown because it is:

* missing or unreadable;
* malformed;
* too large;
* outside the folders the export may read;
* not a picture.

A remote picture is a link to it, with a warning.

== Stylesheet

Every document (the chapters, the navigation document and the cover) links the default stylesheet `EPUB/css/book.css`, which is `src/book.css` in the crate and is listed in the manifest as `text/css`.
It gives readable, reflowable type, headings, lists, wrapped code, tables, figures and footnotes.
It leaves the font, its size and the margins to the reader, and names nothing outside the book.

`EpubOptions::stylesheet` is an optional user stylesheet.
It is written as `EPUB/css/user.css` and linked after the default, so it overrides it.
Nothing yet passes a user stylesheet from settings, which is EPUB 7/9.

`check_stylesheet` refuses a user stylesheet, as `EpubError::Invalid`, when it holds any of:

* `@import`, `@font-face` or `@namespace`;
* `url(`, since no file of the book is the user's to name;
* `expression(`, `javascript:`, `-moz-binding` or `behavior`;
* markup (`</`);
* a backslash escape, which could hide any of these;

or when it is larger than 256 KB.
It is a conservative check and not a CSS parser, so it refuses what it cannot be sure of.

== Metadata

Besides the title, language, identifier, creators, publisher, description and `dcterms:modified`, the package document holds:

* a `dc:subject` for each of the page's `keywords`, which are separated by commas;
* `dc:date` from `revdate`, only when it is a date EPUB can read: `CCYY`, `CCYY-MM` or `CCYY-MM-DD`.
Free text is not written.

When the export gives no identifier, it is a stable `urn:uuid:` from the title, authors and version, which is the shared model's.

=== Accessibility metadata

Only what the book's content shows is written.

* `schema:accessMode` is `textual`, and `visual` too when the book has pictures.
* `schema:accessibilityFeature` is `tableOfContents`, and `structuralNavigation` too when the book has headings.
* `schema:accessibilityHazard` is `unknown`.
* `schema:accessibilitySummary` says the book has not been checked against an accessibility standard.

No conformance is claimed.

== Checks

Every XML file is checked to be well-formed, with `roxmltree`, before the bytes are returned.
An archive name is refused as `EpubError::Invalid` when it is absolute, holds `..`, a backslash or an empty segment, or uses anything but ASCII letters, digits, `.`, `-`, `_` and `/`.
A name used twice is refused the same way.
`EpubError::TooLarge` reports more than a ZIP archive holds.

== Validation

`adoc_epub::validate(bytes) -> Vec<String>` is the in-process validator (`src/validate.rs`).
It reads an archive back with bounds-checked reads, so a damaged archive gives problems and never a panic, and an entry may inflate to at most 512 MB.
It lists every problem it finds, not only the first.

* The archive: `mimetype` not first, compressed, with an extra field or not exact; unsafe or repeated names; encrypted entries.
* The container: one naming no package.
* The package: one that is not EPUB 3, or has no unique identifier, `dc:title` or `dc:language`, or does not have exactly one `dcterms:modified`.
* The manifest: items missing, outside the book, listed with the wrong media type for their extension or listed twice, and a file of the book that is not listed; not exactly one navigation document.
* The spine: an empty one, or one naming something that is not a content document.
* The content: XML that is not well-formed; a navigation document without exactly one `toc`.
* Links: a link out of the book by a scheme other than http, https, mailto, ftp, ftps or tel; a link to no document or no element.
* Resources: a picture or stylesheet that is not a file of the book of its kind; a picture without `alt`.

`write_epub` and `write_book` run it on every book before returning it, and fail with `EpubError::Invalid` and the problems.
It is not EPUBCheck and certifies no conformance.

== Same input, same bytes

The crate reads no clock and no environment.
`EpubOptions` has no default and needs a `Modified`: a UTC time to the second, from 1980 to 2107, made with `Modified::from_unix_seconds`.
It gives `dcterms:modified` and the date of every archive entry, so the same input gives the same bytes.

The ZIP writer (`zip.rs`, deflate through `flate2` and CRC-32 through `crc32fast`) and the XML writer (`xml.rs`) are the crate's own, as Word export's are.

== Tests

The `test-support` feature gives the `testing` module: a ZIP reader of its own (`entries`, `files`, `text` and `parse`) and `assert_valid_ocf`, which checks the container and the package as a reading system does.

`testing` keeps its own independent reader, so the tests check the validator as well as the writer.
`testing::assert_links_resolve` checks every link of the book's XHTML files as a reading system follows it.
A link inside the book must lead to a document of the manifest and, with a fragment, to an element with that id.
Any other link must be an address of `testing::SCHEMES` (http, https, mailto, ftp, ftps and tel), never `file:` or `antora:`.
It checks every `img` too: its `src` must be an image of the manifest, and it must have an `alt`.
It returns every link as an `Href`: the file it is in, the href and its text.

The acceptance tests are `epub_package_is_valid_ocf`, `epub_text_is_escaped` and `epub_output_is_deterministic`, in `crates/adoc-epub/tests/package.rs`.
The content tests are `epub_content_is_wellformed_xhtml`, `epub_footnotes_link_both_ways` and `epub_unsupported_nodes_warn`, in `crates/adoc-epub/tests/content.rs`.
The navigation tests are `epub_nav_matches_the_plan` and `links_inside_and_out_of_a_book`, in `crates/adoc-epub/tests/navigation.rs`.
The media tests are `epub_media_is_embedded` and `epub_bad_assets_are_reported`, in `crates/adoc-epub/tests/media.rs`.
The style tests are `epub_metadata_is_complete_or_reported`, `epub_css_has_no_external_dependencies` and `epub_accessibility_structure`, in `crates/adoc-epub/tests/style.rs`.
The validator's test is `the_validator_finds_what_breaks_a_book`, in `crates/adoc-epub/tests/validate.rs`, which damages a good book eighteen ways.
`epub_internal_links_resolve`, in `crates/adoc-engine/tests/epub_export.rs`, exports the Word and Kindle reference fixtures with a page alias and a missing id added, and checks every link.

== Where it sits

`adoc-epub` is headless.
It depends on `adoc-core`, `adoc-ebook`, `crc32fast`, `flate2` and `roxmltree`.
The pairs `adoc-epub` on `adoc-ebook`, and on `adoc-render` for its tests, are same-layer pairs listed in `SAME_LAYER_ALLOWED` in `xtask/src/layers.rs`.
It starts no process and uses no network: `cargo xtask layers` holds its sources to the same forbidden paths as `adoc-kindle`.

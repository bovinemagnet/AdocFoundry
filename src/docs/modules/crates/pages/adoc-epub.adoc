= adoc-epub
Paul Snow
:revnumber: 0.0.0
:description: EPUB export: a reflowable EPUB 3.3 publication written in process over the book model of adoc-ebook, with no PDF or Typst in between.

`adoc-epub` turns a rendered view tree into an EPUB publication.
It is at layer L2, beside `adoc-render` and `adoc-ebook`, which it reads.
The book model, its mapping, pictures and metadata live in xref:crates:adoc-ebook.adoc[adoc-ebook], which Kindle export writes too.
The specification is `docs/prd/PRD-AdocFoundry_EPUB_Export.md` in the repository, which is not part of this site.

IMPORTANT: The engine reaches the crate through its `epub` feature (`Engine::export_epub_blocking` and the commands `export.epub_page` and `export.epub_component`), but the app, the CLI and the MCP server do not yet, so there is no user-facing way to export an EPUB.
Later packages add the front ends, media, CSS and metadata.

== What it does

`write_epub(&Document, &EpubOptions)` maps the document through `Book::build` of `adoc-ebook` and writes the book with `write_book(&Book, Modified)`.
The result is an `EpubOutput`, or an `EpubError`.
Everything is written in memory.

The publication is an OCF container holding:

* `mimetype`, first and stored, with no extra field and exactly `application/epub+zip`;
* `META-INF/container.xml`;
* the package document `EPUB/package.opf`: EPUB 3 (`version="3.0"`), with `dc:identifier` as the unique identifier, `dc:title`, `dc:language`, a `dc:creator` for each author, the publisher and description where known, one `dcterms:modified`, a manifest with exactly one `nav` item, and a spine of the chapters;
* the navigation document `EPUB/nav.xhtml`, with the table of contents and the landmarks (see below);
* one XHTML content document for each chapter, `EPUB/text/c<n>.xhtml`.

The chapters are semantic XHTML, written by `xhtml.rs`.

* Each chapter is a `section` with `epub:type="chapter"`.
* Headings are `h1` to `h6`, with their ids.
* Paragraphs carry classes for captions (`caption`), attributions (`attribution`) and admonition labels (`label`).
* Listings are `pre class="listing"` holding `code`, and verses are `pre class="verse"`.
* Lists are `ul`, `ol` and `dl`, and quotations `blockquote`.
* Admonitions, sidebars and examples are a `div` with the class `admonition <kind>` (and `role="note"`), `sidebar` or `example`.
It is a `div` and not an `aside`, because some reading systems hide an `aside`, taking it for a note.
* Tables have `thead`, `tbody` and `tfoot`, `th scope="col"` in header rows, `colspan` and `rowspan`, and tables nested in cells are kept.
* Keys are `kbd`, and buttons and menus are `span class="button"` and `span class="menu"`.
* A page break is `hr class="page-break"`, a separator rather than a page.

A link is never written inside a link.
Pages are never split into several content documents.

== Navigation

`EPUB/nav.xhtml` holds two navigations.
No NCX is written.

The table of contents is the `nav` with `epub:type="toc"` and the id `toc`, and there is exactly one.
It is nested ordered lists that follow the book's plan.
Parts come first, then their pages and navigation headings, then each page's sections two levels deep, all in reading order.

The landmarks are a second `nav` with `epub:type="landmarks"`, hidden with `hidden="hidden"`.
`toc` leads to `nav.xhtml#toc`, and `bodymatter` leads to the first chapter.
A cover landmark comes with the cover, in a later package.

== Links

* In a chapter, a reference to an id in the same chapter is a fragment, such as `#c1-a1`.
* A reference to another chapter is `c<n>.xhtml#...`, since the chapters share a folder.
* A reference to a page outside the book is its published address when `page_urls` gives one, and the engine fills it from the site's URL.
Otherwise it is text with a located warning.
* A reference to an id that nothing in the book defines is text with a located warning too.
* Other external links are as written.

The ids are generated by the shared book model of xref:crates:adoc-ebook.adoc[adoc-ebook] (`c<n>-a<m>`).
Two pages that define the same id each keep their own, and a page reached through an alias or across modules is linked like any other.

Footnotes are at the chapter's end, in a `section` with `epub:type="footnotes"`.
Each is an `aside` with `epub:type="footnote"` and a link back to its first mark.
Every mark is a `sup` holding an `a` with `epub:type="noteref"`, and a repeated mark has no id of its own.

Passthrough is shown as text with a located warning, never as markup.
An unsupported block is its source with a located warning.
Pictures are still written as their description, until a later package embeds them.

== Checks

Every XML file is checked to be well-formed, with `roxmltree`, before the bytes are returned.
An archive name is refused as `EpubError::Invalid` when it is absolute, holds `..`, a backslash or an empty segment, or uses anything but ASCII letters, digits, `.`, `-`, `_` and `/`.
A name used twice is refused the same way.
`EpubError::TooLarge` reports more than a ZIP archive holds.

== Same input, same bytes

The crate reads no clock and no environment.
`EpubOptions` has no default and needs a `Modified`: a UTC time to the second, from 1980 to 2107, made with `Modified::from_unix_seconds`.
It gives `dcterms:modified` and the date of every archive entry, so the same input gives the same bytes.

The ZIP writer (`zip.rs`, deflate through `flate2` and CRC-32 through `crc32fast`) and the XML writer (`xml.rs`) are the crate's own, as Word export's are.

== Tests

The `test-support` feature gives the `testing` module: a ZIP reader of its own (`entries`, `files`, `text` and `parse`) and `assert_valid_ocf`, which checks the container and the package as a reading system does.

`testing::assert_links_resolve` checks every link of the book's XHTML files as a reading system follows it.
A link inside the book must lead to a document of the manifest and, with a fragment, to an element with that id.
Any other link must be an address of `testing::SCHEMES` (http, https, mailto, ftp, ftps and tel), never `file:` or `antora:`.
It returns every link as an `Href`: the file it is in, the href and its text.

The acceptance tests are `epub_package_is_valid_ocf`, `epub_text_is_escaped` and `epub_output_is_deterministic`, in `crates/adoc-epub/tests/package.rs`.
The content tests are `epub_content_is_wellformed_xhtml`, `epub_footnotes_link_both_ways` and `epub_unsupported_nodes_warn`, in `crates/adoc-epub/tests/content.rs`.
The navigation tests are `epub_nav_matches_the_plan` and `links_inside_and_out_of_a_book`, in `crates/adoc-epub/tests/navigation.rs`.
`epub_internal_links_resolve`, in `crates/adoc-engine/tests/epub_export.rs`, exports the Word and Kindle reference fixtures with a page alias and a missing id added, and checks every link.

== Where it sits

`adoc-epub` is headless.
It depends on `adoc-core`, `adoc-ebook`, `crc32fast`, `flate2` and `roxmltree`.
The pairs `adoc-epub` on `adoc-ebook`, and on `adoc-render` for its tests, are same-layer pairs listed in `SAME_LAYER_ALLOWED` in `xtask/src/layers.rs`.
It starts no process and uses no network: `cargo xtask layers` holds its sources to the same forbidden paths as `adoc-kindle`.

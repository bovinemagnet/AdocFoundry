= Implementation notes
Paul Snow
:revnumber: 0.0.0
:description: Where building Phases 1, 2, 3 and 4 departed from their specifications, and why.

Where building a phase showed its specification to be wrong or incomplete, the implementation made the smallest change that works.
This page summarises the departures that each phase specification records.
The specifications are the authoritative records.

This section summarises section 12 of `docs/prd/PRD-AdocFoundry_Phase_2_Implementation_Specification.md`.

|===
|Area |Specification |Implementation |Why

|acdc-parser licence
|acdc-parser 0.11 (MIT OR Apache-2.0)
|used, with its `evalexpr` dependency replaced by AdocFoundry's own `vendor/evalexpr` through `[patch.crates-io]`
|acdc-parser depends on `evalexpr = "13"`, which is AGPL-3.0-only. acdc uses only `eval_float` and `eval_int` (for `ifeval` operands); the stand-in implements those two in-house under Apache-2.0. See `vendor/README.md`.

|a variant per block, each carrying span, id, roles and title

|One place for the common fields; the extra kinds exist in AsciiDoc and must not fall back to raw source.

|`build_view`

|acdc spans
|Not specified

|Without it every span was one character short, and a cell's single-character paragraph had an empty span.

|acdc image targets

|merman dependency floor
|Not specified
|the workspace pins move to `serde_json =1.0.154` and `serde-saphyr =1.3.0`
|merman 0.9.2 requires those minimums; both are compatible updates and every existing test passes on them.

|`ExternalProvider`
|`{ kind, program, args }`
|`{ kinds, program, args }`: one tool may serve several block styles (`graphviz` and `dot`; `plantuml` and `uml`)

|`Engine::preview`
|`preview(id) -> Option<Arc<RenderedPreview>>`

|Preview target
|front ends call `request_preview`/`release_preview`
|those exist, and the engine also requests the preview target itself: the pinned document, or else the active one, while the preview is visible (`preview_target()`, `PreviewLayout`)
|Following the active page and pinning are then engine state, testable headlessly, and the docked and detached views render the same target.

|Stale results
|a newer request supersedes an older one
|a result is dropped when a newer job has started for the document, or when the document or a file it includes changed after the job started
|An edit during a render must not flash the old text; the replacement job follows after the settle time.

|Diagram tools in settings
|found on `PATH` or set in settings
|found on `PATH` only
|Settings for tool paths are deferred; Mermaid, the common case, needs no tool.

|Mermaid output
|SVG from merman
|merman's resvg-safe pipeline (`SvgPipeline::resvg_safe()`), and a render revision in the cache key
|Mermaid's default labels are HTML inside `foreignObject`, which GPUI's SVG renderer (resvg) does not draw; the revision makes caches written by an earlier renderer miss.

|Preview link and click commands
|`navigate.follow_link` semantics
|`navigate.go_to` (a position, recorded in back/forward history, for xrefs clicked in the preview) and `navigate.reveal` (a position, not recorded, for click-to-source), both taking `CommandArgs::Position`
|`follow_link` needs an open document and a caret offset in it; the preview knows the resolved target, and the source of a block may be an unopened partial.

|Typographic replacements
|Not specified
|applied by `adoc-dom` to plain text outside verbatim content, honouring backslash escapes
|acdc leaves the `replacements` substitution to the converter; without it `(C)`, `--`, `...` and arrows reached the preview unchanged. Found by the fidelity harness.

|Fidelity harness discovery
|skipped when `asciidoctor` is not on `PATH`
|skipped when `asciidoctor --version` does not succeed
|A broken installation (here, Asciidoctor.js's CLI under a newer Node) is as unusable as a missing one. The comparison treats a rendered diagram as the listing block Asciidoctor writes without its diagram extension, and compares paragraph text with character references decoded.

|`render_blocking`
|Not specified
|`Engine::render_blocking(id, timeout)` renders a document once, waiting for its diagrams
|The CLI has no event loop to pump.

|Second parser
|`AsciidocParser` over asciidoc-parser 0.31
|as specified; section and block titles come from its rendered HTML with tags stripped, because the crate exposes no inline tree for them, and line comments (which it parses as empty paragraphs) are dropped
|The crate's public API; Asciidoctor emits nothing for a comment. The corpus comparison lists one disagreement: where a `[qanda]` list after a description list lands.

|Parser choice
|Not specified
|`Engine::set_document_parser` and `adocfoundry-cli render --parser acdc\|asciidoc-parser`; acdc is the default
|The comparison is a development tool; the app keeps one parser.

|Qualified include targets
|Not specified
|before acdc parses a page or an included file, the colons of an include target that is a qualified Antora id (`module:family$path`, `component:module:family$path`) are replaced by a one-byte placeholder, and restored in the path handed to the `IncludeResolver` and in span file chains
|acdc reads `module:` as a URI scheme and links the include instead of reading it. The placeholder is the colon's length, so every offset is unchanged.

|Include paths for relative pages
|Not specified
|acdc joins targets onto an absolute base; the path handed to the `IncludeResolver` is made relative again when the page was given by a relative path, including one above the working directory
|The workspace's include map is keyed by the path as the page was given.

|Document title
|Not specified
|a title acdc splits at its last `: ` is joined again (`Main: Sub`)
|Asciidoctor's `doctitle` is the whole text. Only a title page partitions it, and `adoc-pdf`'s title page does so itself.

|Comment lines in text
|Not specified
|lines starting `//` (not `///`) are dropped from paragraph and list item text
|acdc keeps tag directives (`// end::x[]`) for include filtering, and they stayed in the text, at times with a comment beside them. A documentation project that tags its leads leaked one into most pages.

|Include attributes and tabbed titles
|Not specified
|before acdc parses a page or an included file, each include's attribute list keeps only the attributes acdc reads (`encoding`, `indent`, `leveloffset`, `lines`, `opts`, `tag`, `tags`), without spaces after its commas, and as many one-byte placeholders go at the end of its target, which the loader removes.
A tab between a section title's `=` and its text becomes a space outside verbatim blocks.
|acdc rejects `[tag=a, leveloffset=+1]`, `subs=` on an include and `===<tab>Title`, all of which Asciidoctor reads.
Every line keeps its length, so spans are unchanged (Phase 5, WP 5.3).

|Legacy asset directories
|Not specified
|`ResourceFamily::directories()`: images and attachments are also discovered under a module's `assets/images` and `assets/attachments`, read first so the standard directory wins when both hold a file; hover names resource ids from either
|Antora still reads this older layout, and real projects use it; their images were unresolved in the preview.

== Phase 3

This section summarises sections 2.1 and 11 of `docs/prd/PRD-AdocFoundry_Phase_3_Implementation_Specification.md`.
Where it differs from the earlier sections of that specification, section 11 wins.

=== Why prosemirror-rs was not adopted

The `prosemirror` crate 0.5.2 (MIT) was built against an AsciiDoc-shaped schema as a spike.
Replace steps applied, inverted and mapped positions correctly, and the crate passes `cargo deny`.
It was not adopted, and its design (steps with inverses, step maps, marks on text) is followed in-house in `adoc-model`.

* Its positions are UTF-16 code units, for parity with JavaScript. Every AdocFoundry crate works in byte offsets of the source, and a second coordinate system would run through the whole edit path.
* Its schemas and attributes are runtime JSON, with node kinds as strings and attributes as `serde_json::Value`, so the typed tree the design asks for would be a layer of conversions on top.
* Its node types live in a thread-local global store, against the workspace rule to avoid global mutable state, and every engine worker would need the scope.
* It enables `serde_json`'s `preserve_order` feature, which feature unification would turn on for the whole workspace and change the key order of every JSON output.
* What it adds is document-position arithmetic. With the source as the truth, a step's effect is a set of source edits, and source offsets already map through edits.

=== Departures from the specification

[cols="1,2,3,3"]
|===
|Area |Specification |Implementation |Why

|Model types
|`Node`, `TextBlock` and `Piece` as listed
|`TextBlock` also carries its `display` text and a `context` (`Flow`, `Line`, `Cell`, `Verbatim`) that says what typed text may contain. `Piece::Atom` carries the text it shows. Marks include `Span` (text with a role, no formatting of its own), and node kinds include `Title`, `Term` and `Description`. `text_block_at` returns the path, node and block rather than a `TextBlockRef`.
|The view draws from the display text and atoms' shown text. A cell must escape a vertical bar and a title stay on one line. A description list item has two text blocks.

|Inline structure
|The scanner's reading is checked against the DOM
|As specified. The check compares the characters shown (ignoring whitespace) and their marks, with `Span` ignored on both sides and link text compared without its inner formatting.
|Over this repository's documentation and the render fixtures, 1,188 of 1,189 text blocks agree. The one that does not is an acdc reading of an image macro inside backticks, and is read-only.

|Block ranges
|The DOM's spans
|Block starts are moved past whitespace and block ends to the end of their line. A section runs to the next block of its parent. Text ranges are found from the source lines (heading markers, list markers, metadata lines).
|acdc spans can be a byte short at either end on pages with multi-byte text, and a section's span ends early when its last child is included.

|`kbd:`, `btn:`, `menu:`
|Atoms
|Atoms only when the document sets `experimental`
|Asciidoctor requires it. Without it they are text, and the DOM check agrees.

|Typed markup
|Escaped, then checked
|The escape goes before the first construct the rescan finds that the step did not intend, which may be existing text. A line of flowing text that would start another block is guarded with `{empty}`. A vertical bar typed in a cell gets a backslash.
|Escaping only what forms markup keeps typed text as written, and Asciidoctor shows a backslash before anything else literally.

|Mark changes
|Keep delimiter form
|As specified. When a split mark, or new text next to a mark, makes the constrained form invalid, the marks involved take the unconstrained form. A new mark leaves the typed text's outer whitespace outside, and adding a mark absorbs marks of the same kind it overlaps.
|`*bo*ld` would not parse and `*bold *` neither, and a code mark over `a`, `b` becomes one span rather than nested backticks.

|`VisualArgs`
|`{ id, selection, marks, value }`
|Also `version`, the document version the selection is in
|A selection from an older version may point at different text. A stale model is rebuilt first, but a stale selection is refused.

|Step errors
|`StepError`
|Reported as `EngineError::Refused` with the step's message. A join that is not possible, such as Backspace at the start of a paragraph after a heading, does nothing.
|A refused join is common and harmless. Anything else is worth telling the user.

|Deleting across blocks
|`Delete` across blocks joins the first and last text blocks
|Refused. Typing over, or pressing Enter on, a selection that spans blocks is refused too.
|The effect of a join on everything between the blocks is easier to judge in the source. Deferred.

|Joining
|Backspace joins with the previous paragraph
|Only the blank line between the paragraphs is removed. A list item joins the item before it by losing its marker. A paragraph does not join a heading.
|Removing only the separator keeps the Git diff to the lines the user changed.

|Enter at the end of a block
|`SplitBlock`
|The new paragraph or list item exists only in the view until its first character, which `visual.insert_block` writes. Enter on a pending list item leaves the list. Enter at the start of a block does nothing.
|AsciiDoc has no empty paragraph or empty list item.

|Split
|Not specified
|The whitespace at the split point is dropped from both halves.
|Otherwise the left half keeps a trailing space, which breaks a constrained mark around it.

|Tables
|`InsertTableRow`, `InsertTableColumn`
|Rows go below the caret's, below the header and before the first body row, so an implicit header stays one. Columns go after it. A table without `cols` takes its column count from its first row, and widths written with `*` are left to the source editor.
|Inserting directly after an implicit header row would turn the header into a body row.

|Highlight binding
|`cmd-shift-h`
|None
|`cmd-shift-h` is Replace in Workspace. Highlight is on the toolbar and in the palette.

|Typing marks
|Not specified
|With nothing selected, Bold, Italic, Code and Highlight toggle the marks the next typed text carries, held by the view. They reset when the caret moves.
|There is nothing in the source to change until text is typed.

|Split mode
|Source and visual side by side
|Each follows the other's caret: the source scrolls to the visual caret, and the visual editor brings the source caret's block into view.
|Keeps both halves on the same text without moving the caret the user is not using.

|Images
|A dialog for target and alt text
|Clicking an editable block image opens it, and the image is drawn from the file it resolves to.
|A click on read-only content (diagrams, included blocks) shows its source instead.

|Bold on Linux
|Not specified
|With the system's IBM Plex Sans installed as a variable font, GPUI draws its default weight, so bold text and headings show at regular weight in the preview and the visual editor alike.
|A font loading limit outside the editor.
|===

== Phase 4

This section summarises section 11 of `docs/prd/PRD-AdocFoundry_Phase_4_Implementation_Specification.md`.
Where it differs from the earlier sections of that specification, section 11 wins.
Not in Phase 4, by decision: typeset STEM, a live Typst preview, PDF/A-1 and PDF/UA-2, cover images beyond a full-page image, and asciidoctor-pdf's Ruby extensions.

[cols="1,2,3,3"]
|===
|Area |Specification |Implementation |Why

|Layout of assets
|`themes/` and `fonts/` at the repository root
|`crates/adoc-pdf/themes` and `crates/adoc-pdf/fonts`, embedded with `include_str!` and `include_bytes!`
|The crate stays self-contained when packaged, and nothing is read from disk.

|Bundled themes
|`base`, `default`, `default-sans` and `default-for-print`
|As specified. The `*-with-font-fallbacks` names load as the theme they extend, with a warning.
|The fallback fonts (M+ 1p and Noto Emoji) add 1.9 MB, and a theme that extends them still loads without edits.

|Typed `Theme`
|A struct of the keys the converter reads
|The flattened keys are passed to the template as a Typst dictionary under asciidoctor-pdf's own names, with typed values. Fallbacks are resolved in the template.
|One name for each setting from the YAML to the template.

|Unknown keys
|A warning per unknown key
|A warning per unknown top-level category, with the keys kept for variables
|Themes keep their own variables in categories of their own, and a warning per key would be noise.

|Spacing
|Typst's block spacing
|Prawn's model: zero block spacing with each bottom margin written as `#v(...)`, weak heading tops, half-leading around paragraphs, line heights with the font's line gap, and Typst's heading styles switched off
|Typst collapses adjacent spacing to the larger value. With this model the reference article lands within 1.7 pt of asciidoctor-pdf on every line.

|Keeping blocks together
|Not specified
|Admonitions, code, quotes, sidebars, examples and captioned blocks are unbreakable when they fit, and `heading_min_height_after` moves a heading with too little room below it. The width is measured from the page's content width.
|asciidoctor-pdf decides page breaks this way. `layout()` would measure exactly, but links inside it lose their place in a tagged PDF.

|Line breaking and spaces
|Not specified
|Greedy breaking, spaces that only stretch, and runs of spaces collapsed
|Prawn fills lines first-fit and never shrinks spaces.

|Footnotes
|Typst footnotes
|Collected at the bottom of the last page of the article or chapter
|Where asciidoctor-pdf puts them.

|Running content
|`+{page-number}+` from Typst's page counter
|Counted from the page holding the body's start marker. Substitutions are limited to attribute references, constrained `*`, `_` and `` ` ``, character references and a lone `image:` macro.
|A counter update at the start of a page comes after that page's background is laid out. Nothing from a theme is written as Typst code; a security review found an image width written as raw text, and it was fixed.

|Titles
|Not specified
|The article's title and the title page's title are level 1 headings in the PDF structure
|PDF/UA-1 requires the first heading to be level 1.

|Source highlighting
|tree-sitter
|Typst's highlighter, only when `source-highlighter` is set
|The tree-sitter highlighter is in the application crate. asciidoctor-pdf also highlights only then.

|PDF/A date
|Not specified
|A date is written when a standard is requested: the given one, else today's in UTC
|PDF/A requires it. An ordinary export stays undated so the same input gives the same bytes.

|`lang`
|Not specified
|Split into Typst's language and region
|Typst rejects a region in `lang`.

|Image alt text
|Not specified
|An image without alt text gets its file name
|Every image needs a text alternative for PDF/UA.

|Book plan
|Parts from nav files or titled lists when there are several
|As specified. An untargeted nav entry is a heading at its depth, each page appears once, and the start page leads as a preface unless the nav lists it. A list title that links to a page (`.xref:index.adoc[Architecture]`) titles the part and its page leads it. A page with no title takes its entry's text.
|Every nav file of a real project titles its list with a link to the module's index page.

|Unreadable pages
|Not specified
|A page the parser rejects is shown as its source, and the export warns with the parser's message
|Without the warning the page's source appeared in the book unexplained.

|Typst's cache
|Not specified
|Emptied after each compile
|Typst memoises layout in a process-wide cache that nothing else empties. After a 2,000-page book it held about 11 GB, which the app would keep. comemo 0.5 kept the memory of the caches it emptied (call-tree slabs and maps, and accelerator tables). That was 15.5 GB after a 2,058-page book. `vendor/comemo` frees it, leaving 67 MB. See `vendor/README.md`.

|Lists
|Not specified
|Typst's `enum`, with each item's marker given as its number in a box as wide as the indent
|A `grid` is tagged `Div`. The enum is tagged `L`, `LI`, `Lbl` and `LBody`, so a screen reader announces a list, with no line moved. Description lists are still blocks, tagged `Div`.

|CLI
|`--component <name>[@<version>]`
|`--component [<version>@]<name>`, and also `--fonts-dir`. For a component directory the workspace is its parent, so its sibling components resolve.
|It matches Antora coordinates, and real projects pass a fonts directory.

|App
|The palette and the File menu
|The palette only
|The application has no menu bar.

|Advisories
|Not specified
|`deny.toml` ignores RUSTSEC-2026-0194 and RUSTSEC-2026-0195
|They reach quick-xml 0.38 only through Typst's `bibliography()`, which generated Typst never calls. citationberg 0.7.0, the latest, still needs it.

|Visual regression
|Books within one page
|Books are not compared. The mean grey difference is at most 0.02, and ink edges are within 6 pt.
|asciidoctor-pdf cannot assemble an Antora component, so the book is covered by the engine's structural tests. The thresholds sit above the first run's worst page (0.0085 and 1.8 pt).

|Index
|`index_*` keys
|Letters as headings, terms and subterms with their pages, in `index_column_count` columns
|It is built with `query` over `metadata` markers, as no Typst package is reachable.

== Phase 5

This section summarises section 12 of `docs/prd/PRD-AdocFoundry_Phase_5_Implementation_Specification.md`, as each package lands.

[cols="1,2,3,3"]

|===
|Area |Specification |Implementation |Why

|Windows in WP 5.1
|the first Windows run, with whatever fails fixed in the package
|CI runs Windows. No Windows-specific fix was needed to type-check on macOS, and a local cross-check stopped at a C build script (`stacker`) that needs the Windows SDK

|Command availability (#17)

|No new field: the context already named the visual editor's commands. The palette also stops listing document commands with no document open.

|Problems rows (#18)

|every sidebar row is one line, cut off with an ellipsis, with the full text in a tooltip. Test: `long_diagnostics_show_in_full_on_hover`
|The sidebar trees are virtual lists with one fixed row height, where a wrapped row would overlap the next.

|Revealing the active tab (#13)
|the strip scrolls the active tab into view
|the reveal is requested on two consecutive frames
|GPUI places a tracked item from the previous frame's layout, which a change of tabs or widths has just made stale.

|Word movement (#14)
|word boundaries in the model
|`adoc-model`'s `next_word_end`, `previous_word_start` and `word_at` over the block's shown text (UAX #29 through `unicode-segmentation` 1.13.3, already in the tree). Also `caret_moves_by_word`
|A word move at the start of a marked word stops before the mark's delimiter, as character movement does.

|Description lists (#31)
|`terms`, styled to keep asciidoctor-pdf's layout
|Typst's `terms` with a hanging indent of `description_list_description_indent`, the term spacing above each description and `strong` neutralised in terms. The emitter no longer ends a term with a paragraph break
|A break inside a term split its tag, which PDF/UA rejects. No line of the reference article moved. Horizontal description lists stay a grid, tagged `Div`.

|Tag directives (#33)
|drop them from tagged includes and callout items
|callout items drop their comment lines as paragraphs do. Tagged includes needed nothing: acdc already drops every directive of a tag-filtered region
|The corpus's remaining directive lines are in literal paragraphs of pages rendered whole, where Asciidoctor shows them too. Tests: `tagged_includes_drop_other_tag_directives`, `callout_items_drop_tag_directives`.

|Footnotes (#35)
|match asciidoctor-pdf's footnote block
|the last footnote keeps `footnotes_item_spacing` below it, the margin that meets the page's bottom margin
|As asciidoctor-pdf's `ink_footnotes`. The reference article's footnote is now 0.56 pt from asciidoctor-pdf's, from 3.6 pt.

|Book memory (#34)
|measure the template's share, then reduce ours
|the emitter marks blocks its text shows fit on a page (`fits: true`, at most 20 estimated lines) so `keep()` measures only the rest.
Running titles look up one memoised list of headings with a binary search instead of filtering every heading on every page
|The 1,833-page corpus book: peak 17.1 GB to 9.3 GB, 55 s to 12.6 s. The 617-page one: 8.5 GB to 5.9 GB. `book_memory_probe` exports a synthetic 300-page component. No line or page changed.

|Code highlighting (#16)
|the source editor's highlighter
|the preview's tree-sitter highlighter, laid over the editable block's runs. The visual editor keeps its cache between frames, emptied past 256 entries
|The cache was rebuilt every frame, so read-only blocks were highlighted again on every render too.

|Reverse map (WP 5.6)
|`adoc-index` keeps a reverse map from targets to references
|the index maps the file name an xref or include names (`setup.adoc` for `admin:setup.adoc`) and each fragment to the references, and `adoc-lang` resolves those candidates, the target page's `page-aliases` included
|Resolving a target needs the Antora catalog, which sits beside `adoc-index` on L1, not below it. A request visits only the references that name the file.

|Renames (WP 5.6)
|`page.rename`'s edits cover xrefs, nav entries and includes
|`rename_preview` now also rewrites includes: an Antora include keeps its family and coordinates (`partial$notes/token.adoc`), a relative one stays relative, and one written through an attribute is left as written; `textDocument/rename` on anything but an anchor is refused
|The app's page rename gains the include edits too. A client renames a file through `willRenameFiles`.

|Git in `adoc-ls` (WP 5.6)
|Git stays off unless `[git] enabled` is set
|`Settings::with_git_opt_in`, kept across reloads
|`open_workspace` reloads settings, which would otherwise turn Git back on.

|Diagnostics timing (WP 5.6)
|published after the engine's settle
|each change is an `edit.replace_range`, which indexes at once, so a notification's diagnostics are published as it is handled; between messages the server pumps the engine every 50 ms and publishes what workers and the watcher changed; `initialize` is answered once the workspace is indexed (at most 120 s)
|The first requests already see every page, as the old server's synchronous indexing did.

|Features (WP 5.6)
|`adoc.exportPdf` advertised only in builds with `typst`
|the server advertises it when the engine registered its export commands, and `Engine::export_blocking` exists without Typst and fails
|A workspace build unifies the engine's features, so the engine, not `adoc-ls`'s own flag, says what is there. `adoc-ls`'s features only forward.

|Default build (WP 5.6)
|`default_build_has_no_typst_or_git` from `cargo metadata`
|from `cargo tree -p adoc-ls`, also run by `cargo xtask layers`
|`cargo metadata` resolves features for the whole workspace at once.

|Size (WP 5.6)
|record the default build's size and crate count
|release, macOS arm64: 32.4 MB and 237 crates by default; 88.0 MB and 535 crates with `typst,git`
|The lean build still carries acdc, merman and the diagram renderers the engine's preview uses.

|Preview tests (WP 5.6)
|stdio tests taking `spawn_guard()`
|the preview tests drive the protocol in process with a sink that never opens a browser, under a guard of their own (`adoc-render`'s is crate-private); the others drive the binary (`tests/engine.rs`)
|Over stdio the preview opens the system browser.

|Shared reports (WP 5.7)
|`check` and `git_status` as the CLI's JSON
|the CLI's diagnostics and Git status reports moved into the engine (`report.rs`: `check_report`, `git_status_report`), and the CLI prints them; `check` answers `{ diagnostics, failed }`, `diagnostics` being the CLI's array
|One implementation, so the two cannot drift; the CLI's snapshots did not change.

|Engine queries (WP 5.7)
|—
|`inspect.rs`: `resolve_target` (a macro as written or a bare xref target, read with the page's attributes), `resource_id` and `resolve_resource_id`; `adoc-render` gains `to_text` for `render_page`
|`adoc-mcp` may depend only on the engine and `adoc-core`, so what it needs from the catalog comes through the engine.

|Write tools (WP 5.7)
|not listed, and refused if called
|removed from the tool router without `--allow-write`, so a call is the protocol's unknown-tool error; `edit_page` is all or nothing (edits already made in a failing call are undone); `rename_page` saves every file it changed
|`workspace.apply_preview` leaves its edits in buffers, which a server with no editor would never save.

|Limits (WP 5.7)
|large results truncated, with the total stated
|lists at 500 items and texts at 200,000 bytes, with `truncated: { shown, total }`; paths are absolute or relative to the first root, and links are followed only through the part of a path that exists
|A path to a file not yet written, such as a rename's target or an export's output, is still checked.

|Runtime (WP 5.7)
|a current-thread tokio runtime
|tokio with `rt`, `macros`, `io-std` and `time`; each tool call locks the engine for its duration
|rmcp's service needs timers. One call at a time matches the engine's single thread.

|Packages (WP 5.8)
|each package carries the app and the three tools
|the DMG puts `adocfoundry-cli`, `adoc-ls` and `adoc-mcp` beside the app in `Contents/MacOS` and is signed ad hoc when no Developer ID is set; the MSI, zip, deb, rpm and Flatpak gain `adoc-mcp`; `adoc-ls`, `adocfoundry-cli` and `adoc-mcp` also ship as archives of their own; every build passes `--features adoc-ls/typst,adoc-ls/git`
|A bundle's `Contents/MacOS` is where macOS expects helper binaries, and linking them onto `PATH` keeps them signed with the app.

|Smoke test (WP 5.8)
|every binary's `--version`, the app on a fixture, a CLI export, both servers' initialise and shutdown
|`packaging/smoke-test.py`, run by the release workflow's `smoke` job on each platform's downloaded artefacts (the mounted DMG, the unpacked zip, the unpacked deb) before `publish`; the app gains `--version`; on Linux the app's launch is left to manual QA
|A hosted Linux runner has no GPU for the app's Vulkan renderer.

|Flatpak (WP 5.8)
|checked against the release
|the Linux release job checks that the manifest installs the four binaries and builds `adoc-ls` with its features
|Building the Flatpak itself needs flatpak-builder and a vendored source list, outside the workflow.

|Documentation version (WP 5.8)
|the documentation site's version
|the site stays unversioned, showing `0.1.0` as its display version
|A versioned component would move every page's URL.

== Git

=== Branch-aware Antora versions

[cols="1,2,3,3"]
|===
|Area |Issue |Implementation |Why

|Versions to branches
|`Playbook::branches_for_version` in `adoc-antora`, using the catalog
|`adoc-antora` parses the sources and matches branch patterns (`ContentSource`, `PublishedVersions`). The engine builds the table on a worker (`src/versions.rs`) from each branch's `antora.yml`, read through `adoc-git`, and sets it on the catalog.
|The playbook names branches, not versions, and the catalog only knows checked-out versions. Mapping versions to branches needs each branch's `antora.yml`, which only the engine can read.

|Branch patterns
|Not specified
|Matching uses `globset` 0.4.20, with numeric ranges such as `{0..9}` expanded first.
|`globset` has no numeric ranges.

|Opening the remote link
|Suggested the `open` crate
|The engine returns `CommandOutcome::Url(String)`, and the front end opens it with `cx.open_url` or copies it.
|The engine needs no browser-opening crate and stays testable without a display.

|Where blame is read
|Not specified
|`blame_for` is on `Engine`, not `GitState`.
|It overlays the HEAD blame with the current hunks, which needs the document's text.

|Unpushed count test
|Suggested a bare remote on disk
|`unpushed_count_against_remote_tracking` uses a remote-tracking branch written by `TestRepo::track_remote`.
|The count reads the remote-tracking branch, so a bare remote adds nothing to the test.

|Writing the index to a tree
|Not specified
|`Repository::commit` builds the tree from the index entries with gix's tree editor.
|gix 0.90 has no index-to-tree writer.

|Staging and committing
|Not specified
|They go through `gix` in process. A commit made with `commit.gpgsign` set is made with the `git` executable so that it is signed with the user's key.
|The signing setup is the user's, and gix does not sign.

|Pushing
|The epic allows the `git` executable
|`git.push` runs `git push` from `[tools] git`, else `git` on `PATH`, on a worker thread. It never forces and never sets an upstream.
|The user's credential helper, SSH agent and signing setup work unchanged.
|===

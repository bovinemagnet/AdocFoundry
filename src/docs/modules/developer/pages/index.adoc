= Developer guide
Paul Snow
:revnumber: 0.0.0
:description: An introduction to AdocFoundry's internals for contributors.

This guide is for people working on AdocFoundry itself.
For using the editor, see the xref:ROOT:index.adoc[user guide].

AdocFoundry is a Rust workspace.
A GPUI desktop application, a command-line checker and a language server are all thin front ends over one headless engine.
The main ideas are:

* One engine owns all document text and semantics.
Views mirror it and never keep their own copy.
* Every user-visible action is a command with a stable id, and every document change is a command recorded in undo history.
* Crates form a ladder, and a crate may depend only on crates below it.
The ladder is checked in CI.
* Positions are byte offsets everywhere, converted to lines and columns only at the edges.
* Diagnostics are conservative, and parsers never panic on half-typed input.

== Working rules

* Work one work package at a time, in the order the phase specification gives.
* Do not start a later phase's features unless the current specification says so.
* Pin every external dependency exactly and check it with `cargo deny`.
* Never depend on Zed's GPL-3.0 editor crates (`editor`, `text`, `rope`, `multi_buffer`, `language`, `project`).
* Keep `unsafe_code` forbidden, and use typed errors in libraries and `anyhow` only in binaries.

This page covers installing AdocFoundry and opening your first workspace.

== Install a package

Release packages are attached to each release at https://github.com/bovinemagnet/AdocFoundry/releases.
Every package carries the application and the `adocfoundry-cli`, `adoc-ls` and `adoc-mcp` binaries.
The `adoc-ls`, `adocfoundry-cli` and `adoc-mcp` binaries are also published as archives of their own.
AdocFoundry needs no Ruby, Node.js or Java at run time.

`adocfoundry --version` prints the version, for example `adocfoundry 0.2.1`, and exits.

=== macOS

Download `AdocFoundry-<version>-macos-universal.dmg`, open it and drag AdocFoundry to Applications.

The app is signed ad hoc, not with a Developer ID, which comes in a later release.
macOS therefore asks before opening it the first time: Control-click the app, choose *Open*, then confirm.

The command-line tools are in `AdocFoundry.app/Contents/MacOS`.
Link them onto your `PATH` to use them from a terminal.

[source,sh]
----
ln -s /Applications/AdocFoundry.app/Contents/MacOS/adoc-ls /usr/local/bin/
----

=== Windows

Download the MSI, which can add the tools to your `PATH`, or the portable zip.
Both are built for x64 and ARM64.

The packages are unsigned, so SmartScreen asks before running them: choose *More info*, then *Run anyway*.

=== Linux

Packages are built for x86_64 and aarch64.

* AppImage: make it executable with `chmod +x`, then run it.
* deb: `sudo apt install ./AdocFoundry-<version>-….deb`
* rpm: `sudo dnf install ./adocfoundry-<version>-….rpm`
* Flatpak: a manifest is kept in `packaging/flatpak/` in the repository.

NOTE: The Linux x86_64 build has been run on Wayland and, through XWayland, on X11.
See xref:developer:testing.adoc#platform-status[platform status].

== Build from source

You need Rust (stable, installed with `rustup`).
On Linux you also need the libraries GPUI uses.

[source,sh]
----
# Debian and Ubuntu
sudo apt-get install libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev libvulkan-dev \
  libfontconfig-dev libxcb1-dev libx11-xcb-dev libssl-dev
----

Clone the repository with its submodules, because the tree-sitter grammars live in `grammars/tree-sitter-asciidoc`.

[source,sh]
----
git clone --recurse-submodules https://github.com/bovinemagnet/AdocFoundry.git
cd AdocFoundry
cargo run --release -p adocfoundry -- path/to/docs
----

If you cloned without `--recurse-submodules`, fetch the grammars first.

[source,sh]
----
git submodule update --init
----

TIP: The repository's default workspace member is the application crate only.
Pass `--workspace` or `-p <crate>` when you build or test anything else.

== Open a workspace

[source,sh]
----
adocfoundry [folder [file...]]
----

`adocfoundry` opens a folder as the workspace and any files you list in tabs.
Open Folder (kbd:[Cmd+Shift+O] or kbd:[Ctrl+Shift+O]) does the same from inside the application.

The fixtures in the repository make a good first workspace.

[source,sh]
----
cargo run --release -p adocfoundry -- tests/fixtures/antora-multi-component
----

The folder can be a repository root, a directory holding several components, or a plain folder of `.adoc` files.
See xref:antora-support.adoc[Antora support] for how components are found.

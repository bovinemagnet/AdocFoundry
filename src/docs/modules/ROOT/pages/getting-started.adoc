This page covers installing AdocFoundry and opening your first workspace.

== Install a package

Release packages are attached to each release at https://github.com/bovinemagnet/AdocFoundry/releases.
Every package carries the application and the `adocfoundry-cli`, `adoc-ls` and `adoc-mcp` binaries.
The `adoc-ls`, `adocfoundry-cli` and `adoc-mcp` binaries are also published as archives of their own.
AdocFoundry needs no Ruby, Node.js or Java at run time.

`adocfoundry --version` prints the version, for example `adocfoundry 0.10.0`, and exits.

=== macOS

Download `AdocFoundry-<version>-macos-universal.dmg`, open it and drag AdocFoundry to Applications.

Alternatively, install it with Homebrew from the `bovinemagnet/tap` tap (https://github.com/bovinemagnet/homebrew-tap).
This needs macOS 13 or later.

[source,sh]
----
brew install --cask bovinemagnet/tap/adocfoundry
----

You can also add the tap first with `brew tap bovinemagnet/tap`, then run `brew install --cask adocfoundry`.
The cask installs the same signed, notarised universal DMG from the GitHub release into `/Applications/AdocFoundry.app`.
It also links `adocfoundry-cli`, `adoc-ls` and `adoc-mcp` from inside the app bundle into Homebrew's `bin`, so they are on your `PATH` without further steps.

To remove the app and those links, run the following.

[source,sh]
----
brew uninstall --cask adocfoundry
----

Releases built with the project's signing credentials are signed with a Developer ID and notarised, so the app opens without a prompt.
A release built without them (every release up to 0.2.1) is signed ad hoc, and macOS asks before opening it the first time: Control-click the app, choose *Open*, then confirm.
The release notes on GitHub say which a release is.

With a DMG installed by hand, the command-line tools are in `AdocFoundry.app/Contents/MacOS`.
Link them onto your `PATH` to use them from a terminal.
An app installed with Homebrew needs no linking.

[source,sh]
----
ln -s /Applications/AdocFoundry.app/Contents/MacOS/adoc-ls /usr/local/bin/
----

=== Windows

Download the MSI, which can add the tools to your `PATH`, or the portable zip.
Both are built for x64 and ARM64.

Alternatively, install it with Scoop from the `bovinemagnet/scoop-bucket` bucket (https://github.com/bovinemagnet/scoop-bucket).

[source,pwsh]
----
scoop bucket add bovinemagnet https://github.com/bovinemagnet/scoop-bucket
scoop install adocfoundry
----

Scoop installs the portable zip for x64 or ARM64 into your Scoop folder, so it needs no administrator rights.
It adds AdocFoundry to the Start menu under *Scoop Apps*, and puts `adocfoundry-cli`, `adoc-ls` and `adoc-mcp` on your `PATH` without further steps.

To update it, or to remove it, run the following.

[source,pwsh]
----
scoop update adocfoundry
scoop uninstall adocfoundry
----

Releases built with the project's signing credentials have Authenticode signatures on the executables and the MSI, so SmartScreen does not warn.
Unsigned releases (every release up to 0.2.1) make SmartScreen ask before running them: choose *More info*, then *Run anyway*.

=== Linux

Packages are built for x86_64 and aarch64.

* AppImage: make it executable with `chmod +x`, then run it.
* deb: `sudo apt install ./AdocFoundry-<version>-….deb`
* rpm: `sudo dnf install ./adocfoundry-<version>-….rpm`
* Flatpak: a manifest is kept in `packaging/flatpak/` in the repository, and each release's workflow run builds a bundle from it; it is not yet on Flathub.

NOTE: The Linux x86_64 build has been run on Wayland and, through XWayland, on X11.
See xref:developer:testing.adoc#platform-status[platform status].

=== Updates

At start-up, at most once a day, AdocFoundry looks for a newer release and tells you once when there is one.
The notice reads "AdocFoundry <version> is available."
Its button is *Release notes*, which opens the release page, or *Update…* where AdocFoundry can install the update itself (see below).
Each release is announced once, and closing the notice dismisses it.

To check at any time, run *Check for Updates* from the command palette.
It reports "AdocFoundry is up to date." or the error.

The check reads GitHub's latest release through the system's `curl`, so without `curl`, or offline, nothing is shown.
It sends nothing but the application's version, in the user agent, and is not telemetry.
To switch it off, set `check = false` under `[updates]` in the user settings file.
See xref:settings.adoc[Settings].

==== Installing an update

*Update…* appears when the app was installed from the DMG (an app bundle on macOS) or the MSI (under `Program Files` on Windows), and the release publishes `SHA256SUMS`.
It asks first, in a dialog with *Release notes* and *Update*.
Once the package is downloaded and checked, AdocFoundry quits as *File › Quit* does, asking first about unsaved changes.
Nothing is installed until you answer.
*Cancel* keeps AdocFoundry open and discards the downloaded update; run *Update…* again to install it.

macOS::
AdocFoundry downloads the universal DMG with the system's `curl` and checks it against the release's `SHA256SUMS`.
It mounts the DMG read-only and checks the new app with `codesign --verify --strict --deep` and Gatekeeper (`spctl`), and that its Team ID is that of the running app.
It then copies the new app beside the running one.
Only as AdocFoundry quits are the two swapped, and the new app is opened once the old one has exited.
An app installed with Homebrew updates itself the same way, because its cask declares that the app updates itself, so `brew upgrade` leaves it alone.
`brew upgrade --greedy` also works once the cask has the new release.

Windows::
AdocFoundry downloads `adocfoundry-<version>-<arch>.msi` (`x86_64` or `aarch64`) and checks it against `SHA256SUMS`.
It checks that the Authenticode signature is valid and from the same signer as the running executable.
As AdocFoundry quits, a background step waits for it to exit and runs `msiexec /i … /passive` into the folder AdocFoundry is installed in.
The MSI's major upgrade replaces the installed version, and the step then starts AdocFoundry again.

Linux AppImage::
The AppImage carries update information, and each release publishes the matching `.zsync` file, so AppImageUpdate (or AppImageLauncher) can update it.
The notice says so.
AdocFoundry does not run AppImageUpdate itself.

deb, rpm, Flatpak, the portable zip and builds from source::
The notice only points to the release.
Update the deb, rpm and Flatpak with their package managers.
A Scoop install is the portable zip, and *Update…* only applies to the MSI, so update it with `scoop update adocfoundry`.

NOTE: A build that is not signed with a Developer ID on macOS, or not Authenticode-signed on Windows, cannot check signatures, so it only points to the release.
Every release up to 0.2.1 is ad hoc signed on macOS and unsigned on Windows.

== Build from source

You need Rust installed with `rustup`, which installs the release that `rust-toolchain.toml` pins on the first build.
On Linux you also need the libraries GPUI uses.

[source,sh]
----
# Debian and Ubuntu
sudo apt-get install libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev libvulkan-dev \
  libfontconfig-dev libxcb1-dev libx11-xcb-dev libssl-dev
----

Clone the repository with its submodules, because the tree-sitter grammars live in `grammars/tree-sitter-asciidoc`.

[source,sh]
----
git clone --recurse-submodules https://github.com/bovinemagnet/AdocFoundry.git
cd AdocFoundry
cargo run --release -p adocfoundry -- path/to/docs
----

If you cloned without `--recurse-submodules`, fetch the grammars first.

[source,sh]
----
git submodule update --init
----

TIP: The repository's default workspace member is the application crate only.
Pass `--workspace` or `-p <crate>` when you build or test anything else.

== Open a workspace

[source,sh]
----
adocfoundry [folder] [file...]
----

`adocfoundry` opens a folder as the workspace and any files you list in tabs.
Given files and no folder, it opens the workspace the first file belongs to: the nearest folder above it holding an Antora playbook or `.adocfoundry.toml`, else the nearest holding an `antora.yml`, else the file's own folder.
So opening an AsciiDoc file from a file manager, or from Finder on macOS, opens it in its project; while the app is running, the file opens in a tab of its window.
Open Folder (kbd:[Cmd+Shift+O] or kbd:[Ctrl+Shift+O]) does the same from inside the application.
Launched with no folder or file, the app reopens the last session; see xref:using-the-editor.adoc#restoring-the-session[Restoring the last session].

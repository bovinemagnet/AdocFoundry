= Command line
Paul Snow
:revnumber: 0.0.0
:description: Using adocfoundry-cli to check, search, follow links, render and export to PDF headlessly, including in CI.

`adocfoundry-cli` is a headless front end over the same engine as the desktop application.
It needs no display, which makes it suitable for continuous integration.

[source,text]
----
adocfoundry-cli check <root> [--format text|json] [--fail-on warning|error]
adocfoundry-cli symbols <root> <query>
adocfoundry-cli follow <file> <byte-offset> [--root <dir>]
adocfoundry-cli render <file> [--root <dir>] [--output <file.html>] [--parser acdc|asciidoc-parser]
adocfoundry-cli pdf <file|component-dir> [--root <dir>] [--component [<version>@]<name>]
    [--theme <name|file.yml>] [--fonts-dir <dir>] [--output <file.pdf>]
    [--standard pdf-a-1b|pdf-a-1a|pdf-a-2a|pdf-ua-1] [--typst <file.typ>]
adocfoundry-cli pdf --profile <name> [<root>] [--output <file.pdf>] [--typst <file.typ>]
adocfoundry-cli git-status <root> [--format text|json]
adocfoundry-cli doctor [<root>] [--format text|json]
adocfoundry-cli --version
----

== check

`check` opens the workspace at `<root>`, waits for indexing to finish and prints every diagnostic, sorted by path.

[source,sh]
----
adocfoundry-cli check docs
adocfoundry-cli check docs --format json
adocfoundry-cli check docs --fail-on warning
----

=== Formats

The default `text` format prints one line per diagnostic, with paths relative to the root and `/` separators.

[source,text]
----
path:line:col: severity code message
----

Lines and columns are one-based, and the column counts bytes.
`severity` is `info`, `warning` or `error`.

`--format json` prints an array of objects.

[source,json]
----
[
  {
    "path": "modules/ROOT/pages/index.adoc",
    "range": { "start": 120, "end": 138 },
    "line": 7,
    "column": 3,
    "severity": "warning",
    "code": "adoc.unresolved-xref-file",
    "message": "..."
  }
]
----

`range` holds byte offsets into the file.

=== Exit codes

[cols="1,4"]
|===
|Code |Meaning

|0
|Success: no diagnostic met `--fail-on`.

|1
|At least one diagnostic met `--fail-on`. The default threshold is `error`.

|2
|Usage or runtime error, such as an unknown option, a bad format or a workspace that could not be indexed in time.
|===

The thresholds are `warning` (fails on warnings and errors) and `error`.
Information diagnostics never fail the check.

== symbols

`symbols` lists workspace symbols that match `<query>`, one per line, as kind, name and `path:line:col`.

[source,sh]
----
adocfoundry-cli symbols docs installation
----

== follow

`follow` resolves the reference at a byte offset in a file and prints where it leads.
It is used by tests and for scripting.

[source,sh]
----
adocfoundry-cli follow tests/fixtures/xrefs/index.adoc 42
----

For an `xref:`, `include::` or attribute it prints `path:line:col`.
For an image or attachment it prints `external <path>`.
If the offset is not on a followable reference, or the target does not resolve, it prints the reason on standard error and exits with 1.

By default the workspace root is the parent of the nearest `antora.yml`, so that sibling components resolve.
Use `--root <dir>` to choose another.

[[render]]
== render

`render` writes a page as a standalone HTML file, as the xref:preview.adoc[preview] renders it.
Without `--output` the HTML goes to standard output.
It waits for diagrams to finish before writing.
Images are linked by `file://` address; the application's Export Page to HTML… embeds them instead, see xref:preview.adoc#exporting-html[Exporting to HTML].

[source,sh]
----
adocfoundry-cli render docs/modules/ROOT/pages/index.adoc --output index.html
adocfoundry-cli render docs/modules/ROOT/pages/index.adoc --root docs > index.html
----

[cols="2,4"]
|===
|Option |Meaning

|`--root <dir>`
|The workspace root, so that includes, xrefs and images resolve across components. Without it, the root is the parent of the nearest Antora component (the directory above the one holding `antora.yml`), or the file's own directory outside Antora. `.` is accepted.

|`--output <file.html>`
|Write to this file instead of standard output.

|`--parser acdc\|asciidoc-parser`
|Choose the document parser. The default is `acdc`. `asciidoc-parser` is a development comparison, and the application always uses `acdc`.
|===

Images and diagrams are written as absolute `file://` URLs, so the file shows them wherever it is opened on the same machine.
A usage or runtime error exits with 2, as for the other subcommands.

[[pdf]]
== pdf

`pdf` exports a page, or a whole component version, as a PDF.
See xref:pdf-export.adoc[Exporting to PDF] for themes, fonts and what the output contains.

[source,sh]
----
adocfoundry-cli pdf docs/modules/ROOT/pages/index.adoc
adocfoundry-cli pdf docs --output docs.pdf --theme acme-theme.yml
adocfoundry-cli pdf docs --root . --component 2.0@guide --standard pdf-a-2a --standard pdf-ua-1
adocfoundry-cli pdf --profile admin-guide .
----

A file argument exports that page as an article.
By default the PDF is written beside the page with a `.pdf` extension.

A directory that holds an `antora.yml`, or `--component`, exports the component version as a book in navigation order.
By default the PDF is `<name>.pdf` in the current directory.
Without a version, `--component` uses the latest version of the component.

[cols="2,4"]
|===
|Option |Meaning

|`--root <dir>`
|The workspace root, so that includes, xrefs and images resolve across components. Without it, the root is the parent of the component directory, or the parent of the nearest Antora component for a page.

|`--component [<version>@]<name>`
|Export this component version as a book, with coordinates written as Antora writes them.

|`--profile <name>`
|Export the publication profile `[pdf.profiles.<name>]` from the settings. The workspace root is the argument, `--root <dir>`, or else the current directory. `--output`, `--theme`, `--fonts-dir` and `--typst` win over the profile's values, and `--standard` adds to its standards. See xref:pdf-export.adoc#publication-profiles[Publication profiles].

|`--theme <name\|file.yml>`
|A bundled theme, a theme found as `<name>-theme.yml` in the themes directory, or a theme file. It overrides the page's `pdf-theme` and `[pdf] theme`.

|`--fonts-dir <dir>`
|The directory of the theme's fonts, in place of the page's `pdf-fontsdir` and `[pdf] fonts_dir`. The bundled fonts remain available.

|`--output <file.pdf>`
|Where to write the PDF.

|`--standard pdf-a-1b\|pdf-a-1a\|pdf-a-2a\|pdf-ua-1`
|Make the PDF conform to a standard. Repeat the option to ask for more than one. Standards in `[pdf] standards` also apply.

|`--typst <file.typ>`
|Also write the generated Typst source, for inspection.
|===

The command waits for diagrams to render, then prints `<output> (<n> pages)` on standard output.
Warnings, such as an unknown theme key or a missing image, print on standard error as `path:line: warning: message`.
An export that fails exits with 1, and a usage error exits with 2.

[[git-status]]
== git-status

`git-status` reports the Git state of the AsciiDoc files under `<root>`.
It finds the repository that holds `<root>` and does not run the `git` executable.

[source,sh]
----
adocfoundry-cli git-status docs
adocfoundry-cli git-status docs --format json
----

The default `text` format prints `branch <head>`, then one line per changed AsciiDoc file in the style of `git status --short`.
The head reads `main`, `detached @ 1a2b3c4` or `no commits yet`.
A file with changes against HEAD ends with the number of changed line runs; a deleted file has no number.

[source,text]
----
branch main
?? docs/new.adoc
 M docs/page.adoc (2 changed)
----

`--format json` prints one object.
`index` and `worktree` are each one of `unmodified`, `added`, `modified`, `deleted`, `renamed`, `untracked`, `ignored` or `conflicted`.

[source,json]
----
{
  "head": "main",
  "files": [
    { "path": "docs/new.adoc", "index": "unmodified", "worktree": "untracked", "hunks": 0 },
    { "path": "docs/page.adoc", "index": "unmodified", "worktree": "modified", "hunks": 2 }
  ]
}
----

If `<root>` is not in a Git repository the command fails with an error and exits with 2.
The other subcommands do not look at Git.

[[doctor]]
== doctor

`doctor` prints a report of the program, the system, the PDF setup, the tools it can find and the settings in force.
Paste it into an issue when reporting a problem.

[source,sh]
----
adocfoundry-cli doctor
adocfoundry-cli doctor docs
adocfoundry-cli doctor docs --format json
----

The report reads the user settings file the application reads, `adocfoundry/adocfoundry.toml` in the platform's configuration directory.
With `<root>`, it also reads that workspace's `.adocfoundry.toml`.
It holds no page content.
The command always exits with 0, even when it reports a missing tool or font.

[source,text]
----
AdocFoundry diagnostics

Program
  Version:  adocfoundry-cli 0.5.0
  Engine:   adoc-engine 0.5.0
  Build:    release
  Features: typst, git

System
  OS:           macOS 26.6.2
  Architecture: aarch64

PDF
  Theme:           default (bundled)
  Fonts directory: none (the bundled fonts only)
  Font families:   Noto Serif, M+ 1mn
  Fonts:           all found

Tools
  asciidoctor: /opt/homebrew/bin/asciidoctor (Asciidoctor 2.0.26 [https://asciidoctor.org])
  dot:         /opt/homebrew/bin/dot (dot - graphviz version 16.1.0 (20260904.0139))
  plantuml:    not found on PATH
  d2:          not found on PATH
  git:         /usr/bin/git (git version 2.54.0)

Settings
  User settings:      /Users/you/Library/Application Support/adocfoundry/adocfoundry.toml (not found)
  Workspace settings: docs/.adocfoundry.toml (not found)
  Workspace root:     docs
  Git:                on
  Warnings:           none
----

The sections, in order, are as follows.

Program::
The version of the program and of the engine, whether the build is `debug` or `release`, and the features it was built with (`typst` and `git`).

System::
The operating system and its version, and the architecture.

PDF::
The theme, resolved through `[pdf] themes_dir`, which reads `default (bundled)` or the theme file's path; the `[pdf] fonts_dir`, or `none (the bundled fonts only)`; and the font families the theme names.
Either `Fonts: all found` follows, or one `Missing` line for each font that is not found, such as `font X for Y not found`.
Any warnings from loading the theme appear as `Theme warning` lines.

Tools::
`asciidoctor`, `dot` (Graphviz), `plantuml`, `d2` and `git`.
Each shows its path and the first line of its version output.
A tool that is missing shows why: `not found on PATH`, or, for a setting that points nowhere, `not found: [tools] asciidoctor is X, which is not a file`.
A tool that does not answer within 15 seconds is reported as not answering.
`[tools] asciidoctor`, `[tools] git`, `[tools] dot`, `[tools] plantuml` and `[tools] d2` are honoured.

Settings::
The paths of the user and workspace settings files, each marked `(not found)` when missing, the workspace roots, whether Git is on or off, and each settings warning, or `Warnings: none`.

`--format json` prints one object of sections, each a title and its labelled lines.

[source,json]
----
{
  "sections": [
    {
      "title": "Program",
      "lines": [
        { "label": "Version", "value": "adocfoundry-cli 0.5.0" }
      ]
    }
  ]
}
----

The desktop application shows the same report, with its display details added.
See xref:using-the-editor.adoc#reporting-a-problem[Reporting a problem].

== Using it in CI

[source,yaml]
----
- name: Check the documentation
  run: adocfoundry-cli check docs --fail-on warning
----

The archives attached to each release contain the binary for Linux, macOS and Windows, so no toolchain is needed.
Because the checker shares its code with the editor, it reports exactly what an author sees.
See xref:diagnostics.adoc[Diagnostics] for the codes.

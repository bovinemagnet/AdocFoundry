= The link graph
Paul Snow
:revnumber: 0.0.0
:description: The graph of how a workspace's pages, partials and navigation files link to each other: the graph window, the local graph in the sidebar, and what counts as a link.

AdocFoundry draws how the pages of a workspace link to each other.
The graph window shows the whole workspace.
The Graph tab in the sidebar shows the active page and its neighbours.
Both are drawn from the links the engine already resolves for link following, so they agree with Find References and with xref:diagnostics.adoc[the diagnostics].

The same graph is available without the app from xref:command-line.adoc#graph[`adocfoundry-cli graph`] and the xref:mcp-server.adoc[MCP server]'s `link_graph` tool.

== What the graph holds

=== Nodes

[cols="1,4"]
|===
|Node |What it is

|Page
|An AsciiDoc page that nothing has to include.

|Partial
|A file reached by `include::`. Outside Antora, a file that is included counts as a partial.

|Navigation file
|A file listed under `nav` in an `antora.yml`.

|Unresolved target
|The text of a link that points at nothing. These "ghost" nodes are hidden unless you turn on Unresolved.
|===

Images are not nodes.
An `include::` of a file that is not AsciiDoc, such as source code, makes no link.

=== Edges

[cols="1,2,3"]
|===
|Kind |Drawn as |Made by

|Xref
|Solid line
|An `xref:` or `+<<…>>+` link from one page to another.

|Include
|Dashed line
|An `include::` of an AsciiDoc file.

|Navigation
|Dotted, bowed line in its own colour
|An entry in a navigation file. The nav file links to the page of each top-level entry, and each entry's page links to the pages of its child entries. An entry with text but no page hands its children to its nearest ancestor that has a page.
|===

A link to a target that does not resolve is drawn dash-dot.
Several links of one kind between the same two files make one heavier edge with a count.
A navigation file's own xrefs are not drawn again as xref edges.

Some references make no link, so the graph does not report problems that are not there:

* A dynamic target, such as `+include::{attr}/x.adoc[]+`, makes no link.
* An include inside `ifdef`, `ifndef` or `ifeval` that does not resolve makes no link.
* An xref into a component or version that is not in the workspace is taken to be published elsewhere and makes no link.

An _orphan_ is a page with no links in or out, navigation included.
A page listed in a navigation file is therefore never an orphan.

== The graph window

Show Graph (`view.graph`, in the View menu) opens the graph in its own window.
It is bound to kbd:[Cmd+K] then kbd:[G] on macOS and kbd:[Ctrl+K] then kbd:[G] on Linux and Windows.
This is a chord: hold the modifier for kbd:[K] only, release it, then press kbd:[G] on its own.

There is one graph window for each workspace window.
Choosing Show Graph again brings it to the front.
The window shows "Building graph…" until the first build is done.

The window remembers its size and position, and keeps them with the last session, so after a restart it comes back on the screen you put it on.
The first time it opens at 1100 by 760 pixels, centred.
If less than half of the saved place is on a display, because a screen has been unplugged, it opens centred on the main display and is made smaller to fit.

=== The toolbar

[cols="1,4"]
|===
|Control |What it does

|Search
|Highlights the nodes whose title or path matches and dims the rest.

|Partials, Navigation, Orphans, Unresolved
|Toggles that show or hide each kind of node.

|Component menu
|Limits the graph to the components you choose.

|Colour
|Colours nodes by Component, Module or Family. Clicking the button moves to the next.

|Workspace or Local
|Switches between the whole workspace and the active page's neighbourhood. Local has a depth of 1 to 3 links.

|Zoom out, Zoom in, Fit
|Change the zoom. Fit shows the whole graph.

|Reset Layout
|Throws away pinned nodes and lays the graph out again.
|===

=== The canvas

* Drag the background to pan.
* Scroll the wheel, or pinch, to zoom around the pointer.
* Drag a node to pin it where you drop it. Release with kbd:[Alt] held to unpin it.
* Hover over a node to highlight it and its neighbours and dim the rest.
* Click a node to select it and open its page in the preview tab. Double-click keeps the page open.
* kbd:[Shift]-click a node to show the xref:graph-view.adoc#_the_path_between_two_pages[path] from the selected node to it. The selection stays where it was and nothing opens.
* kbd:[Tab] and kbd:[Shift+Tab] move the selection between nodes in title order. kbd:[Enter] opens the selected node.

A node is sized by how many links it has.
Partials are hollow, unresolved targets have a dashed outline, and navigation files are squares.
Labels show when you have zoomed in, and always for the hovered and selected node, their neighbours and the search matches.

Right-click a node for its menu:

[cols="1,4"]
|===
|Item |What it does

|Open
|Opens the page in a tab.

|Open to the Side
|Opens the page in a tab and pins the docked xref:preview.adoc[preview] to it, so it shows beside the page you are editing. The app has no editor split, so the preview is the side.

|Insert Xref at Caret
|Page nodes only.
Writes `+xref:<target>[]+` into the active page in the main window at its caret, or at the end of the page if the caret has not moved since it opened.
It is set apart by a space when it would follow a word.

|Include at Caret
|Partial nodes only.
Writes `+include::<target>[]+` on the caret's line when that line is blank, otherwise on a new line after it.

|Find References
|Lists the references to the page.

|Reveal in Files
|Selects the file in the Files panel.

|Show Path from Selection
|The last item, after a separator.
It is there when a node other than the one you right-clicked is selected.
Shows the xref:graph-view.adoc#_the_path_between_two_pages[path] from the selected node to this one.
|===

The target is the shortest resource id that names the file from the active page.
For example, it is `+configure.adoc+` in the same module, `+admin:users.adoc+` in another module, `+reference:ROOT:api.adoc+` in another component, and `+partial$note.adoc+` for an include.
A version is written only when it is needed to reach the file.
Outside Antora it is a path relative to the active page.
The link is checked to resolve before it is written.

Insert Xref at Caret and Include at Caret are greyed out when there is no active AsciiDoc page, when the node is the active page itself, or when the page cannot name the file, such as an Antora page and a file outside any component.
Either one is an ordinary edit, so Undo takes it out, and the new edge appears in the graph as the page is re-indexed.

Right-click an unresolved target, shown when the Unresolved toggle is on, and its menu offers *Create Page* below the greyed-out "Unresolved target" label.
It makes the page the broken link expects and opens it in a tab.
The file goes where the link points: in the module the xref resolves to, in that module's `pages` folder, at the path the xref names.
For example, `+xref:admin:setup/roles.adoc[]+` makes `modules/admin/pages/setup/roles.adoc`.
Its title is made from the file name: hyphens and underscores become spaces and the first letter is capitalised, so `missing-page.adoc` gets `= Missing page`.
The page is not added to the navigation.

Create Page is `page.new` underneath, so one Undo takes it back on the same terms as xref:using-the-editor.adoc#new-page[New Page].
The file is deleted and its tab closed only while it still holds what was written and has no unsaved edits.
Once the page exists, the unresolved target becomes a page node with its edges, with no rebuild.

An unresolved target of an include offers *Create Partial* instead.
It makes an empty file where the include expects it and opens it.
For a resource id with a family, such as `+include::partial$tips.adoc[]+`, the file goes in that family's folder of the module, so this makes `modules/ROOT/partials/tips.adoc`.
For a plain path, such as `+include::parts/_gone.adoc[]+`, the file goes relative to the including page's folder, which also works outside Antora.
The file must be inside a workspace folder.
Undo deletes it on the same terms as New Page.

The menu shows Create Page for the targets of xrefs and Create Partial for the targets of includes, and both when a target is named both ways.
When neither can be made, Create Page shows greyed out.

Create Page is unavailable when:

* The link is outside an Antora module.
* The target is in another family, such as `partial$`.
* The target is in a module or component the workspace does not have.
* The path leaves the `pages` folder with `../`.
* Different links that share the target's text expect different files.

Create Partial is unavailable when:

* The target is dynamic (it uses an attribute, such as `+{snippets}/x.adoc+`) or is a URL.
* The target is not an AsciiDoc file.
* A resource id names a component, version or module the workspace does not have.
* A resource id's path leaves its family's folder with `../`.
* The file would fall outside every workspace folder.
* Different includes that share the target's text expect different files.

The side panel lists the selected node's *Links out* and *Backlinks*, one row for each neighbour.
A row names every kind of link between the two, such as `xref · nav`.
Clicking a row selects that node.

== Export the graph

Export Graph… (`graph.export`, in the File menu and the command palette) saves the link graph as an image.
It has no default key binding.
It asks where to save.
A file name ending in `.png` gets a PNG drawn at twice the graph's size.
Any other name gets an SVG.

With the graph window open, the image is what the window shows: its scope (workspace or local), its filters, its colouring and every node where the layout has it, pinned nodes included.
With no graph window, the whole workspace is laid out afresh with the `[graph]` settings.
The image is drawn on a light or a dark background, following the app's theme.
A notification says where the file was saved, with an Open button.

=== What the image holds

Nodes and edges look as they do on the canvas:

* Pages are filled, partials are hollow, unresolved targets have a dashed outline and navigation files are squares.
* Xrefs are solid, includes are dashed, navigation links are dotted and bowed, and links to unresolved targets are dash-dot.
Repeated links make a heavier edge.
* Nodes are coloured by component, module or family, as in the window.
* Every node is labelled with its title.
In a browser, hovering over a node shows its title.

The image holds titles only, never file paths.
The same layout always gives the same file.

The same image is available without the app.
`adocfoundry-cli graph --format svg` prints it, as described in xref:command-line.adoc#graph[the command line reference], and the xref:mcp-server.adoc[MCP server]'s `link_graph` tool returns it with `format: svg`.

== The path between two pages

The graph can show the shortest chain of links from one page to another.
It works in the graph window and in the Graph panel of the sidebar.

Click a node to select it, then kbd:[Shift]-click another node.
The graph shows the shortest path from the selected node to the one you kbd:[Shift]-clicked.
The selection stays where it was, and the kbd:[Shift]-click opens nothing.
You can also right-click the second node and choose *Show Path from Selection*, which is the last item of the node menu.

The nodes on the path are labelled in order, such as `1. Home` and `2. Install`, and its links are drawn.
Everything else is dimmed.

The path is found among what the view shows.
It follows the scope, whole workspace or local neighbourhood, and the filters.
With Navigation off, navigation links are not followed and navigation files are not entered.
With Partials off, includes are not followed and partials are not entered.

By default the path follows links only in their direction, as a reader clicks them.

=== The Path panel

The window's side panel lists the path under *Path*.
Each step shows its number and title.
Below the title are the kinds of link that reached it, such as `by xref · nav`.
When the path goes against a link's direction, the step adds "followed back".

* Click a step to select that node and bring it into view.
* The *Directed* button switches to *Either way*, which follows links in both directions, and back.
* *Clear* removes the path, and so does kbd:[Esc] in the graph.

When there is no path, the panel says "No path from A to B." with the two titles.
The path updates as the graph changes.

Among equally short paths, one is chosen consistently, so the same graph always gives the same path.

=== Without the app

`adocfoundry-cli graph <root> --path <from> <to>` prints the graph along the shortest path, as described in xref:command-line.adoc#graph[the command line reference].
The xref:mcp-server.adoc[MCP server]'s `link_graph` tool does the same with `scope: "path"`.

== The local graph

The *Graph* tab is the last tab of the sidebar.
Show Local Graph (`view.local_graph`) opens it, bound to kbd:[Cmd+K] then kbd:[Shift+G] on macOS and kbd:[Ctrl+K] then kbd:[Shift+G] on Linux and Windows.

It shows the active page and the pages linked to it, to the depth you set, from 1 to 3.
It follows the active tab.
When an image or a file that is not AsciiDoc is active, it says "No page".
Partials and Navigation toggles hide those nodes, and a button opens the graph window.

Below the canvas is the page's place in the navigation, drawn as trails:

[source,text]
----
nav.adoc › Introduction › Configuration › Settings reference
----

A trail is the navigation file, the entries above the page, the page in bold, then its child entries.
There is one trail for each place the page is listed.
A page in no navigation shows "Not in any navigation".
Clicking an entry that has a page opens it as a preview.
The trails are hidden when Navigation is turned off.

After the trails come the *Links out* and *Backlinks* lists.
Clicking a row opens the page as a preview.

== Show in Graph

Show in Graph is the last item of a page tab's context menu, and is in the Files panel's context menu for AsciiDoc files.
It opens the graph window with that page selected.

== Reset Graph Layout

Reset Graph Layout (`graph.reset_layout`, in the View menu) resets the layout of both the sidebar panel and the window.

== Settings

The `[graph]` table sets what the graph starts with.
See xref:settings.adoc[Settings].

== Keeping it current

The graph is built once after the workspace is indexed.
After that, typing, saving, changes on disk, renames and new pages update it file by file.
Only a change to the catalog's components, versions, modules or navigation files rebuilds all of it, in the background.

= Settings
Paul Snow
:revnumber: 0.0.0
:description: The TOML user and workspace settings files and every key they accept.

Settings are TOML.
There are two layers, and the workspace layer is applied after the user layer.

[cols="1,3"]
|===
|Layer |File

|User
|`adocfoundry/adocfoundry.toml` in the platform configuration directory: `~/.config` on Linux, `~/Library/Application Support` on macOS and `%APPDATA%` on Windows.
Open Settings creates it if it is missing.

|Workspace
|`.adocfoundry.toml` at the root of the workspace.
|===

Saving either file applies it, whether in AdocFoundry or in another editor while a workspace is open.
Reload Settings re-reads both.

[#state-folder]
The app also keeps two folders and two files in its state folder, `adocfoundry` under the platform's local state location: `$XDG_STATE_HOME/adocfoundry` on Linux, normally `~/.local/state/adocfoundry`; `~/Library/Application Support/adocfoundry` on macOS; and `%LOCALAPPDATA%\adocfoundry` on Windows.
It is local, never roaming, because the settings file is often synchronised or kept in a dotfiles repository and copies of pages should not travel with it.
The folders are `recovery`, holding copies of unsaved pages until they are saved or closed, and `history`, holding saved versions of pages.
The files are `session.json`, the last session, and `recent-folders.json`, the folders opened recently.
`update-state.toml` and `sidebar-state.json` stay beside the settings file.
See xref:using-the-editor.adoc#crash-recovery[Recovering unsaved changes], xref:using-the-editor.adoc#local-history[Local history] and xref:using-the-editor.adoc#restoring-the-session[Restoring the last session].

== Example

[source,toml]
----
[editor]
font_family = "JetBrains Mono"   # falls back to the platform monospace
font_size = 13
soft_wrap = true
tab_width = 2
theme = "auto"                   # auto | light | dark; the older setting, used when [appearance] mode is not set
preview_tabs = true              # false: every page you open stays open
auto_save = "off"                # off | on_focus_change | after_delay

[appearance]                     # user file only
mode = "auto"                    # auto | light | dark
light_theme = "Solarized Light"  # a light theme's name; the native default when left out
dark_theme = "Tokyo Night"       # a dark theme's name; the native default when left out
# themes_dir = "themes"          # relative to the user settings file's folder; ~/ is the home folder
font_scale = 1.0                 # text this many times the default size, 0.5 to 3

[sidebar]
remember_expansion = true        # remember opened and closed branches (user file only)
follow_active = true            # reveal the active page in Files, Navigation and Modules

[sidebar.navigation]
default_expansion = 2            # 0 or more, or "all"

[sidebar.modules]
default_expansion = 2            # to keep the old fully open trees, use "all" in both

[workspace]
ignore = [".cache", ".git", ".zed", "node_modules", "build", "target", "dist", ".idea", ".gradle"]

[tools]
asciidoctor = ""                 # optional absolute path; discovered on PATH if empty
git = ""                         # optional absolute path; discovered on PATH if empty
dot = ""                         # optional absolute path; discovered on PATH if empty
plantuml = ""                    # optional absolute path; discovered on PATH if empty
d2 = ""                          # optional absolute path; discovered on PATH if empty
diagram_timeout = 30             # seconds a diagram may render (Mermaid included) before it is stopped
node = ""                        # optional absolute path to node; npm is found beside it, else on PATH (Build Site)
build_timeout = 600              # seconds Build Site may run, npm install included, before it is stopped

[templates]
dir = "templates"                # folder of project templates, one per subfolder (also allowed in a workspace file, inside the workspace)

[git]
enabled = true                   # false: no repository is discovered
show_markers = true              # reserved for change markers
blame_on_hover = false           # tooltip on a line number
remote = "origin"                # the remote used for links to a line

[git.hosts]
"git.example.com" = "gitlab"     # github | gitlab | bitbucket | azure

[pdf]
theme = "default"                # a bundled name, a theme name or a .yml path
themes_dir = "resources/themes"  # where <name>-theme.yml is found
fonts_dir = "resources/fonts"
site_url = "https://docs.example.com"
standards = ["pdf-a-2a"]         # pdf-a-1b | pdf-a-1a | pdf-a-2a | pdf-ua-1

[pdf.profiles.quick-start]       # a named PDF, run by name
page = "docs/modules/ROOT/pages/quick-start.adoc"
output = "build/quick-start.pdf"

[spelling]
enabled = true                   # underline misspelt words in prose
language = "en_GB"               # for pages with no lang attribute
dictionaries = ""                # folder of extra Hunspell .aff/.dic files (user file only)

[graph]
depth = 1                        # the local graph's starting depth, 1 to 3
show_partials = true
show_nav = true
show_orphans = true
show_unresolved = false
colour_by = "component"          # component | module | family
group = "off"                    # off | module | component
layout = "force"                 # force | mind-map | radial

[quality]
fail_on = "warning"
require_complete = true
# providers = []

[quality.rules]
"quality.navigation.unlisted-page" = "info"

[[quality.exclusions]]
rule = "quality.navigation.unlisted-page"
resource = "product:ROOT:internal-notes.adoc"
reason = "Deliberately unlisted staff-only page"

[updates]
check = true                     # look for a newer release at start-up
----

== Keys

[cols="2,2,2,4"]
|===
|Key |Type |Default |Meaning

|`editor.font_family`
|string
|`"JetBrains Mono"`
|The editor font. Falls back to the platform monospace font.

|`editor.font_size`
|positive integer
|`13`
|The editor font size.
`appearance.font_scale` multiplies it.

|`editor.soft_wrap`
|boolean
|`true`
|Wrap long lines.

|`editor.tab_width`
|positive integer
|`2`
|The width of a tab.

|`editor.preview_tabs`
|boolean
|`true`
|Open pages you browse to in a temporary preview tab, which the next page you browse to replaces. When `false`, every page you open stays open until you close it. See xref:using-the-editor.adoc#preview-tabs[Preview tabs].

|`editor.auto_save`
|`"off"`, `"on_focus_change"` or `"after_delay"`
|`"off"`
|Save pages without asking. `"after_delay"` saves a page one second after your last edit to it. `"on_focus_change"` saves a page when you leave its tab and every edited page when the AdocFoundry window loses focus. Any other value is ignored with a warning and leaves auto-save off. See xref:using-the-editor.adoc#auto-save[Auto-save]. The xref:language-server.adoc[language server] ignores this setting and never saves.

|`editor.theme`
|`"auto"`, `"light"` or `"dark"`
|`"auto"`
|The colour theme: the older setting, used for the mode when `appearance.mode` is not set.
When both are set, `appearance.mode` wins and a warning says `editor.theme` is ignored.
Choosing a theme in AdocFoundry takes this line out of the user settings file.

|`appearance.mode`
|`"auto"`, `"light"` or `"dark"`
|`editor.theme`'s value, else `"auto"`
|Whether the application follows the system's light or dark appearance or stays light or dark.
User file only.
See xref:using-the-editor.adoc#themes[Themes].

|`appearance.light_theme`
|string
|the native Default Light
|The name of the light theme to show.
A name that names no light theme, whether missing or a dark theme's, shows the native default with a warning, and the name is kept so the theme is used again once it is back.
User file only.

|`appearance.dark_theme`
|string
|the native Default Dark
|The name of the dark theme to show, treated as `appearance.light_theme` is.
User file only.

|`appearance.themes_dir`
|string
|`themes`
|The folder of your own theme files, relative to the user settings file's folder; `~/` is the home folder.
User file only.

|`appearance.font_scale`
|number
|`1`
|A multiplier of the default text size, as a zoom: `1.5` draws text half as large again and `2` twice as large.
From `0.5` to `3`, whole or not; anything else, or a value that is not a number, warns and keeps `1`.
It scales the whole interface together: panels, menus, dialogs, the preview, the visual editor, the graph's labels and the source editor, whose `editor.font_size` it multiplies (`13` at `1.5` draws at `19.5`); spacing sized to the text grows with it.
It follows every theme, and takes effect when the settings are read again, without a restart.
User file only.
These settings never affect PDF export (`pdf.theme`), HTML or the Antora site.

|`sidebar.follow_active`
|boolean
|`true`
|Reveal the active page in Files, Navigation and Modules whenever another file becomes active, opening the folders and branches above it. When `false`, the panels do not select or open anything by themselves. See xref:using-the-editor.adoc#following-the-active-page[Following the active page].

|`sidebar.remember_expansion`
|boolean
|`true`
|Remember the branches you open and close in Navigation and Modules, for each workspace and panel, in `sidebar-state.json` beside the user settings file. When `false`, a reopened workspace starts from the defaults and earlier saved state is ignored. User file only. See xref:using-the-editor.adoc#how-far-the-trees-open[How far the trees open].

|`sidebar.navigation.default_expansion`
|integer of 0 or more, or `"all"`
|`2`
|How many levels of branches the Navigation tree opens, counting the component version row as level 1. `0` shows only the component versions, closed. `"all"` opens every branch, as earlier releases did. A depth greater than the tree opens everything.

|`sidebar.modules.default_expansion`
|integer of 0 or more, or `"all"`
|`2`
|The same for the Modules tree, whose levels are component version, module, family and resource. Set both this and the Navigation key to `"all"` to keep fully expanded trees.

|`workspace.ignore`
|array of strings
|`[".cache", ".git", ".zed", "node_modules", "build", "target", "dist", ".idea", ".gradle"]`
|Folder names skipped by indexing, Antora discovery and the file watcher, and hidden in Files unless Show Excluded Files is on. A workspace file's list replaces the default rather than adding to it.

|`tools.asciidoctor`
|string
|`""`
|An absolute path to `asciidoctor`. Discovered on `PATH` when empty. Used by the language server's preview only; the language server falls back to the engine's own preview when it is empty and `asciidoctor` is not on `PATH`. The application's preview renders in process and does not use it.

|`tools.git`
|string
|`""`
|An absolute path to `git`. Discovered on `PATH` when empty. Used to push, and to make signed commits. Everything else in Git is done in process.

|`tools.dot`
|string
|`""`
|An absolute path to Graphviz's `dot`, for `graphviz` and `dot` diagram blocks. Discovered on `PATH` when empty. If the path does not exist, the diagram shows its source with the reason.

|`tools.plantuml`
|string
|`""`
|An absolute path to `plantuml`, for `plantuml` and `uml` diagram blocks. Discovered on `PATH` when empty. If the path does not exist, the diagram shows its source with the reason.

|`tools.d2`
|string
|`""`
|An absolute path to `d2`, for `d2` diagram blocks. Discovered on `PATH` when empty. If the path does not exist, the diagram shows its source with the reason.

|`tools.diagram_timeout`
|integer
|`30`
|The number of seconds a diagram may render before it is stopped: a Graphviz, PlantUML or D2 process is killed, and Mermaid, which renders in process, is stopped at the same deadline. It must be a positive whole number; `0` or any other value is a warning and keeps the default. Like the other `[tools]` keys, it is read from the user settings file only.

|`tools.node`
|string
|`""`
|An absolute path to `node`, for Build Site. npm is the one beside it (`npm.cmd` on Windows), else the first `npm` on `PATH`, and the folder of `node` is put first on the build's `PATH`. Discovered on `PATH` when empty. Without npm, Build Site is greyed out with a hint. User file only.

|`tools.build_timeout`
|integer
|`600`
|The number of seconds a site build may run, `npm install` included, before it and every process it started are stopped. A build that writes more than 8 MiB of output is also stopped. User file only.

|`templates.dir`
|string
|`"templates"`
|The folder of project templates for New Antora Project, each template a subfolder holding a `template.toml`. In the user file it is relative to the settings file's folder, or starts with `~/` for the home folder, and by default is the `templates` folder beside it. A workspace file may set it too, relative to the workspace and only to a folder inside it; otherwise it is ignored with a warning. See xref:using-the-editor.adoc#project-templates[Project templates].

|`git.enabled`
|boolean
|`true`
|Discover the Git repository of each workspace root, and show its branch and track its changes. When `false`, nothing is discovered and the workspace behaves as if it were outside a repository. The language server leaves Git off unless the user file sets this to `true`.

|`git.show_markers`
|boolean
|`true`
|Show change markers in the source and visual editors. When `false`, both hide them.

|`git.blame_on_hover`
|boolean
|`false`
|Show the commit that last changed a line in a tooltip when the pointer rests on its line number. See xref:using-the-editor.adoc#blame[Blame].

|`git.remote`
|string
|`"origin"`
|The remote used for links to a line on the hosting site.

|`git.hosts`
|table of strings
|empty
|Names the kind of a self-hosted site, host name to `"github"`, `"gitlab"`, `"bitbucket"` or `"azure"`. Host names are matched without regard to case. A table with any other kind is ignored with a warning. See xref:using-the-editor.adoc#remote-links[Links to a line on the hosting site].

|`pdf.theme`
|string
|`"default"`
|The theme for PDF export: a bundled name (`default`, `default-sans`, `default-for-print` or `base`), a theme name found in `pdf.themes_dir`, or a path to a `.yml` file. A page's `pdf-theme` attribute and the command line's `--theme` take precedence.

|`pdf.themes_dir`
|string
|none
|The directory searched for `<name>-theme.yml`, relative to the first workspace root. A page's `pdf-themesdir` attribute takes precedence.

|`pdf.fonts_dir`
|string
|none
|A directory of theme fonts, relative to the first workspace root. A page's `pdf-fontsdir` attribute and `--fonts-dir` take precedence. The bundled fonts are always available.

|`pdf.site_url`
|string
|none
|The base address of the published site. In an export, a cross reference to a page the PDF does not hold links to that page's address on the site. When it is not set, the playbook's `site.url` is used. Without either, such a reference is plain text.

|`pdf.standards`
|array of strings
|empty
|Standards every export conforms to: `"pdf-a-1b"`, `"pdf-a-1a"`, `"pdf-a-2a"` and `"pdf-ua-1"`. The command line's `--standard` adds to these.

|`pdf.profiles.<name>`
|table
|none
|A named publication profile: exactly one of `page`, `component` or `nav`, and optionally `output`, `theme`, `fonts_dir`, `standards` and `attributes`. A workspace profile replaces a user profile of the same name. A profile that is not valid is left out with a warning. See xref:pdf-export.adoc#publication-profiles[Publication profiles].

|`history.enabled`
|boolean
|`true`
|Keep the saved text of each page in local history. When `false`, no history is kept. See xref:using-the-editor.adoc#local-history[Local history].

|`history.keep_days`
|positive integer
|`30`
|Versions older than this many days are removed.

|`history.max_versions`
|positive integer
|`50`
|The most versions kept for each page. The oldest go first.

|`history.max_size_mb`
|positive integer
|`256`
|The history of every page together is kept under this many megabytes. The oldest versions of any page are removed first.

|`spelling.enabled`
|boolean
|`true`
|Underline misspelt words in prose, in the source and visual editors, and offer suggestions. When `false`, nothing is checked. See xref:using-the-editor.adoc#spelling[Spelling].

|`spelling.language`
|string
|`"en_GB"`
|The language of pages that have no `lang` attribute. British (`en_GB`) and American (`en_US`) English are bundled. A page in a language with no dictionary is not checked. See xref:using-the-editor.adoc#spelling[Spelling].

|`spelling.dictionaries`
|string
|none
|A folder of extra Hunspell dictionaries, each a `.aff` and `.dic` pair named for its language, such as `de_DE.aff` and `de_DE.dic`. User file only. See xref:using-the-editor.adoc#spelling[Spelling].

|`graph.depth`
|integer, 1 to 3
|`1`
|How many links out the local graph starts with. See xref:graph-view.adoc[The link graph].

|`graph.show_partials`
|boolean
|`true`
|Show partials in the graph.

|`graph.show_nav`
|boolean
|`true`
|Show navigation files and their edges.

|`graph.show_orphans`
|boolean
|`true`
|Show pages with no links in or out.

|`graph.show_unresolved`
|boolean
|`false`
|Show the targets of links that do not resolve as nodes of their own.

|`graph.colour_by`
|`"component"`, `"module"` or `"family"`
|`"component"`
|What the graph window colours nodes by.

|`graph.group`
|`"off"`, `"module"` or `"component"`
|`"off"`
|What the graph window groups nodes by when it opens. See xref:graph-view.adoc#graph-groups[Groups]. Any other value warns and keeps the default.

|`graph.layout`
|`"force"`, `"mind-map"` or `"radial"`
|`"force"`
|How the graph window and the Graph panel lay the graph out when they open. See xref:graph-view.adoc#graph-mind-map[Mind maps]. Any other value warns and keeps the default.

|`quality.enabled`
|boolean
|`false`
|Keeps the documentation quality audit current from the moment a workspace opens, so the Quality overview and the Problems panel show it from the start. Without it, the app keeps the audit once Run Audit is used. `adocfoundry-cli audit` audits whether it is set or not.

|`quality.fail_on`
|string
|`"error"`
|The lowest severity that fails `adocfoundry-cli audit`: `none`, `warning` or `error`.

|`quality.require_complete`
|boolean
|`false`
|Makes an audit that could not cover everything in scope fail with exit code 2 instead of passing.

|`quality.rules.<rule>`
|string
|the rule's own, `"warning"`
|The severity of one of the audit's rules, `off`, `info`, `warning` or `error`, keyed by its name, such as `"quality.navigation.unlisted-page"`. Existing diagnostics keep their own severities.

|`quality.exclusions`
|array of tables
|none
|Findings accepted for one resource each: `rule` (a rule or diagnostic code), `resource` (a resource ID naming at least its component and module, such as `product:ROOT:internal.adoc`; with no version it covers every version, and `~@` only the versionless component) and `reason`, which is required. Excluded findings stay in the report with their reason and never fail it.

|`quality.providers`
|array of strings
|`[]`
|The optional providers to run: `compatibility`, `external-links`, `page-age` and `vale`. None is in this build yet, so an enabled one is reported unavailable and leaves the audit partial. Both files may set it, and both files' providers are enabled. See xref:quality-audit.adoc[].

|`updates.check`
|boolean
|`true`
|Look for a newer release at start-up, at most once a day, and tell you once when there is one. The app reads GitHub's latest release for the repository through the system's `curl`; without `curl`, or offline, nothing happens. The request sends only the app's version in its user agent. When `false`, the app never checks unasked. Check for Updates in the command palette checks whatever this says. See xref:getting-started.adoc#updates[Updates].
|===

See xref:pdf-export.adoc[Exporting to PDF].

== What a workspace file may set

A workspace file may override `editor.*`, `templates.dir`, `sidebar.navigation.default_expansion`, `sidebar.modules.default_expansion`, `sidebar.follow_active`, `workspace.ignore`, `pdf.*`, `graph.*`, `quality.*`, `spelling.enabled` and `spelling.language`.
The two depths override separately.
Both files may set `[quality]`: a rule's severity from the workspace file wins, and the exclusions and the providers of both files apply.
`tools.*` is accepted only in the user file, so a repository cannot point the editor at an executable of its choosing.
`git.*` is also accepted only in the user file, so a repository cannot change how the editor treats it.
`sidebar.remember_expansion` is also accepted only in the user file, because it decides what is saved outside the repository.
`updates.*` is also accepted only in the user file, so a repository cannot make the editor reach the network.
`history.*` is also accepted only in the user file, because history is kept outside the repository.
`spelling.dictionaries` is accepted only in the user file, so a repository cannot point the editor at files of its choosing.

== Warnings

Problems with settings produce warnings and never stop the application:

* An unknown key warns and is ignored.
* A value of the wrong type or range, such as `font_size = -3` or `theme = "purple"`, warns and keeps the default.
* An invalid `default_expansion` (a negative number, a fraction, `true`, an array, or a string other than `"all"`) warns and keeps the value from the layer beneath.
* A key set in the workspace file that is only allowed in the user file warns and is ignored.
* A section that is not a table warns.
* An invalid `[quality]` value, an unknown rule, or an exclusion with an unqualified resource ID, no reason or a duplicate warns and is left out, and makes `adocfoundry-cli audit` exit with 2.

Each warning names the file and the key and is shown once.

A file that is not valid TOML at all (for example a missing closing bracket) is reported as a settings error instead.

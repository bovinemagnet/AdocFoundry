= Settings
Paul Snow
:revnumber: 0.0.0
:description: The TOML user and workspace settings files and every key they accept.

Settings are TOML.
There are two layers, and the workspace layer is applied after the user layer.

[cols="1,3"]
|===
|Layer |File

|User
|`adocfoundry/adocfoundry.toml` in the platform configuration directory: `~/.config` on Linux, `~/Library/Application Support` on macOS and `%APPDATA%` on Windows.
Open Settings creates it if it is missing.

|Workspace
|`.adocfoundry.toml` at the root of the workspace.
|===

Saving either file applies it, whether in AdocFoundry or in another editor while a workspace is open.
Reload Settings re-reads both.

[#state-folder]
The app also keeps two folders and two files in its state folder, `adocfoundry` under the platform's local state location: `$XDG_STATE_HOME/adocfoundry` on Linux, normally `~/.local/state/adocfoundry`; `~/Library/Application Support/adocfoundry` on macOS; and `%LOCALAPPDATA%\adocfoundry` on Windows.
It is local, never roaming, because the settings file is often synchronised or kept in a dotfiles repository and copies of pages should not travel with it.
The folders are `recovery`, holding copies of unsaved pages until they are saved or closed, and `history`, holding saved versions of pages.
The files are `session.json`, the last session, and `recent-folders.json`, the folders opened recently.
`update-state.toml` and `sidebar-state.json` stay beside the settings file.
See xref:using-the-editor.adoc#crash-recovery[Recovering unsaved changes], xref:using-the-editor.adoc#local-history[Local history] and xref:using-the-editor.adoc#restoring-the-session[Restoring the last session].

== Example

[source,toml]
----
[editor]
# font_family = "Iosevka"       # replaces the font set's source font
# font_size = 13                 # replaces the font set's source size
soft_wrap = true
tab_width = 2
theme = "auto"                   # auto | light | dark; the older setting, used when [appearance] mode is not set
preview_tabs = true              # false: every page you open stays open
auto_save = "off"                # off | on_focus_change | after_delay

[appearance]                     # user file only
mode = "auto"                    # auto | light | dark
light_theme = "Solarized Light"  # a light theme's name; the native default when left out
dark_theme = "Tokyo Night"       # a dark theme's name; the native default when left out
# themes_dir = "themes"          # relative to the user settings file's folder; ~/ is the home folder
font_scale = 1.0                 # text this many times the default size, 0.5 to 3
font_set = "workshop"            # workshop | reading-room | legible | current | one of your own

[sidebar]
remember_expansion = true        # remember opened and closed branches (user file only)
follow_active = true            # reveal the active page in Files, Navigation and Modules

[sidebar.navigation]
default_expansion = 2            # 0 or more, or "all"

[sidebar.modules]
default_expansion = 2            # to keep the old fully open trees, use "all" in both

[workspace]
ignore = [".cache", ".git", ".zed", "node_modules", "build", "target", "dist", ".idea", ".gradle"]

[tools]
asciidoctor = ""                 # optional absolute path; discovered on PATH if empty
git = ""                         # optional absolute path; discovered on PATH if empty
dot = ""                         # optional absolute path; discovered on PATH if empty
plantuml = ""                    # optional absolute path; discovered on PATH if empty
d2 = ""                          # optional absolute path; discovered on PATH if empty
diagram_timeout = 30             # seconds a diagram may render (Mermaid included) before it is stopped
node = ""                        # optional absolute path to node; npm is found beside it, else on PATH (Build Site)
build_timeout = 600              # seconds Build Site may run, npm install included, before it is stopped
commit_timeout = 120             # seconds a signed commit may run, waiting for a passphrase or key, before it is stopped

[templates]
dir = "templates"                # folder of project templates, one per subfolder (also allowed in a workspace file, inside the workspace)

[git]
enabled = true                   # false: no repository is discovered
show_markers = true              # reserved for change markers
blame_on_hover = false           # tooltip on a line number
remote = "origin"                # the remote used for links to a line

[git.hosts]
"git.example.com" = "gitlab"     # github | gitlab | bitbucket | azure

[pdf]
theme = "default"                # a bundled name, a theme name or a .yml path
themes_dir = "resources/themes"  # where <name>-theme.yml is found
fonts_dir = "resources/fonts"
site_url = "https://docs.example.com"
standards = ["pdf-a-2a"]         # pdf-a-1b | pdf-a-1a | pdf-a-2a | pdf-ua-1

[pdf.profiles.quick-start]       # a named PDF, run by name
page = "docs/modules/ROOT/pages/quick-start.adoc"
output = "build/quick-start.pdf"

[docx]                           # Word export; nothing here is read for PDF
paper = "a4"                     # a4 | letter
orientation = "portrait"         # portrait | landscape

[docx.styles]
heading_colour = "1F3864"

[docx.profiles.quick-start]      # a named Word document, run by name
page = "docs/modules/ROOT/pages/quick-start.adoc"
output = "build/quick-start.docx"

[spelling]
enabled = true                   # underline misspelt words in prose
language = "en_GB"               # for pages with no lang attribute
dictionaries = ""                # folder of extra Hunspell .aff/.dic files (user file only)

[graph]
depth = 1                        # the local graph's starting depth, 1 to 3
show_partials = true
show_nav = true
show_orphans = true
show_unresolved = false
colour_by = "component"          # component | module | family | age
stale_after_days = 365           # pages unchanged longer are ringed
group = "off"                    # off | module | component
layout = "force"                 # force | mind-map | radial

[quality]
fail_on = "warning"
require_complete = true
# providers = []

[quality.rules]
"quality.navigation.unlisted-page" = "info"

[[quality.exclusions]]
rule = "quality.navigation.unlisted-page"
resource = "product:ROOT:internal-notes.adoc"
reason = "Deliberately unlisted staff-only page"

[updates]
check = true                     # look for a newer release at start-up
----

[[font-sets]]
== Font sets

A font set gives three roles: Interface (menus, panels, tabs, dialogs and the status bar), Source (the source editor, and code in the preview, the visual editor and reports) and Reading (prose and headings in the preview and the visual editor).
`appearance.font_set` chooses one.
The fonts of `workshop`, `reading-room` and `legible` ship inside the app, so nothing needs installing.

[cols="2,3,3,3"]
|===
|Id |Interface |Source |Reading

|`workshop` (default)
|IBM Plex Sans
|IBM Plex Mono, 13
|IBM Plex Sans, 15

|`reading-room`
|Source Sans 3
|Source Code Pro, 14
|Source Serif 4, 17

|`legible`
|Atkinson Hyperlegible Next
|Atkinson Hyperlegible Mono, 14
|Atkinson Hyperlegible Next, 16

|`current`
|the theme's or the system's interface font
|the theme's or the system's monospace font; JetBrains Mono in the source editor only, if installed
|as Interface
|===

`current` is the fonts the app used before font sets; they do not ship.
A theme's `font.family` and `mono_font.family` apply only under `current`; any other set overrides them.
`editor.font_family` and `editor.font_size`, when a settings file names them, replace the set's source role.
Font sets change the app and never PDF export, which keeps its theme's fonts.

Define a set of your own in the user file:

[source,toml]
----
[appearance]
font_set = "house"

[appearance.font_sets.house]
name = "House"            # defaults to the id
based_on = "reading-room" # a built-in id; workshop when left out
source = "Iosevka"
source_size = 14
reading = "Georgia"
reading_size = 16
----

A role left out comes from `based_on`.
The keys are `name`, `based_on`, `interface`, `source`, `source_size`, `reading` and `reading_size`.
The families must be installed; a missing interface, source or reading family is reported in a notification and falls back to the theme's.
An id a built-in set has, a bad `based_on` or a bad value leaves the set out with a warning.

*Select Font Set...* in the View menu and the command palette is the quick way to choose; see xref:using-the-editor.adoc#themes[Themes].

== Keys

[cols="2,2,2,4"]
|===
|Key |Type |Default |Meaning

|`editor.font_family`
|string
|the font set's source font
|The source editor's font, replacing the font set's source role when a settings file names it.

See xref:#font-sets[Font sets].

|`editor.font_size`
|positive integer
|the font set's source size
|The source editor's font size, replacing the font set's source size when a settings file names it.

|`editor.soft_wrap`
|boolean
|`true`
|Wrap long lines.

|`editor.tab_width`
|positive integer
|`2`
|The width of a tab.

|`editor.preview_tabs`
|boolean
|`true`
|Open pages you browse to in a temporary preview tab, which the next page you browse to replaces. When `false`, every page you open stays open until you close it. See xref:using-the-editor.adoc#preview-tabs[Preview tabs].

|`editor.auto_save`
|`"off"`, `"on_focus_change"` or `"after_delay"`
|`"off"`
|Save pages without asking. `"after_delay"` saves a page one second after your last edit to it. `"on_focus_change"` saves a page when you leave its tab and every edited page when the AdocFoundry window loses focus. Any other value is ignored with a warning and leaves auto-save off. See xref:using-the-editor.adoc#auto-save[Auto-save]. The xref:language-server.adoc[language server] ignores this setting and never saves.

|`editor.theme`
|`"auto"`, `"light"` or `"dark"`
|`"auto"`
|The colour theme: the older setting, used for the mode when `appearance.mode` is not set.
When both are set, `appearance.mode` wins and a warning says `editor.theme` is ignored.
Choosing a theme in AdocFoundry takes this line out of the user settings file.

|`appearance.mode`
|`"auto"`, `"light"` or `"dark"`
|the value of `editor.theme`, else `"auto"`
|Whether the application follows the system's light or dark appearance or stays light or dark.
User file only.
See xref:using-the-editor.adoc#themes[Themes].

|`appearance.light_theme`
|string
|the native Default Light
|The name of the light theme to show.
A name that names no light theme, whether missing or a dark theme's, shows the native default with a warning, and the name is kept so the theme is used again once it is back.
User file only.

|`appearance.dark_theme`
|string
|the native Default Dark
|The name of the dark theme to show, treated as `appearance.light_theme` is.
User file only.

|`appearance.themes_dir`
|string
|`themes`
|The folder of your own theme files, relative to the user settings file's folder; `~/` is the home folder.
User file only.

|`appearance.font_set`
|string
|`"workshop"`
|The font set: `workshop`, `reading-room`, `legible`, `current`, or the id of one of your own.
An unknown id warns and uses `workshop`.
User file only.
See xref:#font-sets[Font sets].

|`appearance.font_sets.<id>`
|table
|none
|A font set of your own.
User file only.
See xref:#font-sets[Font sets].

|`appearance.font_scale`
|number
|`1`
|A multiplier of the default text size, as a zoom: `1.5` draws text half as large again and `2` twice as large.
From `0.5` to `3`, whole or not; anything else, or a value that is not a number, warns and keeps `1`.
It scales the whole interface together: panels, menus, dialogs, the preview, the visual editor, the graph's labels and the source editor, whose `editor.font_size` it multiplies (`13` at `1.5` draws at `19.5`); spacing sized to the text grows with it.
It follows every theme, and takes effect when the settings are read again, without a restart.
User file only.
These settings never affect PDF export (`pdf.theme`), HTML or the Antora site.

|`sidebar.follow_active`
|boolean
|`true`
|Reveal the active page in Files, Navigation and Modules whenever another file becomes active, opening the folders and branches above it. When `false`, the panels do not select or open anything by themselves. See xref:using-the-editor.adoc#following-the-active-page[Following the active page].

|`sidebar.remember_expansion`
|boolean
|`true`
|Remember the branches you open and close in Navigation and Modules, for each workspace and panel, in `sidebar-state.json` beside the user settings file. When `false`, a reopened workspace starts from the defaults and earlier saved state is ignored. User file only. See xref:using-the-editor.adoc#how-far-the-trees-open[How far the trees open].

|`sidebar.navigation.default_expansion`
|integer of 0 or more, or `"all"`
|`2`
|How many levels of branches the Navigation tree opens, counting the component version row as level 1. `0` shows only the component versions, closed. `"all"` opens every branch, as earlier releases did. A depth greater than the tree opens everything.

|`sidebar.modules.default_expansion`
|integer of 0 or more, or `"all"`
|`2`
|The same for the Modules tree, whose levels are component version, module, family and resource. Set both this and the Navigation key to `"all"` to keep fully expanded trees.

|`workspace.ignore`
|array of strings
|`[".cache", ".git", ".zed", "node_modules", "build", "target", "dist", ".idea", ".gradle"]`
|Folder names skipped by indexing, Antora discovery and the file watcher, and hidden in Files unless Show Excluded Files is on. A workspace file's list replaces the default rather than adding to it. Only folders beneath a workspace folder count, so a workspace that itself sits in a folder named `build` is indexed and watched as usual. Inside the `modules` folder of a component version, `build`, `target` and `dist` are ordinary folders, since nothing is built there: a page in `modules/ROOT/pages/build/` is indexed and watched like any other.

|`""`

|`tools.git`
|string
|`""`
|An absolute path to `git`. Discovered on `PATH` when empty. Used to push, and to make signed commits. Everything else in Git is done in process.

|`tools.dot`
|string
|`""`

|`tools.plantuml`
|string
|`""`
|An absolute path to `plantuml`, for `plantuml` and `uml` diagram blocks. Discovered on `PATH` when empty. If the path does not exist, the diagram shows its source with the reason.

|`tools.d2`
|string
|`""`
|An absolute path to `d2`, for `d2` diagram blocks. Discovered on `PATH` when empty. If the path does not exist, the diagram shows its source with the reason.

|`tools.diagram_timeout`
|integer
|`30`
|The number of seconds a diagram may render before it is stopped: a Graphviz, PlantUML or D2 process is killed, and Mermaid, which renders in process, is stopped at the same deadline. |`tools.node`
|string
|`""`
|An absolute path to `node`, for Build Site. npm is the one beside it (`npm.cmd` on Windows), else the first `npm` on `PATH`, and the folder of `node` is put first on the build's `PATH`. Discovered on `PATH` when empty. Without npm, Build Site is greyed out with a hint. User file only.

|`tools.build_timeout`
|integer

|The number of seconds a site build may run, `npm install` included, before it and every process it started are stopped. A build that writes more than 8 MiB of output is also stopped. User file only.

|`tools.commit_timeout`

|`templates.dir`

When `false`, the app never checks unasked. Check for Updates in the command palette checks whatever this says. See xref:getting-started.adoc#updates[Updates].

[#docx-settings]
== Word export settings

The `[docx]` table sets how the Word documents the engine writes are laid out and styled, and `[docx.profiles.<name>]` saves Word publications under a name.
These settings are what Export Page to Word…, Export Component to Word…, Export DOCX Profile…, `adocfoundry-cli docx` (see xref:command-line.adoc#docx[docx]) and the MCP `export_docx` tool read.

Both settings files may set `[docx]`.
A key the workspace file sets replaces the user file's.
A `[docx.header]` or `[docx.footer]` table replaces that one's lines whole, so a workspace that sets `[docx.footer]` does not keep the user file's even-page footer.
A workspace profile replaces a user profile of the same name.
An unknown key, or a value that cannot be used, warns and leaves the default.

Word export and PDF export are set apart.
Nothing in `[pdf]`, its theme, fonts or standards, is read for Word, and nothing in `[docx]` is read for PDF.

[cols="2,2,2,4"]
|===
|Key |Type |Default |Meaning

|`docx.paper`
|string
|`"a4"`
|The paper size: `"a4"` or `"letter"`.

|`docx.orientation`
|string
|`"portrait"`
|`"portrait"` or `"landscape"`.

|`docx.logo`
|string
|none
|The image that `\{logo}` shows in a header or footer, relative to the first workspace root.

|`docx.odd_even`
|boolean
|`true`
|Give odd and even pages their own headers and footers.
When `false`, the odd page's lines are used on every page.

|`docx.margins.top`, `right`, `bottom` and `left`
|length
|`"1in"`
|The page margins.

|`docx.margins.header` and `footer`
|length
|about 1.25 cm
|How far the header and the footer are from the edge of the page.
The default is 708 twentieths of a point.

|`docx.header` and `docx.footer`
|tables
|no header; the page number in the footer
|The running content.
Each table has `left`, `centre` (or `center`) and `right` slots, and the tables `.even` and `.first` take the same slots for even pages and for the body's first page.
See <<docx-running>>.

|`docx.styles.body_font`, `heading_font` and `code_font`
|string
|Word's own
|A font family of 1 to 31 characters for the body, for headings (the title, subtitle, headings and the table of contents' heading) and for code.

|`docx.styles.body_size`
|number
|Word's own
|The body text's size in points, from 6 to 72.

|`docx.styles.heading_colour` and `link_colour`
|string
|Word's own
|Six hexadecimal digits, such as `"1F3864"`; a leading `#` is allowed.
`heading_color` and `link_color` are accepted too.

|`docx.profiles.<name>`
|table
|none
|A named Word publication.
See <<docx-profiles>>.
|===

A length is a string with a unit, `"25mm"`, `"2.5cm"`, `"1in"` or `"72pt"`, or a number of points.
No length may be more than 10 inches.

[source,toml]
----
[docx]
paper = "letter"
orientation = "portrait"
logo = "images/logo.png"
odd_even = true

[docx.margins]
top = "25mm"
header = "12mm"

[docx.header]
left = "{document-title}"
right = "{logo}"

[docx.footer]
left = "{chapter-title}"
right = "{page-number} of {page-count}"

[docx.styles]
body_font = "Calibri"
heading_font = "Calibri Light"
code_font = "Consolas"
body_size = 11
heading_colour = "1F3864"
link_colour = "0563C1"
----

By default the page is A4, portrait, with a margin of an inch on every side, no header, and the page number in the footer: at the right of odd pages and at the left of even ones.

[#docx-running]
=== Headers and footers

Each slot holds text and these placeholders.
An unknown placeholder stays as written.

[cols="1,3"]
|===
|Placeholder |Shows

|`\{page-number}`
|The page's number, as a field that Word keeps current.

|`\{page-count}`
|The number of pages in the document, covers included.

|`\{document-title}`
|The document's title.

|`\{chapter-title}`
|The title of the chapter the page is in, as Word and LibreOffice find it.

|`\{logo}`
|The image `docx.logo` names, drawn small enough for a line of text.
|===

With `odd_even` on, an even page uses its `.even` table; when there is none, it uses the odd page's lines with left and right swapped.
A `.first` table, in either the header or the footer, gives the body's first page headers and footers of its own, empty where none is given.
Covers and the title page show no running content.

[#docx-profiles]
=== Word profiles

A Word profile names a Word document you produce again and again, as a PDF profile does.
It is a table `[docx.profiles.<name>]` in either settings file.

[cols="1,4"]
|===
|Key |Meaning

|`page`, `component` or `nav`
|Exactly one of them, as for xref:pdf-export.adoc#publication-profiles[a PDF profile]: a page's path, a component version (`name` or `version@name`), or an array of navigation file paths, relative to the first workspace folder.

|`output`
|Where to write the document, relative to the first workspace folder.
The default is `<name>.docx` there.
It must be a `.docx` file name and inside the workspace folder; a profile whose output would be written outside it is refused when it is run.

|`paper` and `orientation`
|This document's own, in place of the value in `[docx]`.

|`attributes`
|A table of attribute names to strings, numbers or `true`, applied to every page before its own header.
|===

A profile that has none of `page`, `component` and `nav`, or more than one of them, that has an `output` which is not a `.docx` file name, a bad `paper` or `orientation`, or an unknown key is left out with a warning.
A key that only PDF profiles have, such as `theme`, is an unknown key here.

A profile declares its own content in each format, and a PDF profile and a Word profile of the same name are independent.
A book published in both formats therefore repeats its one line of content, and neither profile can change the other.

This example publishes one Antora book as both a PDF and a Word document, with output paths and style settings of their own.

[source,toml]
----
[pdf.profiles.admin-guide]
component = "2.0@admin"
output = "build/admin-guide.pdf"
theme = "acme"

[docx.profiles.admin-guide]
component = "2.0@admin"
output = "build/admin-guide.docx"
orientation = "portrait"

[docx]
paper = "a4"

[docx.styles]
heading_font = "Calibri Light"
heading_colour = "1F3864"

[docx.footer]
left = "{chapter-title}"
right = "{page-number} of {page-count}"
----

The PDF profile's `theme` is not read for Word, and the Word profile's `orientation` is not read for PDF.

== What a workspace file may set

A workspace file may override `editor.*`, `templates.dir`, `sidebar.navigation.default_expansion`, `sidebar.modules.default_expansion`, `sidebar.follow_active`, `workspace.ignore`, `pdf.*`, `docx.*`, `graph.*`, `quality.*`, `spelling.enabled` and `spelling.language`.
The two depths override separately.
Both files may set `[quality]`: a rule's severity from the workspace file wins, and the exclusions and the providers of both files apply.
`tools.*` is accepted only in the user file, so a repository cannot point the editor at an executable of its choosing.
`git.*` is also accepted only in the user file, so a repository cannot change how the editor treats it.
`sidebar.remember_expansion` is also accepted only in the user file, because it decides what is saved outside the repository.
`updates.*` is also accepted only in the user file, so a repository cannot make the editor reach the network.
`history.*` is also accepted only in the user file, because history is kept outside the repository.
`spelling.dictionaries` is accepted only in the user file, so a repository cannot point the editor at files of its choosing.

== Warnings

Problems with settings produce warnings and never stop the application:

* An unknown key warns and is ignored.
* A value of the wrong type or range, such as `font_size = -3` or `theme = "purple"`, warns and keeps the default.
* An invalid `default_expansion` (a negative number, a fraction, `true`, an array, or a string other than `"all"`) warns and keeps the value from the layer beneath.
* A key set in the workspace file that is only allowed in the user file warns and is ignored.
* A section that is not a table warns.
* An invalid `[quality]` value, an unknown rule, or an exclusion with an unqualified resource ID, no reason or a duplicate warns and is left out, and makes `adocfoundry-cli audit` exit with 2.

Each warning names the file and the key and is shown once.

A file that is not valid TOML at all (for example a missing closing bracket) does not stop a folder opening.
The folder opens with the other file's settings and the defaults, and a warning names the file, line and column and ends "Its settings are not applied until it is fixed."
Fixing the file on disk applies it, and the warning goes.
A file that stops parsing while the folder is open, or when you choose Reload Settings, is reported as a settings error instead, and the settings already in force are kept.

= AdocFoundry
Paul Snow
:revnumber: 0.0.0
:description: A native desktop editor for AsciiDoc documentation laid out the Antora way.

Forge your documentation in real time.

AdocFoundry is a native desktop editor for AsciiDoc documentation laid out the Antora way.
It is written in Rust for macOS, Linux and Windows.
It is a thin GPUI application over a headless engine, and the same engine powers a command-line checker (`adocfoundry-cli`) and a language server (`adoc-ls`) for other editors.

Nothing else is needed at run time: no Ruby, Node.js or Java.

== Phases

The project is built in four phases, each of which ships a usable tool.

[cols="1,3,2"]
|===
|Phase |Scope |Status

|1
|A source editor with Antora support and link following.
|Implemented

|2
|A native rendered preview inside the application.
|Implemented

|3
|WYSIWYG editing.
|Not started

|4
|PDF export with themes.
|Not started
|===

== Phase 2 status

Phase 2 is implemented.
It adds xref:preview.adoc[the preview]:

* A native rendered preview docked beside the editor, or detached into its own window, that follows the active page or stays pinned to one.
* Scroll sync in both directions, and click-to-source, including into partials.
* Clickable xrefs that record back and forward history, with unresolved references marked.
* Includes, images and attachments resolved through the Antora catalog.
* Highlighted source blocks, and diagrams: Mermaid in process, and Graphviz, PlantUML and D2 through their tools when found on the `PATH`.
* `adocfoundry-cli render`, which writes a page as HTML as the preview renders it.

== Phase 1 status

Phase 1 is implemented.
It provides:

* A workspace that discovers every `antora.yml` beneath a folder, so several components and versions live side by side.
* A sidebar with the Antora navigation, a module and family browser, workspace problems and an outline.
* A source editor with syntax highlighting, folding, diagnostics as you type, hover and completion.
* Link following for `xref:`, `include::` and `+{attribute}+` references, with back and forward history and a read-only peek at includes.
* Workspace find and replace, and page rename that rewrites every xref, both with a preview and a single undo step.
* A command palette, light and dark themes, a read-only second window and TOML settings.

The following are not implemented yet:

* WYSIWYG editing (Phase 3) and PDF export (Phase 4).
* Settings for the paths of the Graphviz, PlantUML and D2 tools, which are found on the `PATH` only.
* Typeset STEM in the preview, which shows styled maths source until Phase 4.
* Editing included content in place, spell checking, Git integration and plugins.
* XML and Dockerfile highlighting inside source blocks, because the editor component has no grammar for them yet.
* Diagnostics inside `antora.yml` itself, beyond reporting that it cannot be read.

Some things are unverified.
Frame timing and input-method (IME) composition have not been verified on every platform, and the macOS and Windows builds are produced by continuous integration but have not yet been run by hand.
See xref:developer:testing.adoc#manual-qa[the manual QA record] for the checklist.

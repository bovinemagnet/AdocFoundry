= Comments
Paul Snow
:revnumber: 0.0.0
:description: Leave notes on the text of a page, reply to them and resolve them, without changing the page.

A comment is a note on some text of a page.
You can ask a question, suggest a change or leave a reminder, and others can reply.
The comments are kept beside the page, so the page itself never changes and its Git diff never shows them.

== Adding a comment

. Select the text in the source editor.
. Choose *Edit › Add Comment*, or press kbd:[Cmd+Alt+M] on macOS or kbd:[Ctrl+Alt+M] elsewhere.
The command is also in the command palette.
. A box opens in the *Comments* panel in the sidebar.
Write the comment and choose *Comment*, or choose *Cancel*.

If nothing is selected, AdocFoundry asks you to select some text first.

== Seeing comments in the editor

The source editor fills commented text and marks the gutter beside it.
The visual editor fills the text of each open comment in the same colour, apart from a pending suggestion, which it draws as described under xref:comments.adoc#_seeing_a_suggestion[Seeing a suggestion]; it has no gutter, so it shows no gutter mark.
When the caret is inside a comment, the status bar says whose it is.

*Edit › Next Comment* and *Edit › Previous Comment* move to the next or previous open comment, going round the page.

Comments follow their text as you type.

* Text typed at the edge of a commented passage stays outside it.
* Text typed inside it makes the passage longer.
* Deleting part of it makes the passage shorter.

== The Comments panel

The *Comments* tab in the sidebar reads "Comments (n)".
It is shown while the page has comments, or while you are writing one.

The panel lists the open comments of the page in the order of their text.
Each shows:

* the text it is on, which you can choose to select that text in the editor;
* the author;
* when it was written, as a time for today and a date for earlier days, in UTC;
* the comment itself, and its replies.

The buttons are *Reply*, *Resolve* (*Reopen* for a resolved comment), *Edit* and *Delete*.
Only those you may use are shown.

=== Resolved comments

A resolved comment is folded under *Resolved (n)* and is no longer marked in the editor.
Choose *Reopen* to bring it back.

=== Detached comments

If the text a comment was on is deleted, the comment is _detached_.
It is listed under *Detached (n)*, with "Was on" and the text it was on.

If the text comes back, for example when you undo the deletion, the comment finds it again once typing pauses.

== Suggesting a change

A suggestion is a comment that proposes replacing the text it is on.
Suggesting changes nothing in the page.
Only accepting a suggestion changes it.

The visual editor shows suggestions too.
A pending suggestion has the part that accepting it would remove struck through, and the text it would add drawn inline right after it, underlined, both in the theme's information colour.
The added text is for display only.
It is not part of the page, and you cannot select, copy or edit it.
The caret steps over it as it steps over an inline formula, and typing beside it edits only the page.
A pending suggestion is not filled in the comment colour.

An outdated suggestion is filled like a comment, in the warning colour, with nothing struck through or added.
Accepted and rejected suggestions are not shown, as resolved comments are not.

You cannot start a suggestion in the visual editor.
Use *Suggest Change* in the source editor.

=== Making a suggestion

. Select the text in the source editor.
. Choose *Edit › Suggest Change*, which follows *Add Comment*, or press kbd:[Cmd+Alt+Shift+M] on macOS or kbd:[Ctrl+Alt+Shift+M] elsewhere.
. A "Suggested change" box opens in the *Comments* panel.
The *Replace with* box holds the selected text, all selected, so typing replaces it.
Add a note if you want to explain the change.
. Choose *Suggest*, or choose *Cancel*.

Leave *Replace with* empty to suggest deleting the text.
The replacement must differ from the text it replaces.

AdocFoundry refuses a suggestion in these cases:

* Nothing is selected: "Select the text to change first."
* More than 4 KiB of text is selected: "Select at most 4 KiB of text to suggest a change."
* The text changed while the box was open: "The text changed while you were suggesting; try again."
The box stays open with what you typed, so choose *Suggest* again.

A replacement may be up to 8 KiB.

=== Seeing a suggestion

In the source editor, the text of a pending or outdated suggestion is framed, and its line is marked in the gutter, in the theme's information colour.
Comments use the warning colour.
While a suggestion is pending, the part that accepting it would remove is struck through.

When the caret is inside a suggestion, the status bar says what accepting it would do.
For example, "Suggestion by Ada: replace ‘word’ with ‘term’".
It reads "delete ‘…’" or "insert ‘…’" when the suggestion only removes or only adds text.

In the *Comments* panel, the card shows the change.
It shows the original with the part to be removed struck through, then the replacement with the part to be added underlined.
Choose the change to select its text in the editor.

=== States of a suggestion

Pending:: The text is still what was suggested on.
Outdated:: The text has changed since this was suggested.
An outdated suggestion cannot be accepted.
Reject it, or edit it to suggest again on the current text.
Accepted:: Someone accepted the suggestion and the text was changed.
Rejected:: Someone turned the suggestion down.

If the page changes outside AdocFoundry, a suggestion is found again by the text it was on.
It is outdated unless its place is certain.

=== Accepting, rejecting and the other buttons

A suggestion has the buttons *Accept*, *Reject*, *Reply*, *Edit* and *Delete*, and *Reopen* once it is decided.
Only those you may use are shown.

* *Edit* changes the replacement and the note while the suggestion is undecided.
Once it is decided, *Edit* changes the note alone.
* A suggestion is never just resolved.
If you try, AdocFoundry says "Accept or reject a suggestion instead of resolving it."

Accepting makes one small edit, and only the part that differs changes.
The edit is in the page's undo history.
*Undo* takes it back, and the suggestion's text with it, and *Redo* puts it back.
The suggestion stays accepted.

Accepted and rejected suggestions are folded with the resolved comments, under "Accepted by …" or "Rejected by …".

Accepting a suggestion credits its author as a co-author of your next commit, as edits in a session do.
It does not when you are the author, or when the author gave no usable address.
See xref:collaboration.adoc#_credit_for_guests[Credit for guests].

=== Who may do what

* Anyone who may comment may suggest.
* The author of a suggestion may edit it or withdraw it, by rejecting it.
* Accepting and rejecting the suggestions of others is for whoever is working alone, the host and Editors.
A Viewer never can.

== Where comments are kept

Comments are written to a file beside the page, named after it with a leading dot and `.afd` added: `.install.adoc.afd` for `install.adoc`.
It is a TOML file.
The leading dot keeps it out of the published Antora site.

The page is never changed, so nothing about comments appears in its Git diff.
Suggestions are kept in the same file.
A file that holds one is written as `format = 2`, which an older AdocFoundry shows read-only.

=== Sharing comments through Git

Commit the `.afd` file to share comments with others.
The file changes only when comments change, so editing a page on two branches does not make its comments file conflict.

If someone else changes the file, for example when you pull, AdocFoundry reads it again and keeps what you added.
When a page has changed elsewhere, each comment is found again by the text it was on.

=== A file that cannot be used

* A comments file with a merge conflict, or one AdocFoundry cannot read, shows the reason in the panel.
It is never overwritten.
* A file written by a newer version of the app is read-only.

=== Renaming, moving and deleting pages

Renaming, moving or deleting a page in the app takes its comments with it.
*Undo Delete* and *Restore Deleted File* bring them back.

A page that has never been saved keeps its comments only while it is open.

== Your name on comments

Comments carry the name and e-mail address from the `[comments]` table of your user settings file, as `name` and `email`.
Without them AdocFoundry uses your Git name and e-mail address from your global Git settings, and then your computer's user name.
See xref:settings.adoc[Settings].

== Limits

* 500 comments a page, suggestions included.
* 100 replies to a comment.
* 8 KiB of text in each comment or reply.
* 4 KiB of selected text for a suggestion, and 8 KiB for its replacement.

== Comments in a shared session

In a session (see xref:collaboration.adoc[Working together]), everyone who has a shared page open sees its comments.
They are on the same text whoever types, and Viewers can comment and reply too.
The host keeps them in its `.afd` file.

* Anyone can add a comment or a reply.
* The host, Editors and the author of a comment can resolve or reopen it.
* Only the author edits a comment.
* The author or the host can delete it.

Everyone with the page open sees suggestions too.

* A Viewer may suggest but not accept.
* An Editor and the host may accept.
* A guest's suggestion changes nothing until someone accepts it.
* The host applies every accept once, so two people accepting at once change the text once.

A guest's accept is not in anyone's undo history.
To take it back, edit the text or suggest the reverse.
A guest who sees "The text changed while you were suggesting; try again." should simply suggest again.

Guests see names, never e-mail addresses.

A guest cannot comment while the host cannot be reached.
If the host refuses a comment, a notification says why.

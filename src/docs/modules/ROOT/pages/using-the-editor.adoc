= Using the editor
Paul Snow
:revnumber: 0.0.0
:description: The workspace, sidebar, editor, link following, search and replace, and page rename.

This page describes the source editor and the workspace around it.
The rendered preview has its own page, xref:preview.adoc[The preview], and editing the rendered page has another, xref:visual-editing.adoc[Visual editing].
Every action described here is an engine command with a stable id, so it also appears in the command palette (kbd:[Cmd+Shift+P] or kbd:[Ctrl+Shift+P]) and, where it fits, in the xref:using-the-editor.adoc#application-menu[application menu].
See xref:keyboard-shortcuts.adoc[Keyboard shortcuts] for the bindings.

== The workspace

When you open a folder, AdocFoundry discovers every `antora.yml` beneath it and indexes the AsciiDoc files on a background worker.
The window stays usable while indexing runs.
The status bar shows "Indexing…" only while the whole workspace is being indexed or file changes are being applied, not after every keystroke.
Plain AsciiDoc folders work too, with relative-path resolution only.

Folders named in `workspace.ignore` (by default `node_modules`, `.git`, `build`, `target` and `.cache`) are skipped.
See xref:settings.adoc[Settings].

AdocFoundry watches the workspace.
A file changed on disk is re-indexed, and `antora.yml` is re-read when it changes.
A buffer with unsaved edits is never overwritten: you are told that the file changed on disk and your buffer is kept.

Saving a page whose file changed on disk since you opened or last saved it is refused, so an outside change is never written over without asking.
Save All still saves every other page and reports the conflict, and Save and Commit stops in the same way.
A dialog titled "<file> changed on disk" explains that the file changed since you opened or last saved it, and offers two buttons:

Reload from Disk::
Replaces the buffer with the version on disk, as one undo step, and leaves the page clean.
Undo brings your edits back.

Overwrite::
Writes your buffer over the file.

Closing the dialog leaves the page as it was, still unsaved.
The same choices are in the command palette as Reload from Disk (`document.reload`) and Save, Overwriting the File on Disk (`document.overwrite`); neither has a key.
A file deleted outside the editor is simply written again by Save.

[#auto-save]
=== Auto-save

Auto-save is off by default.
Set `editor.auto_save` to choose when AdocFoundry saves for you; see xref:settings.adoc[Settings].

`"after_delay"`::
A page is saved one second after your last edit to it, so the unsaved marker on its tab clears shortly after you stop typing.

`"on_focus_change"`::
A page is saved when you leave its tab for another page or an image.
Every edited page is saved when the AdocFoundry window loses focus, for example when you switch to another application or to a detached preview window.

Auto-save uses the ordinary Save command, so the file watcher and Git state behave as after a manual save.
Pages without unsaved edits are not written, and untitled pages that have never been saved are never auto-saved.
A file that changed on disk is never overwritten: the save is refused with the usual "changed on disk" conflict and reported once as a notification.
That page is not auto-saved again until you save, overwrite or reload it by hand.

Every save writes a temporary file in the same directory and renames it over the page, keeping the file's permissions.
For a symbolic link, the link's target is written and the link is kept.
A failed write can no longer leave a truncated file.

== The sidebar

The sidebar has four tabs and an outline.

Navigation::
Each component version's navigation, nested as its `nav.adoc` files list it.
A line such as `product@2.0 · main` heads the panel, naming the active page's component version and branch.
A component that declares no `nav` in `antora.yml` shows its pages by module instead.

Modules::
Every module, with its families (pages, partials, examples, images and attachments) and their resources.

Files::
The folders and files beneath each workspace folder, as they are on disk.
See <<the-files-view>>.

Problems::
Workspace diagnostics grouped by file, with a count in the tab title.
Click one to open the file at that location.
A row too long for the sidebar ends with an ellipsis, and hovering it shows the full text in a tooltip.
This applies to every panel in the sidebar.

Outline::
The sections of the active document.
For a navigation file, the outline is its navigation tree.

[[the-files-view]]
=== Files

Files shows the folders and files beneath each workspace folder as they are stored on disk.
Navigation and Modules show the documentation as Antora organises it.
Files shows where the files actually are.

Every file type is shown.
That includes files outside Antora's layout, files that no navigation mentions, files that Git ignores and files with any extension.
Empty folders are shown too.
Files works without an `antora.yml` and without Git.
It shows only the folders you opened, never their parents.

Each workspace folder has one top row, named after the folder.
When two workspace folders have the same name, the folder above is added, as in `docs — /work/a`.
Under it, folders come first and then files.
Both are sorted by name, ignoring case, with numbers in natural order, so `file2` comes before `file10`.
Hovering a row shows its full path.
The footer shows the selected entry's path relative to its workspace folder.

A folder's contents are read only when you open it, one level at a time.
Nothing is read for folders you do not open, and file contents are never read just to draw the tree.
The arrow keys move through the tree: kbd:[Right] opens a folder and kbd:[Left] closes it.
A folder that is being read says "Loading…", and an empty folder says "Empty folder".
A folder that cannot be read says "Permission denied — right-click to retry", or "Unavailable:" followed by the reason.

==== What is hidden

Ordinary dotfiles such as `.adocfoundry.toml` and `.gitignore` are shown.
Folders and files named in `workspace.ignore` are hidden.
By default these are `node_modules`, `.git`, `build`, `target` and `.cache`.
A `.gitignore` file does not hide anything.
Show Excluded Files, in the right-click menu, shows the hidden entries marked "(excluded)".
It changes nothing else: not the settings, the index or Antora.

A symbolic link is shown with a "→" after its name and is not followed.
A link to a folder cannot be opened as a folder, so links can never lead outside the workspace or loop.

==== Opening files

Click a file, or select it and press kbd:[Space], to open it in a preview tab, as browsing does.
Double-click to keep it open.
See <<preview-tabs>>.
A file that is already open just activates its tab.
Selecting a script never runs it.

* AsciiDoc pages open as usual, with Source, Visual and Split.
* Other text files, such as YAML, TOML, JSON, Markdown and scripts, open as text in the source editor.
They are highlighted when their type is known.
They are never indexed or checked for AsciiDoc problems, and they have no visual editor or rendered preview, so the mode buttons are hidden for them.
* Images open in an image tab; see <<image-viewer>>.
* PDFs open in the system's own application, with no tab.
* Every other file is tried as text.
A file that is not text, such as a font, an archive, an office document, media or a program, is refused with a message, because it holds binary content or is not UTF-8.
* Only Open Externally in the right-click menu opens such a file in the system's application.
A click never hands it to the system, so selecting a file can never run or install it.
* A symbolic link is never handed to the system by a click.

==== The Files menu

Right-click a file or folder for these items.

Open and Open Externally::
Open the file in a tab, or in the system's application.
Both are for files only.

Copy Path and Copy Relative Path::
Copy the full path, or the path relative to the row's workspace folder.

Reveal in Finder::
Shows the entry in the system's file manager.
It is called Reveal in File Explorer on Windows and Reveal in File Manager on Linux.

Refresh Folder::
Reads the folder again.
It is for folders only.

The menu also has items for the whole panel, and it shows them on the panel's empty space too.

Refresh::
Reads every open folder again.

Collapse All::
Closes every folder.

Show Excluded Files::
Shows or hides the excluded entries.
A checkmark shows when it is on.

==== Reveal in Files

Reveal in Files, in the *View* menu and the command palette, shows the active document in Files.
It has no default key.
It switches the sidebar to Files, opens the folders above the document, and selects and scrolls to it.
The editor keeps focus.
A document beneath an excluded folder is shown anyway, for the moment.
A document outside the workspace folders gets a message instead.

When you switch tabs, Files selects the active document's row if it is shown.
It does not open folders or switch the sidebar.

==== Changes outside the app

Files, folders and empty folders created, deleted or renamed outside the app appear and disappear in the open folders by themselves, through the file watcher.
Folders in `workspace.ignore` are not watched.

=== How far the trees open

Navigation and Modules open to two levels by default.
Earlier releases opened every branch.
Levels count the expandable rows as shown, starting with the component version row at level 1.
A branch at level 2 or above opens when its level is no more than the depth, so the children of the last open level show, closed if they have children of their own.

In Modules the levels are component version, module, family and resource.
The default shows the families of each module with their resources closed.
In Navigation, levels follow the tree as shown, including linked entries that have children; they are not the number of `*` in a nav file.

A depth only sets where a tree starts, and you can open deeper branches by hand.
To open everything, as earlier releases did, set both depths to `"all"`; see xref:settings.adoc[Settings].

=== Remembering open and closed branches

The branches you open and close stay as you left them when you switch between Navigation and Modules, when the workspace is indexed again, and when a navigation file or the catalogue changes.
A branch that is new takes the configured depth, and a closed parent keeps its children hidden.

By default your choices are also remembered for each workspace, and for each panel separately, in `sidebar-state.json` beside the user settings file.
They return when you reopen the workspace or restart the app.
Nothing is written into the documentation repository.
Your choices win over the configured depth: with `"all"`, a branch you closed stays closed, while branches you never touched follow the current depth.

With `sidebar.remember_expansion` set to `false`, a reopened workspace starts from the configured depths, and any saved state is ignored.
Your changes still last for the session.
A missing or damaged state file means the configured depths.

=== The right-click menu

Right-click a row, or the empty space, in Navigation or Modules to open a menu headed *All of Navigation* or *All of Modules*.
It acts on the whole panel, and right-clicking never opens a page.
With the tree focused, kbd:[Shift+F10] opens the same menu on every platform.
The arrow keys move through the menu, kbd:[Enter] chooses an item and kbd:[Esc] closes it.
The arrow keys in the tree itself work as before.

Expand All::
Opens every branch.

Collapse All::
Closes every branch, including those hidden under closed parents.
The component version rows stay visible.

Collapse One Level::
Closes the deepest level of open branches that are visible and leaves shallower ones alone.
Repeat it to close the tree level by level.
It is disabled when nothing is open.

Reset to Configured Default::
Forgets that panel's choices and opens it as the settings say.

These change the view and what is remembered, and never the TOML files.
When a collapse hides the selected row, the nearest row above it that is still shown becomes selected.

The same four commands are also in the *View* menu and the command palette.
There they are titled Expand All in Sidebar, Collapse All in Sidebar, Collapse Sidebar One Level and Reset Sidebar to Configured Default.
They act on whichever of Navigation or Modules the sidebar is showing, and on Navigation when it shows neither.
They have no default keys, which makes them reachable from the keyboard.

[[the-editor]]
== The editor

The editor is a source editor.
The rendered page is shown beside it by the preview; see xref:preview.adoc[The preview].
The Source, Visual and Split buttons beside the tabs switch a page to the visual editor, where you edit the rendered text in place; see xref:visual-editing.adoc[Visual editing].
It provides:

* Syntax highlighting from the AsciiDoc tree-sitter grammars.
The inline grammar is injected into paragraphs, titles, table cells and macro targets.
* Highlighting inside source blocks for Rust, Java, JavaScript, TypeScript, Python, Go, JSON, YAML, TOML, shell, SQL and HTML.
XML and Dockerfile blocks are not highlighted yet.
* Folding of sections, delimited blocks and lists, line numbers and soft wrap.
* Diagnostics as you type.
See xref:diagnostics.adoc[Diagnostics].
* Hover on xref, include and image targets, anchors and `+{attributes}+`.
* Completion after `xref:`, `include::`, `image::`, `{` and `#`.
* Undo and redo that treat a run of typing as one step.
Typed characters within 500 ms of each other coalesce.

Tabs follow the active document, so opening a page by any route (the sidebar, link following, the palette or a rename) shows it in a tab.
With the preview docked, the tab strip scrolls to keep the active page's tab in view, including when a page becomes active by following a link or through the outline.

Each tab has an X button that closes it, asking first if the page has unsaved changes.
Tabs are in the order the pages were opened, apart from a preview tab, which takes the place of the one it replaces.
Right-click a tab for a menu that acts on that tab, not necessarily the active one:

* *Close* closes the tab.
* *Close Others* closes every other tab.
* *Close Left* and *Close Right* close the tabs to its left or right.
* *Close Clean* closes every tab without unsaved changes.
* *Close All* closes every tab.

Items that would close nothing are greyed out, such as Close Left on the first tab.
Right-clicking the empty part of the tab bar offers only Close Clean and Close All.
The same commands are in the palette and act on the active tab; see xref:keyboard-shortcuts.adoc[Keyboard shortcuts] for their keys.
When any of the tabs to be closed has unsaved changes, you are asked once, naming them (for example "a.adoc and b.adoc have unsaved changes."): Discard closes them all and Cancel closes none.
Close Clean never asks, since it leaves unsaved tabs open.

The ← and → buttons at the start of the tab bar are Go Back and Go Forward through the places you have followed links to.
Each is greyed out when there is nowhere to go.

[[preview-tabs]]
=== Preview tabs

Browsing to a page opens it in a preview tab, a temporary tab whose title is in italics.
Its tooltip reads "Preview tab — edit or double-click to keep open." and its accessible label is "<name>, preview tab".
Browsing to another page reuses that tab, in the same place in the tab strip, so casual reading does not fill the tab bar.
There is at most one preview tab.

You are browsing when you:

* click once in Navigation or Modules,
* choose a search result, a Problems entry or a row in the Changes panel,
* use Follow Link or Go to Definition on an xref, an include or an image,
* click once on an image in the Files view, or on an image in a module's images in Modules,
* use Back or Forward,
* click a link or a block in the rendered preview, or
* choose Open in a Peek Include.

These open pages as ordinary tabs instead: the Open File dialog, files named on the command line, new untitled pages, Open Settings, and Edit partial in the visual editor.
An Outline entry only moves the caret.

Images share the one preview tab with pages: browsing to an image replaces a preview page, and the reverse.
See <<image-viewer>>.

Browsing to a page that already has a tab only activates that tab.
A page with an ordinary tab is never made a preview tab.

A preview tab becomes an ordinary tab, for good, when:

* its page is edited in any way, whether by typing in the source, visual editing, formatting or any other edit command,
* its page is saved,
* you double-click its tab, or its entry in Navigation or Modules, or
* you choose *Keep Open*, from the tab's context menu, the File menu or the command palette.

Undoing back to the saved text, or saving, does not make the tab a preview tab again.
Keeping a tab open does not reopen the page: its caret, its mode (source, visual or split) and its undo history stay as they were.

A preview tab is kept open instead of being replaced when its page has unsaved changes, has text being composed through an input method, or is pinned in the rendered preview with Pin Preview.
A rendered preview that follows the active page follows the newly browsed page.

Keep Open is not Pin Preview, which fixes the rendered preview on one page, and it is not pinning tabs, which is a separate proposed feature.

Set `editor.preview_tabs` to `false` to turn preview tabs off; see xref:settings.adoc[Settings].
Every page you open then stays open until you close it.
Turning the setting off keeps the current preview tab open as an ordinary tab and closes nothing.
Turning it on leaves existing tabs as they are.
The setting applies when settings are reloaded, without restarting.

[[image-viewer]]
=== The image viewer

An image opens in an image tab inside AdocFoundry.
You can open one by:

* selecting it in the Files view,
* choosing it from a module's images in the Modules panel,
* choosing Open File…,
* naming it on the command line, or
* following an image macro such as `image::logo.png[]` with Go to Definition or Follow Link.

A PDF still opens in the system's viewer when you click it.
Any other binary file is still refused, and opens only through Open Externally.

The formats shown are:

* PNG, with transparency.
* JPEG, with its EXIF orientation respected.
* SVG, static.
* GIF and WebP, showing the first frame only for animated files.
* BMP and ICO.
* TIFF, showing the first page only.

HEIC, HEIF and AVIF open in an image tab that says the image cannot be shown and offers Open Externally.
The file's content decides the format, not its name, so a corrupt file, or a text file named `.png`, shows an error and never a blank panel or text.

==== Image tabs

Image tabs follow the same rules as page tabs.
A single click shows the image in the one reusable preview tab, with its title in italics; double-click it, or choose *Keep Open*, to keep it.
With `editor.preview_tabs` set to `false`, every tab is kept.
Opening an image that is already open activates its tab.

An image tab shows an image icon.
Hovering over a kept image tab shows its full path, and the status bar shows the path of the active image.
Close, Close Others, Close Left, Close Right, Close Clean and Close All work across page and image tabs together.
An image is always clean, so Close Clean closes image tabs.

An image is read-only.
The Source, Visual and Split buttons are not shown, and Save, Undo, formatting and export do nothing to it.
Save All saves pages and never writes image files.
Images are never indexed, checked for problems or previewed as AsciiDoc.
While an image is active, the rendered preview shows only a page that is pinned.

==== Viewing an image

A toolbar above the image shows its format, its size in pixels and the size of the file.
For an SVG the size is its own width and height.
The toolbar has these controls:

* Zoom Out (-), the zoom percentage and Zoom In (+).
* Fit, for Fit to Window.
* 100%, for Actual Size.
* Reload Image.
* Open Externally.

An image first opens whole and centred, and is never enlarged beyond its actual size.
Fit to Window fills the canvas and follows the window when it is resized.
A zoom you have chosen runs from 5% to 3200% in steps of 1.25 times, and is kept when the window is resized.
Scroll or drag to pan.

Actual Size is one image pixel to one screen pixel, so a screenshot appears at the size it was taken, including on HiDPI and Retina displays.
An SVG's 100% is its own width and height in interface units.
SVGs are drawn at up to 16 times, about 2048 pixels on the long side, so they stay sharp when zoomed.

Transparent images are shown over a checkerboard that suits light and dark themes.

Right-click the image for Zoom In, Zoom Out, Fit to Window, Actual Size, Reload Image, Open Externally, Copy Path, Reveal in Files, and Reveal in Finder (Reveal in File Explorer on Windows, Reveal in File Manager on Linux).

Zoom In, Zoom Out, Actual Size, Fit to Window and Reload Image are also in the View menu and the command palette, which offer them only while an image is the active tab.
See xref:keyboard-shortcuts.adoc#image-viewer[Keyboard shortcuts] for their keys.

==== Loading, errors and changes

An image loads in the background, and the tab shows "Loading <name>…" meanwhile.
An error says why: the file cannot be read, is damaged or is not an image, its format is not supported, or it is too large.
It offers Retry and Open Externally.
A file over 256 MB, with either side over 16,384 pixels, or with more than 64 megapixels is refused with a message naming its size.

When the file watcher sees an image change, the tab reloads it.
This covers files inside the workspace folders that are not excluded.
Use Reload Image for an image in an excluded folder or outside the workspace.
If a reload fails, because the file was deleted or is now corrupt, the last pixels stay on screen with a banner saying they are the version that last loaded, and a Retry button.

==== SVG safety

An SVG shows only what it contains.
Scripts never run and links are not followed.
Images it links to, whether local files or web addresses, are not loaded, but images embedded as `data:` URIs are shown.

[[formatting-text]]
== Formatting text in the source editor

Bold (`Cmd-B` or `Ctrl-B`), Italic (`Cmd-I` or `Ctrl-I`) and Code (`Cmd-E` or `Ctrl-E`) toggle a mark around the selection in the source editor, with the same keys as the visual editor.
Highlight has no key and is in the command palette.
They work in Source mode and on the source side of Split mode.

* The constrained form (`+*bold*+`, `+_italic_+`, `+`code`+` and `+#highlight#+`) is used where it is valid.
Where it cannot be, such as part of a word (`+un**break**able+`), the unconstrained form (`+**+`, `+__+`, `+``+` and `+##+`) is used.
* Spaces at the edges of the selection stay outside the mark.
* If the selection is already marked, with its delimiters just inside or just outside it, the command removes the mark.
Another mark's delimiters do not count, so bolding an italic word gives `+_**word**_+`.
* A selection over several lines marks each line on its own, because a mark never runs across lines, which might be list items or block delimiters.
Blank lines are skipped.
If every line is already marked, all are unmarked; otherwise only the unmarked lines are marked.
* With nothing selected, an empty pair of delimiters is inserted with the caret between them, ready to type.

The marked text stays selected afterwards, so pressing the key again undoes the mark.
Each toggle is one undo step.

[[inserting-blocks]]
=== Inserting blocks and links

Insert Table, Insert Code Block, Insert Admonition, Insert Image and Insert Link also work in the source editor, in Source mode and on the source side of Split mode.
They are in the command palette, and Insert Link keeps its key (`Cmd-Shift-L` or `Ctrl-Shift-L`).
Each is one undo step.

* Insert Table, Insert Admonition, Insert Image and Insert Code Block write the block's skeleton at the caret.
It is the same source the visual editor writes, so inserting a table and typing into it gives the same source in either editor.
If the caret is in the middle of a line, the line is split, and a blank line is added before and after the block where needed.
* Insert Table writes a 2×2 table with a header row (`+|Column 1 |Column 2+`), with "Column 1" selected to type over.
* Insert Admonition writes `+NOTE: Note.+` with "Note." selected.
* Insert Code Block writes an empty `----` listing block with the caret inside.
With lines selected, the block goes around those whole lines, and they stay selected.
A selection that ends at the start of a line does not take that line.
* Insert Image writes `+image::[]+` with the caret where the target goes.
The visual editor asks for the target and alt text in a dialog instead.
* Insert Link wraps the selected text as `+link:[text]+`, escaping any `]` in it, with the caret where the target goes, ready for you to type a URL.
With nothing selected it inserts `+link:[]+`.
The visual editor opens a dialog asking for the target and text instead.

[[format-table]]
== Formatting a table in the source editor

Format Table, in the command palette and in the Format menu of the application menu, lines up the cells of the `|===` table at the caret.
It has no key binding.
It pads each cell so that the `|` separators form columns:

[source,asciidoc]
----
|===
|Name|Value

|alpha |1
|beta|22
|===
----

becomes

[source,asciidoc]
----
|===
| Name  | Value

| alpha | 1
| beta  | 22
|===
----

The rendered page is the same before and after, because Asciidoctor strips the spaces around cell text.
Blank lines, escaped `\|` and line endings are kept, and trailing spaces are trimmed.
Formatting is one undo step.
A table that is already aligned is left as it is and adds nothing to the undo history, so formatting twice changes nothing.

Format Table works on tables written one row to a line, with every cell starting with a bare `|`.
It leaves any other table unchanged and says why in a notification:

* A row spread over several lines, or a line that does not start with `|`.
* A cell specifier, such as a span (`2+|`), an alignment (`^|`) or a style (`a|`).
* Rows with different numbers of cells.
* Another separator or format, such as `separator=` or `format=csv`.
* A `cols` attribute with column styles, such as `1l`, because a literal column keeps its spaces.
* A table with no closing `|===`.

Tables shown as text inside listing, literal, passthrough or comment blocks are not tables.
With no table at the caret, the command reports that there is no table there.

== Following links

Cmd-click (Ctrl-click on Linux and Windows), F12 or kbd:[Cmd+Enter] (kbd:[Ctrl+Enter]) on a reference follows it:

* An `xref:` opens the target page and places the caret on the anchor, if there is one.
* An `include::` opens the included file.
* An `+{attribute}+` goes to the place the attribute is defined: the document, an included file, `antora.yml` or the playbook.
* An `image::` opens the image in an image tab; see <<image-viewer>>.
* An attachment opens in the system's default application.

If the target cannot be resolved, the diagnostic is shown and nothing is opened.

=== Back and forward

Every followed link is recorded.
Go Back (`Ctrl-minus`) and Go Forward (`Ctrl-Shift-minus`) move through that history, also available from the arrows in the title bar and at the start of the tab bar.
These two bindings use Ctrl on every platform, including macOS.

=== Peek an include

kbd:[Alt+F12] on an `include::` shows the included file read-only, without leaving the current page.
Use Open from the peek to open it in a tab.

== Find and replace

Find in Workspace (kbd:[Cmd+Shift+F] or kbd:[Ctrl+Shift+F]) searches every file in the workspace.
Regular expression, case-sensitive and whole-word options are available.
Results arrive as the search runs, and clicking one opens it.

Replace in Workspace (kbd:[Cmd+Shift+H] or kbd:[Ctrl+Shift+H]) does not change anything immediately.
It shows a preview listing every change; nothing is written until you apply it.
Applying the preview is one undo step across every file it touches.
It is undone only as a whole, under the rule described in <<Rename a page>>.

The preview shows the text each file will be changed from, so for a page with unsaved edits it shows the editor's text, not the file on disk.
Apply refuses, and changes nothing, if a listed file has changed since the preview was made; make the preview again.

== Rename a page

Rename Page (kbd:[F2]) renames the active page.
AdocFoundry shows a preview that lists the file move and every xref, navigation and include edit needed to keep links working.
Apply the preview to move the file and rewrite the xrefs, nav entries and includes of the file.
An include written through an attribute is left as written.
The moved page's own references keep naming what they named, and their edits appear in the preview with the others.
In a plain document, xref, include and image targets are relative to the page's folder, so moving the page into `guides/` rewrites `+xref:child.adoc[]+` as `+xref:../child.adoc[]+`.
In an Antora page, xrefs, images and `family$` includes are resource IDs relative to the module, so a move within the module changes nothing, while a move to another module, component or version qualifies them: `+xref:other.adoc[]+` becomes `+xref:ROOT:other.adoc[]+`, and `include::partial$p.adoc[]` becomes `include::ROOT:partial$p.adoc[]`.
IDs written with `./` or `../`, and includes written as plain paths, are relative to the page's folder and are rewritten when it changes.
A reference from the page to itself, such as `+xref:index.adoc#top[]+`, keeps pointing at the page in its new place.
Targets written through an attribute, URLs and pure `#fragment` references are left as written.
One undo moves the page back and restores every edit.
A rename, like a workspace Replace, is undone and redone only as a whole.
If one of the pages it changed has been edited since, Undo is refused with a message naming that page; undo that page's later edits first, and the change then undoes as a whole from any of its pages.
Editing one of its pages after undoing the change means it can no longer be redone.
A page you have closed since does not hold the undo back, because closing discarded its unsaved edits.
If the rename cannot be completed, for example because the destination folder cannot be written to, everything already done is undone and nothing is left in the undo history.

[[application-menu]]
== The application menu

The ☰ button at the left of the title bar, before the Back and Forward buttons, opens the application menu.
It is shown on macOS, Linux and Windows.

Clicking it opens the File menu and replaces the button with the name of every menu: File, Edit, Format, View, Go, Git and Help.
With a menu open, pointing at another name opens that menu, and clicking the open menu's name closes it.
Choosing an item, pressing kbd:[Escape] or clicking elsewhere closes the menu and folds the names back into the button.
The arrow keys move through a menu's items and kbd:[Enter] chooses one.

Each item shows its key binding and runs the same command as the key and the palette entry.
The command acts on whatever had focus before the menu opened, the source editor or the visual editor, so Bold in the Format menu marks the visual editor's selection when that is where you were working.

Unlike the palette, the menus keep their shape.
An item whose command cannot run just now is greyed out instead of hidden, for example when no page is open, when the page is not shown in Visual or Split mode, or when the workspace has no Antora component.
A command the build lacks, such as PDF export in a build without Typst, is left out.

File::
Open, save, reload, export to PDF or HTML, close, settings and re-indexing.

Edit::
Undo, Redo, Find in Workspace, Replace in Workspace, Rename Page and Revert Change.

Format::
Marks, links, lists, blocks, images and tables.
The marks, links and the table, code block, admonition and image inserts work in the source editor too; the rest are for the visual editor.
Format Table aligns the table at the caret in the source editor.

View::
The command palette, the editor modes, the preview, change markers and blame, the theme and the read-only window.

Go::
Back and forward, definition, links, peeking an include, moving between changes and opening a page in another version.

Git::
Refreshing status, staging, committing, pushing and the remote links.

Help::
Check for Updates and Show Diagnostics.

[[reporting-a-problem]]
== Reporting a problem

*Help > Show Diagnostics*, also in the command palette as *Show Diagnostics*, opens a dialog with a report for an issue.
It lists the version, the system, the PDF theme and fonts, the tools it found and the settings in force, and holds no page content.
Choose *Copy* to put the report on the clipboard, then paste it into the issue.

The application's report is the one `adocfoundry-cli doctor` prints, with a Display section added.
That section gives the graphics backend (Metal on macOS, DirectX 11 on Windows, wgpu on Linux), the GPU where the platform reports one, the display server on Linux (Wayland or X11), the scale factor, and whether the editor and interface fonts are installed.
A font that is not installed is marked `(not installed, so a fallback is used)`.

The tools are asked for their versions in the background, so the dialog appears once they have answered.
See xref:command-line.adoc#doctor[doctor] for the sections and what they mean.

== Themes

The theme follows the system by default.
Toggle Light/Dark Theme (`Cmd-K Cmd-T` or `Ctrl-K Ctrl-T`) switches immediately, and the `editor.theme` setting fixes it to `light`, `dark` or `auto`.

== The read-only second window

Open Read-Only Window (`Cmd-K Cmd-N` or `Ctrl-K Ctrl-N`) opens a second window that shows the active document read-only and follows it as you edit.
It uses the same multi-window path as the detachable preview; see xref:preview.adoc[The preview].

== Settings and the palette

Open Settings (`Cmd-,` or `Ctrl-,`) opens your user settings file, creating it if necessary.
Saving it applies the change.
See xref:settings.adoc[Settings].

The command palette lists every command with its title.
Bold, Italic, Code and Highlight are listed in every mode.
Insert Table, Insert Code Block, Insert Admonition, Insert Image and Insert Link are listed in every mode too.
The other commands that apply only to the visual editor, such as the list commands, are listed only while the active page is shown in Visual or Split mode.
Commands that need an open page are hidden when none is open, and Antora-only commands are hidden when the workspace has no Antora component.

== The line and column in the status bar

The status bar shows the caret's line and column as `Ln, Col`.
In Visual mode, and in Split mode while the visual side has focus, they follow the visual editor's caret.
Otherwise they follow the source editor's caret.

== The word count in the status bar

The status bar shows the active page's word count and an estimated reading time, such as `120 words · 1 min read`.
A page with one word shows `1 word`, and an empty page shows `0 words`.
When text is selected, the bar shows the selection's words out of the page's, such as `12 of 120 words`.

Only prose is counted: titles, paragraphs, list items, description lists, callout lists, table cells, admonitions, quotes, verses, sidebars, examples and footnotes.
Markup, attribute entries, listing, source and literal blocks, diagrams, formulas, passthrough content and images are not counted, and neither is generated text such as list numbers and table captions.
Content brought in with `include::` is counted as part of the page.

A word is a run of characters between white space that holds a letter or a digit, so a hyphenated word counts once and a dash on its own does not count.
The selection is counted the same way over the text as you typed it, so it can include words from markup.
The reading time assumes 200 words a minute and is rounded up to whole minutes.

The page is counted once it has been unchanged for half a second, so the last count stays shown while you type.
Switching to another tab, or opening a page, counts it straight away.
Only the active page is counted.

== The branch in the status bar

Inside a Git repository the status bar shows the current branch, such as `⎇ main`.
It is the branch of the repository that holds the active document, or of the first root when no document is open.
A detached HEAD shows `⎇ detached @ 1a2b3c4` and a repository with no commits shows `⎇ no commits yet`.
Outside a repository nothing is shown.
When the active page belongs to an Antora component, the bar shows its version and the branch together, such as `product@2.0 · main`, or `product@latest` for a component with `version: ~`.
See xref:antora-support.adoc#versions-and-branches[Versions and branches].
When the branch has a remote-tracking branch on the remote named by `git.remote`, the bar adds the number of commits the remote does not have, such as `⎇ main ↑2` or `product@2.0 · main ↑0`.
Nothing is added while the branch has no remote-tracking branch yet.
The branch and the count update after a commit, a push or a branch switch.
Refresh Git Status (`git.refresh`) in the palette discovers the repositories again, and the `git.enabled` setting turns this off; see xref:settings.adoc[Settings].

[[change-markers]]
== Change markers

A 3-pixel bar at the left edge of the source editor, beside the line numbers, marks the lines changed against the last commit (`HEAD`).
Unsaved edits are included.
Green marks added lines and blue marks modified lines.
A small red triangle between two lines marks where lines were deleted.
The markers follow scrolling, soft wrap and folding, and never move the text.
They update shortly after typing pauses.
The visual editor marks changed blocks in the same colours; see xref:visual-editing.adoc#changed-blocks[Changed blocks].
Setting `git.show_markers` to `false` hides the markers in both editors; see xref:settings.adoc[Settings].

=== Reverting a change

Clicking a marker opens a card showing the lines as they were in the last commit.
Its heading reads "Before this change", "Added since the last commit" or "Deleted since the last commit".
*Revert Change* puts those lines back as one undo step, and Undo brings the edit back.
*Copy* copies the old lines.
Clicking elsewhere closes the card.

Revert Change (`git.revert_hunk`) is also in the palette and acts on the change at the caret.
It reports "there is no change here" when the caret is not in a change.
Go to Next Change (`Option-Down` or `Alt-Down`) and Go to Previous Change (`Option-Up` or `Alt-Up`) move the caret from change to change, wrapping round at the ends.
They report "there are no changes" when the page has none.

== The Changes panel

The sidebar has a *Changes* tab when a workspace root is in a Git repository.
A folder outside Git has no Changes tab, and a repository with no changes shows an empty panel.
Show Changes (`git.show_changes`) in the palette switches the sidebar to it.

The panel lists the changed files under the roots that are AsciiDoc pages (`.adoc`, `.asciidoc` or `.ad`) or lie in an Antora family directory (`images`, `attachments`, `examples` or `partials`).
Ignored files are never listed.
Each row has the status letters of `git status --short`, the path relative to the root and, for an open document, the number of changes in brackets:

----
 M modules/ROOT/pages/page.adoc (2)
?? modules/ROOT/images/diagram.svg
----

With more than one repository, the files are grouped under each repository's folder name.
Clicking a row's name opens the file with the caret on its first change.
The name of a deleted file is struck through and opens nothing.

[[staging-and-committing]]
=== Staging and committing

Each row has a checkbox, ticked when the file has changes staged.
Ticking it stages the file as it is in the working tree: new and changed files are added and a deleted file is staged as deleted.
Unticking it unstages the file by putting the `HEAD` version back in the index.
The working tree is not touched.

Above the rows, *Stage All* stages every file the panel lists and is disabled when it lists none.
*Commit…* opens the commit dialog and is disabled when nothing is staged.

The commit dialog has:

* a message field, whose first line is the summary, with a note under it such as "Summary: 41 of 72 characters", shown in the warning colour past 72;
* the files that will be committed;
* *Commit* and *Commit and Push* buttons.

The dialog has no option to amend a commit or to create a branch.
After committing, a notification reads `Committed abc1234`, or `Saved 2 files and committed abc1234` when open documents with unsaved edits were saved first.
The change markers and the Changes panel clear, because `HEAD` has moved.

Commit (`git.commit`) in the palette opens the same dialog.
Stage (`git.stage`) and Unstage (`git.unstage`) in the palette act on the active file, and Stage All Changes (`git.stage_all_adoc`) does what *Stage All* does.

Save and Commit (`git.save_and_commit`, in the Document category) saves the active page, stages it and opens the dialog with the message `docs: update <page title>`.
The page title is the document title, or the file name when the page has none.

A commit needs an author.
The name and address come from `user.name` and `user.email` in the usual Git configuration scopes.
Without them the commit is refused with a message that says how to set them:

[source,sh]
----
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
----

A commit with nothing staged is refused with "nothing is staged to commit".
When `commit.gpgsign` is `true`, the commit is made with the `git` executable so that it is signed with your key.

[[pushing]]
=== Pushing

*Commit and Push* in the dialog, and Push (`git.push`) in the palette, push the current branch to the remote named by `git.remote`, `origin` by default.
Pushing runs the `git` executable, so your credential helper, SSH agent and signing setup work unchanged.
A notification reports the result, such as "Pushed main to origin", or shows the error Git gave.

Push never forces and never sets an upstream.
A branch with no upstream is refused with "branch X has no upstream: run `git push --set-upstream origin X` once".
The executable is `tools.git` when set, else `git` on `PATH`.
Without one, the command says "pushing needs the git executable: install Git or set [tools] git".
Staging and committing do not need the executable, apart from signed commits.

[[blame]]
== Blame

Toggle Blame (`git.show_blame`, in the View category) in the palette shows or hides a blame column at the left of the source editor for the active document.
Each visible line shows the short commit id, the author and how long ago the line last changed, such as `abc1234 Paul Snow, 3 days ago`.
A line changed since the last commit, including by unsaved edits, shows `Not committed`.
The column follows scrolling, soft wrap and folding.

With `git.blame_on_hover` set to `true`, resting the pointer on a line's number for 400 ms shows a tooltip such as `abc1234 · Paul Snow · 3 days ago · Fix the install steps`, or `Not committed`.
The setting is `false` by default; see xref:settings.adoc[Settings].

Blame is worked out once for the file as it is in the last commit, in the background, the first time it is asked for.
It is not worked out again as you type: lines you change are shown as not committed.
It is worked out again after a save, a commit or a branch switch.
Times are shown relative to now, such as "just now", "5 minutes ago", "2 hours ago", "3 days ago", "2 months ago" and "1 year ago".

[[remote-links]]
== Links to a line on the hosting site

Open on Remote (`navigate.open_on_remote`, in the Navigate category) opens the caret's line in the browser, on the site that hosts the repository's remote.
Copy Remote Link (`navigate.copy_remote_link`) copies the address instead and says so.
Both are in the palette and have no default binding.

The remote is `git.remote`, `origin` by default.
The link points at the current branch, or at the commit when HEAD is detached.
Remote URLs in the forms `git@host:org/repo.git`, `ssh://git@host/org/repo.git` and `https://host/org/repo` (with or without `.git`) are all understood.

[cols="1,3"]
|===
|Site |Link

|GitHub
|`\https://github.com/org/repo/blob/main/README.md?plain=1#L12`

|GitLab
|`\https://gitlab.com/group/repo/-/blob/main/page.adoc#L3`

|Bitbucket Cloud
|`\https://bitbucket.org/team/repo/src/main/page.adoc#lines-7`

|Azure DevOps
|`\https://dev.azure.com/org/project/_git/repo?path=/page.adoc&version=GBmain&line=7&...`
|===

The GitHub link carries `?plain=1`, which shows the source so that the line anchor works on rendered files such as AsciiDoc.
Azure DevOps uses `GC` and the commit in place of `GB` and the branch when HEAD is detached.

github.com, gitlab.com, bitbucket.org, dev.azure.com, ssh.dev.azure.com and `*.visualstudio.com` are recognised.
A self-hosted site is named in the `[git.hosts]` table of the user settings file, host name to kind:

[source,toml]
----
[git.hosts]
"git.example.com" = "gitlab"   # github | gitlab | bitbucket | azure
----

The commands refuse, with a message, in three cases:

* The repository has no such remote: "the repository has no remote named origin".
* The branch has not been pushed, so `refs/remotes/origin/<branch>` does not exist: "branch main is not pushed to origin".
A local branch that is ahead of its remote still gets a link.
* The host is not recognised: the message asks you to name its kind under `[git.hosts]`.

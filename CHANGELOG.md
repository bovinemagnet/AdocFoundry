# Changelog

All notable changes are recorded here. Versions follow [Semantic Versioning](https://semver.org/).

## Unreleased

### Added

- Tabs can be dragged into another order, pinned, and copy their path (#82). A tab dropped on another takes its place, and Close Left and Close Right follow the order shown. Pin Tab, in a tab's menu, puts it with the other pinned tabs at the start of the strip, a pin in place of its X, which unpins it; Close Others, Left, Right, Clean and All leave pinned tabs open, and the session keeps them. A pinned tab is dragged only among the pinned ones, and any other only after them. The tab menu also has Copy Path, Copy Relative Path (to the workspace folder holding it) and Reveal in Navigation. `adoc-engine` gains `document.pin_tab`, `document.unpin_tab` and `document.move_tab` (`CommandArgs::MoveTab`), `Engine::is_pinned`, `pin_tab`, `unpin_tab` and `move_tab`, and `EngineEvent::TabsReordered`.

## 0.8.0 — 2026-11-09

### Added

- Paste or drop an image into a page (#73). A picture on the clipboard asks for a file name, offering one made from the page's, and goes into the `images` family of the page's module, or outside Antora into the page's `imagesdir` or an `images` folder beside it, with `image::name.png[]` written at the caret: in the source editor the caret is left in the empty alt text, and in the visual editor the image goes after the caret's block, its alt text asked for in the same dialog. Image files dropped on either editor, or copied in a file manager and pasted, go in the same way under their own names, numbered when another picture has the name and used again when the same picture is there; a file the page can name where it is, in its module or by resource id in another, is not copied. It is one undo step, which takes back any file copied unless it has changed since. Text on the clipboard still pastes as text. Images over 64 MiB, and links, are refused. `adoc-engine` gains `edit.place_images`, `ImageSource`, `suggested_image_name` and `pasted_image_path`, and `adoc-model` `NewBlock::Images`.
- The visual editor deletes across blocks (#59). With a selection from one block into another, Backspace, Delete, typing and Enter all work: what is left of the two joins in the first, the blocks between go, and one undo step restores it all. Formatting the selection cuts stays closed, and selecting every character of the blocks removes them with their attributes. It is refused, changing nothing, where it would take something only the source can edit (an include, attribute, conditional or comment), cross the edge of a delimited block or table, or start or end in code, a table cell, a description list or the title. Enter at the start of a paragraph, heading or list item begins a new block before it, written when its first character is typed. Text pasted into a new block, before or after, now stays in it: blank lines and lines that would start another block no longer break out. `adoc-model` gains `Step::InsertBlockBefore` and `Model::takes_block_before`, and `adoc-engine` `VisualValue::NewBlockBefore`.
- Admonitions show their icon with `:icons: font` (#191). In a PDF the label's place holds the kind's Font Awesome glyph, as asciidoctor-pdf draws it: the theme's `admonition_icon_<kind>` `name`, `size` and `stroke_color` over asciidoctor-pdf's defaults (`fas-info-circle`, `far-lightbulb`, `fas-exclamation-circle`, `fas-fire`, `fas-exclamation-triangle`, 24 pt), in a column `admonition_label_min_width` wide or one and a half times the icon, the icon shrinking to fit a short block. The glyphs come from a 7 KB subset of Font Awesome Free 5.15.1 (OFL-1.1), bundled with its notice: the five defaults and 34 common alternatives, by `fas-`, `far-` or Font Awesome 4 name; any other name falls back to the kind's default glyph. A block with an `icon` image of its own, and any admonition under PDF/A-2a, which forbids the glyphs' private-use code points, keep the text label. `admonition_label_min_width` now widens text labels too. HTML follows Asciidoctor: `<i class="fa icon-note" title="Note"></i>` in the icon cell and `<span class="icon"><i class="fa fa-heart"></i></span>` for `icon:heart[]`, and a standalone page, which links no icon font, shows the label in the icon's place. `adoc_pdf::TextRun` gains `font` and `size`.
- PDF export reads the page and cover attributes asciidoctor-pdf reads (#190). `pdf-page-size` (a name, `[8.5in, 11in]` or `8.5in x 11in`), `pdf-page-layout` and `pdf-page-margin` are read before the theme's `page_size`, `page_layout` and `page_margin`, so a book or a profile can set them. `front-cover-image` and `back-cover-image`, else the theme's `cover_front_image` and `cover_back_image`, add a cover page before the title page and after the body: an image macro or a path, a PDF's page among them, fitted with `fit=contain` (the default), `cover`, `fill`, `none` or `scale-down`, an empty value for a blank page and `none` for none, without margins or running content, found and confined to the workspace as the page's other images are. The theme's `running_content_start_at` also takes `title`, `toc` and `after-toc`, front matter pages printing their numbers in roman numerals. `adoc-render` gains `ViewTree::attribute_images`, `IMAGE_ATTRIBUTES` and `attribute_image`, and `adoc-pdf` `TypesetPage::images` (`PlacedImage`).
- Fuzz targets (#194): `fuzz/` is a cargo-fuzz project, outside the main workspace and built with nightly, with targets for the source parser (`parse_source`), acdc-parser on a worker's stack (`parse_dom`), the visual editor's write-back rules under arbitrary steps (`model_roundtrip`), Antora resource ids (`antora_resource_id`), the STEM allow-list (`math_is_safe`) and the Typst string literal writer (`pdf_literal`, through a new `fuzzing` feature of `adoc-pdf`). `python3 fuzz/seed.py` seeds them from the fixtures. A weekly workflow runs each for five minutes and keeps any crash as an artefact; a change to the targets builds them.
- XML and Dockerfile source blocks are highlighted (#66), in the source editor, the preview, the visual editor and PDF export, with the same colours in each. `[source,xml]`, `[source,dockerfile]` and `[source,docker]` take the grammars of `tree-sitter-xml` 0.7.0 and `tree-sitter-containerfile` 0.9.2 with their own queries, which the app registers itself, as gpui-component has none for them. In a Dockerfile a `RUN` line is highlighted as shell, and a heredoc `COPY` into a `.json`, `.yaml`, `.toml` or `.xml` file as that language. Files of these kinds opened in a tab of their own are still plain text.

### Changed

- A test that hangs on CI's Windows runner now fails within ten minutes, by name, instead of holding the job for its two hours (#391). `cargo test` there has hung in a different test each time, naming none of them, which kept v0.6.0 from being published; the Windows tests now run through cargo-nextest 0.9.151 with the `ci` profile in `.config/nextest.toml`. Ubuntu and macOS still run `cargo test`.
- A release no longer runs CI again on a commit whose push to `main` already passed it (#391). The new `ci-passed` job of `release.yml` waits for `main`'s CI run on the tagged commit, which is usually still going when the tag is pushed, through `packaging/ci-result.py`; `publish` takes a passed run as its tests, and the release calls `ci.yml` itself only without one, or when the check fails. This saves CI's runners about an hour and a half per release, and a hang in a second Windows run can no longer hold up publishing.
- Development and test builds keep line tables only (`[profile.dev] debug = "line-tables-only"`, #391), so backtraces still name files and lines but builds no longer write and link the rest of the debug information, which is slowest on CI's Windows runner. A debugger shows no local variables in them; `CARGO_PROFILE_DEV_DEBUG=full` builds with the lot.
- A pause in typing no longer holds the interface to parse the page while the preview or the visual editor is shown (#401). The first to settle starts the index's parse on a worker and waits for it, so the page is parsed once, off the engine thread, for all of them; on a 20,000-line page the pause holds the engine thread for about 0.4 ms instead of 2.65, and the new `settle_preview` benchmark holds it to 2 ms. With either shown, a page is now indexed and diagnosed about 50 ms sooner after typing stops.
- The fidelity test now fails on differences in text, not only in block structure (#92): paragraphs, headings and block titles, table cells, preformatted text, footnotes, link destinations and anchors are compared with Asciidoctor's. The differences that remain are listed in the test, each with its reason, and one that stops happening fails it too. `ViewInline::FootnoteRef` gains `repeat` and `name`.
- An idle app no longer wakes ten times a second (#222): the pump sleeps until the engine's next deadline, or until a worker, the writer, the file watcher or a call into the engine wakes it, at most five seconds. `adoc-engine` gains `Engine::next_due`, the earliest deadline of everything `pump` keeps, which `has_pending` now reads, and `Engine::set_waker`.
- CI and the release workflow build the same way next month as today (#195): every third-party action is pinned to a commit, `tree-sitter-cli`, `cargo-wix`, `cargo-deb` and `cargo-generate-rpm` are built at pinned versions with their dependencies locked rather than at whatever is newest, checkouts keep no credentials, linuxdeploy is a tagged release checked against its SHA-256 before it packs the AppImage, and every job's toolchain is the one `rust-toolchain.toml` names. Every job has a time limit, so a hung test fails within two hours instead of holding a runner for six as the v0.6.0 tag's Windows tests did, and a newer push to a pull request cancels the run it supersedes. `packaging/test_workflows.py` checks all of this.
- The release executables are about 18% smaller (#196): `[profile.release]` uses thin LTO and strips symbols, so the macOS arm64 app is 116.8 MB rather than 142.5 MB and `adoc-ls` 85.8 MB rather than 104.1 MB. Each release job reports its executables' sizes in its summary against the 40 MB budget. Rust is pinned to 1.99.1 in `rust-toolchain.toml`, with `rust-version = "1.99"` to match, so every build uses the same compiler. The app, `adoc-ls` and `adoc-mcp` no longer compile the second AsciiDoc parser, which only `adocfoundry-cli render --parser asciidoc-parser` uses, behind `adoc-dom`'s `comparison` feature. `cargo deny` warns on a crate's second version outside the GPUI, Typst, Mermaid and Git trees, and `renovate.json` sets up weekly, grouped dependency updates once the Renovate app is installed.
- A pause in typing no longer holds the interface while the page is indexed (#238): the page is parsed and its index entry prepared on a worker, and the engine thread only files it and diagnoses, so on a 20,000-line page the pause holds it for about 0.5 ms instead of 8 (14 on a CI runner), and `settle_index` is held to 2 ms. Filing the entry visits only what the edit changed, so typing in prose, which moves every place after it but changes no link, heading or include, touches almost nothing; diagnosing a page looks each file it links to up once rather than once per link, and on disk at most once. `adoc-index` gains `PreparedFile`, `WorkspaceIndex::shared_path`, `insert_prepared` and `Retired`, which the next worker frees.
- Linux packages carry AppStream metadata (#198): the deb, rpm, AppImage and Flatpak install `io.github.bovinemagnet.AdocFoundry.metainfo.xml`, so GNOME Software and KDE Discover show the app's description and releases, and CI validates it and the desktop entry. The Flatpak manifest builds the release's tag rather than `main`, with `cargo xtask bump` writing the tag and the metainfo's release and `packaging/release-version.py` checking both, and runs cargo offline throughout. The release workflow builds the Flatpak from the tagged commit and keeps the bundle with the run.

### Fixed

- Anchors on blocks now reach the page (#92). `[[id]]` and `[#id]` on a paragraph, list, listing or any other block were dropped, so a cross-reference to one led nowhere, in the preview, HTML and PDF; a discrete heading now has its generated id too, numbered when its title repeats. A `<<id>>` to a block with no title reads `[id]`, as in Asciidoctor. A page repeating an id still exports to PDF, links going to the first. Also from comparing more against Asciidoctor: `mailto:` links no longer write the scheme twice and keep their subject and body; a named footnote used twice defines its ids once; a header cell of an AsciiDoc-style column is plain; and a `[quote]` paragraph's HTML has no paragraph inside.
- A wide line in a code block now wraps inside its frame in the preview, and in the visual editor for a block it keeps as source, such as a fenced one (#386). Before, the line ran out past the frame's right edge.
- Staging and committing from the app store what `git add` stores (#98). Before, every file went in as its raw bytes: a CRLF file under `core.autocrlf` or `text eol=lf` was committed with its carriage returns, and showed as changed afterwards; a symbolic link was stored as a copy of its target, and one to a folder or to nothing could not be staged at all; and `ident` and `working-tree-encoding` were ignored. A file under a named `filter`, such as Git LFS, was stored unfiltered and is now refused with a message saying to use `git add`, as filters run commands the repository's configuration names. With `core.symlinks` or `core.filemode` off, a file keeps the mode the index gives it. `crates/adoc-git/tests/git_add.rs` compares the result with the `git` executable.
- A page, partial or image added, deleted or renamed outside the app, in Finder, another editor or by `git rm` or `git mv`, reaches the Antora catalog as soon as the watcher reports it (#402). Before, only the index followed it, so until the whole workspace was indexed again an xref to a new page in another module still warned "Unknown Antora resource" and an xref to a deleted page raised no warning and opened a file that was gone. A page whose `:page-aliases:` changed on disk answers to its new aliases and no longer to its old ones. The file alone is catalogued or forgotten, not its whole component, and the Modules panel, the previews and the open pages' diagnostics follow. `AntoraCatalog::remove_source` now forgets the aliases of what it removes, and `adoc_antora::page_aliases` is public.
- PDF export: a block image with no width is no longer a third larger than asciidoctor-pdf's (#190). It is set at 0.75pt to the pixel, whatever resolution the file records, and held to the column, and an SVG is sized as prawn-svg sizes it: a width without a unit in points, in `px` at 0.75pt, and the column's width with only a view box. The theme's `image_width` now sizes an image that has no `pdfwidth` or `scaledwidth`, before its `width`, and a `width` is held to the column.
- Caption labels follow `figure-caption`, `table-caption`, `example-caption` and `listing-caption`, in the preview, HTML and PDF, instead of always reading Figure, Table and Example (#190): unsetting one (`:figure-caption!:`) drops the label and the number, and listings are numbered only when `listing-caption` is set, as in Asciidoctor. `sectnumlevels` (3 unless set) now limits the section levels `sectnums` numbers, in the text and the table of contents, and `:appendix-caption!:` leaves an appendix its letter alone.
- A page with a carriage return that does not end a line (old Mac line endings) no longer shifts the source of every block after it, which put scroll sync and the visual editor's blocks in the wrong place and could end a block inside a character. Found by fuzzing (#194).
- Typing at the start of a block in the visual editor no longer shows the typed text twice, or panics when the page is written out, where an empty read-only block starts at the same place (a paragraph after an author line, which the model reads as part of the header and the parser does not). Found by fuzzing (#194).
- Making a link with empty text inside bold or other formatting leaves the caret after the link, rather than a selection running backwards. Found by fuzzing (#194).

## 0.7.0 — 2026-11-05

### Added

- The graph shows how long ago pages changed, from Git history (#289): Colour: Age runs the nodes from green, the most recently changed, to red, the oldest; pages unchanged for `[graph] stale_after_days` (365 unless set) are ringed; Stale shows only them and their neighbours; and the side panel says "Last changed 14 months ago". The history is read on a worker, one first-parent walk of `HEAD` stopping when every page is found or after 10,000 commits, again whenever `HEAD` moves; a page moved without an edit keeps its age, and one with changes not committed, on disk or unsaved, changed now. Without Git there are no ages and the options are hidden. `adocfoundry-cli graph --ages` adds `last_changed` to each node. `adoc-git` gains `Repository::last_changed` and `TestRepo::commit_all_at`, `adoc-graph` `LastChanged`, `ColourBy::Age` and `Palette` (in place of `colour_groups` and `node_colour`), and the engine `Engine::page_age` and `has_page_ages`.
- The graph window and the Graph panel lay the graph out as a mind map (#284): Layout in the toolbar moves from Force to Mind Map (left to right) to Radial, and `[graph] layout = "force" | "mind-map" | "radial"` sets where they start. Rooted at a navigation file, the tree is the navigation's nesting; rooted at a page, the page and what lies within the chosen depth, every kind of link both ways. Each node is placed once, at its first and shallowest place, navigation links before xrefs before includes, siblings in title order, and the other links between its nodes are drawn faintly. The root is the selected node, else the active page, else the first navigation file; a double click or Root Mind Map Here in a node's menu roots it elsewhere, and a node's disclosure closes and opens its branch. Nodes glide to their places. `adoc-graph` gains `MindMap`, `TreeStyle`, `GraphSnapshot::restrict` and `Layout::set_targets`, and its bench holds a 2,000-node mind map to the 8 ms budget.
- The graph window groups its nodes by module or component version (#288): Group in the toolbar moves from Off to Module to Component, and `[graph] group = "off" | "module" | "component"` sets where it starts. Grouped, the layout draws each node towards its group and pushes the groups apart, a soft hull labelled with the group's name (`version@component:module`, `Other` outside Antora) is drawn behind each, and clicking the label collapses the group into one node whose links to the rest merge by kind with their counts summed; clicking that node, Enter or Expand Group in its menu expands it again. `adoc-graph` gains `GroupBy`, `Groups`, `group_name`, `GraphSnapshot::collapse` (`GraphKey::Group`, `NodeKind::Group`) and `Layout::set_grouping`, and its layout bench holds the 8 ms budget for 2,000 nodes grouped too.
- `[appearance] font_scale` draws the application's text larger or smaller for big or high-resolution screens (#374): a multiplier of the default from 0.5 to 3, 1 unless set, in the user settings file. It scales the interface, the preview, the visual editor, the graph's labels and the source editor's `[editor] font_size` together, along with the spacing sized to the text, follows every theme, and is applied when the settings are read again. The engine gains `AppearanceSettings::font_scale` and `FontScale`.
- Application themes (#357): View › Select Theme… lists every theme, light first, the chosen ones marked; moving through the list shows each in every window, Enter keeps it and saves it, Escape or any other close puts back what was shown and saves nothing. The native defaults are joined by bundled Catppuccin (Latte, Frappe, Macchiato, Mocha), Tokyo Night (Night, Storm, Moon), Solarized, Everforest and Flexoki, as ported by GPUI Kit, and by your own gpui-component JSON theme sets in the themes folder (`themes` beside the user settings file, or `[appearance] themes_dir`), read again by Reload Themes. Following the system, a chosen theme becomes the light or dark half of the pair and the app now changes with the system's appearance; Appearance: Follow System, Light and Dark set the mode. Choices are saved to a new user-only `[appearance]` table (`mode`, `light_theme`, `dark_theme`, `themes_dir`), changing only those keys and keeping your comments; `[editor] theme` still gives the mode when `[appearance] mode` is not set. A missing theme shows its mode's native default, with a warning, and is used again once it is back. The engine gains `AppearanceSettings`, `appearance.save` (`CommandArgs::Appearance`, `AppearanceChoice`, `Engine::save_appearance`). The bundled themes' licences are in Help › About and the notices file.
- More bundled application themes: Gruvbox, Hybrid, macOS Classic and Mellifluous (a Light and a Dark each), Alduin, Asciinema, Jellybeans and Spaceduck (dark) and Aurora Light, the rest of GPUI Kit's themes whose originals state an MIT or Apache-2.0 licence, with their notices in Help › About.
- `cargo xtask run [--release] [-- <args>]` builds the desktop app and runs it. On macOS it runs from a development bundle in `target/` (`AdocFoundry.app`, with its own identifier and no document types), so the Dock and the app switcher show the anvil icon instead of the generic one of a bare executable that `cargo run` gives (#363).
- The Navigation, Modules and Files panels' right-click menus act on the row (#361). Files: New File… (an empty file of any kind in the folder, opened, undone by Undo), Rename… (AsciiDoc files, rewriting every xref, as Rename Page does), Add to Navigation (a page of a module with a navigation file that no navigation of its component version lists yet, added at the end of the module's `nav.adoc` as one undoable edit) and Export Pages as PDF… (the folder's pages, partials and examples left out). Navigation and Modules: a page's row offers New Page Here… (Navigation: the New Page dialog, the entry going after this one), Rename Page…, Add to Navigation, Export This Level as PDF… (the row's page and its siblings'), Show in Graph, Inspect Impact and Delete File… before the panel's own commands. Exporting pages writes each page to its own PDF in a folder you choose, one after another so a folder is never typeset at once, with one notification at the end. The engine gains `file.new`, `nav.add_page` and `export.pdf_pages` (`CommandArgs::ExportPages`, `EngineEvent::PagesExported`), `Engine::new_file`, `add_to_nav`, `can_add_to_nav`, `export_pages` and `pages_in_folder`.
- Font sets choose the interface, source and reading fonts together (#383): View › Select Font Set… previews each set across the window, Enter keeps it and `[appearance] font_set` saves it. Workshop (IBM Plex Sans and Mono), Reading Room (Source Sans 3, Source Code Pro and Source Serif 4) and Legible (Atkinson Hyperlegible Next and Mono) ship inside the app, under the OFL, and Current keeps the fonts used before. `[appearance.font_sets.<id>]` in the user settings file adds a set of your own. Code outside the source editor uses the source font, and the preview and the visual editor have a reading font of their own.

### Changed

- The live PDF preview typesets a page after an edit in about 9 ms instead of 23 (#188): its compiles keep what Typst memoised for the last 10 compiles, so the blocks an edit left alone are laid out from the cache (an export still empties it); a theme's own font files are read once per process, and again only when one changes, instead of twice on every compile; the theme is kept between compiles and loaded again only when another is chosen or one of its files changes; and finding the source of each line of text on the pages is a binary search, not a scan of every span.
- A pause in typing parses the active page once, on a worker, rather than once each for the preview, the visual model, the word count and the spell check, the visual model's on the UI thread: in split mode with the preview shown and 20 tabs open, the longest the engine thread is held while a 5,000-line page settles falls from about 44 ms to 18 ms. A page's parse no longer copies every open buffer, only shares them (#183).
- The interface, source and reading fonts are Workshop's unless the settings choose otherwise (#383): set `[appearance] font_set = "current"` to keep the fonts used before. `[editor] font_family` and `font_size`, when a settings file names them, still choose the source font.
- Seven dependencies are updated to their latest compatible releases (#362). `merman` 0.9.3 draws Mermaid diagrams with a new HTML parser, and `notify` 8.2.1 reaches macOS's file events through a different backend, so the file watcher on macOS is new code.
- Toggle Light/Dark Theme saves the mode it switches to, rather than changing it for the session only (#357).
- The source editor sends the engine each edit exactly as the editor widget makes it, so typing no longer compares the widget's text with the engine's on every keystroke (#210). The UI framework moves to gpui-component 0.9.0 and gpui-pre 0.3.11, which report the edits. In the Navigation and Modules panels' menu the first Down now selects Expand All, the first command, rather than the menu's title.

### Fixed

- The blame column no longer runs into the page's text (#388): it is as wide as its longest line of blame in the source editor's font, at the font set's size and `[appearance] font_scale`, and its text is clipped to it.
- On a page with a line ending in spaces or tabs, every block after that line was given the wrong place in the source, which the preview's scroll sync and clicks, the visual editor and PDF export's error positions all use, and a short paragraph straight after such a line could be lost: acdc-parser strips that whitespace before parsing, and its offsets were mapped back only for removed carriage returns (#383).
- Visual editor: a typed line beginning `+` and a word in a list item (`+word`) no longer ends the item, and nor does `+ text` (#383, #380). acdc-parser reads such a line as a list continuation, which Asciidoctor does only for a `+` alone, so the editor writes `{empty}` before it.
- `adocfoundry-cli` commands other than `git-status` no longer read Git: opening the workspace read the settings again and turned it back on.
- PDF export: a theme holding an empty list (`custom_list: []`) no longer makes export fail with "unexpected comma" (#276).
- PDF export: an ordered list with an extreme `start` (`[start=9223372036854775807]`, `-9223372036854775808`, or a Greek or Roman style past their range) no longer panics or counts round to negative numbers; counting stops at the ends of the range, and a Roman numeral past 3999 is written in figures (#277).
- PDF export: Typst errors and positions on PDF pages map back to the right line for blocks inside examples, sidebars, admonitions, quotes, list items, description lists, callouts, titled blocks and table cells, rather than to the container's line or another block's (#275).
- PDF export: a short block is kept whole without being measured only when the theme's page holds it, so a listing on small paper or in a large code font breaks across pages rather than running off the bottom (#274).
- Visual editor: typed or pasted text can no longer split a paragraph or list item into two blocks (#176). A line of block attributes (`[note]`, `[.role]`, `[[id]]`) anywhere in the text, not only on its first line, is escaped, as are the comma, colon and exclamation table delimiters (`,===`, `:===`, `!===`) and lines beginning with four of a delimiter's characters (`----and`). A line break typed at either end of a block's text, or beside a line break already there, is left out, since the empty line it would leave ends the block or leaves a list item without text.
- A fragment of an xref to a page in another module (`xref:security:auth.adoc#tokens[]`) is found in the partials that page includes from its own module, rather than looked for in the linking page's module and reported unresolved; an include inside an included file resolves a resource ID (`partial$x.adoc`) against that file's own module, as Antora does, which also corrects the attributes, definitions and preview of pages composed from partials of other modules (#179).

## 0.6.0 — 2026-11-03

### Added

- File › Quit (Quit AdocFoundry on macOS, Exit on Windows; Cmd-Q, or Ctrl-Q on Linux, from any window) asks about unsaved pages as closing the window does, titled "Save changes before quitting?", and quits once answered; a quit the system asks for (logging out, the Dock) still keeps unsaved text for Recover Unsaved Changes. On macOS the menu bar has the app menu: About AdocFoundry, Settings…, Services, Hide AdocFoundry (Cmd-H), Hide Others (Cmd-Alt-H), Show All and Quit AdocFoundry. Until now nothing quit the app on macOS but the Dock (#354).
- Delete File (File menu, a tab's menu, Delete… in the Files panel's menu) deletes a file of the workspace after listing what removing it would break, worked out by Inspect Impact while it asks: the pages that include it, the references to it with where each is written, the navigation that lists it and the PDF profiles that publish it. The file is moved aside into the app's state folder, not destroyed: the notification's Undo, or Edit › Undo Delete, puts back the latest deletion and reopens it; deletions from earlier sessions are removed after `[history] keep_days` (#100).
- The user guide's MCP server page shows how to connect `adoc-mcp` to Claude Code, Claude Desktop, Codex, VS Code, Cursor, Gemini CLI and Zed, over standard input and output and over HTTP, with the binary's full path on each platform (#353).
- The impact inspector (#311, Impact 5/5): Inspect Impact (Edit menu, palette, a page tab's and the Files panel's menus) analyses a page or partial as if it were removed, without removing it: the references that would break (with where each is written), the pages that include it, the navigation that lists it and the PDF profiles that publish it, which #100 asked to see before a page is moved or deleted. Git › Analyse Impact of Changes compares `HEAD` with the working tree and unsaved edits, and Git › Compare Revisions… two refs. - Optional auto-save: `[editor] auto_save = "after_delay"` saves a page a second after its last edit, and `"on_focus_change"` when you leave its tab or the window. It is off by default, and never overwrites a file changed on disk (#76).
- The status bar shows the active page's word count and reading time, for example `120 words · 1 min read`, or the words in the selection (#77).
- File › Export Page to HTML… writes the page as one HTML file, as `adocfoundry-cli render` does, with its unsaved edits and with local images and diagrams embedded (#78).
- Format › Format Table lines up the `|` separators of the table at the caret as one undo step, and leaves a table it cannot format safely as it is, saying why (#84).
- Insert Table, Code Block, Admonition, Image and Link work in the source editor as well as the visual editor, each as one undo step (#83).
- Problems inside `antora.yml` are reported at their lines, as warnings: a missing `name` or `version`, a top-level key Antora does not use, a `nav` entry naming a file that does not exist, and an attribute value that is a list or mapping (#67).
- `[tools] dot`, `plantuml` and `d2` set the paths of Graphviz, PlantUML and D2, for an app started from the Dock, which does not see a shell's `PATH` (#64). `[tools] diagram_timeout` (30 seconds by default) stops a diagram tool that runs too long or writes more than 32 MB, and at most four diagrams render at once (#94).

### Changed

- Faster on long pages and large workspaces (#200–#209):
  - A keystroke no longer copies the page or parses it again, so typing in a long page costs about what it does in a short one, and only the views a change affects are redrawn (#201, #202).
  - The visual editor and the preview lay out only the blocks in view, so long pages open and scroll without waiting for the whole page (#203, #204).
  - Saves, recovery records and the app's state files are written off the UI thread, and Git's change markers are diffed against `HEAD`'s text read once, not on every change (#205, #207).
  - At start-up, folders are watched and indexed off the UI thread, and the last session comes back after the window is first drawn, building each page's visual editor only when its tab is shown (#206).
  - Quick Open keeps its list between keystrokes, Find in Workspace streams its results from a worker and stops at 10,000 matches, and indexing a large workspace needs about a quarter of the memory it did (#208).
  - The Problems panel is worked out by the engine, the whole workspace on a worker, instead of while the sidebar is drawn, and typing waits for a pause before updating the index (#181, #182).
- A change made to several files at once (a page rename or Replace All) is undone and redone only as a whole: undo is refused, naming the page, while a page it changed has been edited since (#95).
- Releases: a tag that disagrees with the version in `Cargo.toml`, `src/docs/antora.yml` or this changelog fails before anything is built, and a release is published only once CI passes on the tagged commit (#97, #193).

### Fixed

- PDF export reads `index_columns` for the number of index columns, as asciidoctor-pdf does, instead of `index_column_count`; a theme that set it no longer fails to typeset (#106).
- Bold, italic, monospace and highlighted text broken over two lines of a paragraph is highlighted in the editor.
- On Linux the app's windows show the AdocFoundry icon in the task bar and window switcher instead of the desktop's placeholder: every window now has the app id `io.github.bovinemagnet.AdocFoundry`, which the desktop entry's name and `StartupWMClass` match (#153).
- Antora resource ids with a version before a module or path are read as Antora reads them: `2.0@index.adoc` is version 2.0 of the current module, and `2.0@security:index.adoc` module `security` of it (#172).
- Insert Column and Delete Column handle `cols` given as a count, such as `[cols=3]` (#173).
- Anchor ids written with a role, an option or `id=` (`[#intro.lead]`, `[#intro%collapsible]`, `[id=intro]`) are indexed, so references to them resolve and Rename Anchor rewrites them in place (#174).
- Typing straight after a save or auto-save no longer reports the editor's own write as a change on disk (#180).
- A PDF theme that extends itself, directly or through another theme, is refused with the chain of files instead of crashing the app (#189).
- HTML and PDF export keep block attributes and options: list numbering styles, table options, image placement, collapsible blocks and vertical cell alignment (#186).
- When two indexes of the workspace finished out of order, the older could replace the newer; it is now dropped (#93).

## 0.2.1 — 2026-10-25

### Security

- The MCP server now confines what a page reads, not only the paths its tools are given. Before, rendering or exporting a page inside the roots read whatever its includes, images and PDF theme named outside them (such as `include::../outside.adoc[]`). External diagram tools are not run by the MCP server, since they read files of their own.

### Fixed

- Saving no longer writes over a change made to the file outside the editor. The engine refuses with a save conflict; the app asks whether to reload the file's version or overwrite it, and the CLI and MCP server return the conflict. Two commands, Reload from Disk and Save, Overwriting the File on Disk, make the choice explicitly (#88).
- Saves write a temporary file and rename it over the page, keeping its permissions and any symbolic link, so a failed write cannot leave a truncated file.
- A rename whose file move fails leaves nothing changed: the reference edits already made are undone, files already moved are moved back, and nothing is left in the undo history. Every move is also checked before anything changes, so a destination inside a file is refused at once (#89).
- Applying a Replace All or rename preview is refused when a file it edits has changed since the preview was made, instead of editing the new text at the old offsets. The confirmation shows the text the edits were computed against, the buffer for an unsaved page (#91).
- Renaming or moving a page rewrites its own references as well as those that name it, so its xrefs, includes and images keep naming what they named: relative to its new folder in a plain document, or qualified with the old module when an Antora page moves to another module, component or version. A reference from the page to itself now keeps pointing at it (#90).

## 0.1.0 — 2026-10-24

The first release: the four phases of the editor, and the release-readiness work of Phase 5.

### Editor (Phase 1)

- A source editor for AsciiDoc laid out the Antora way: components, versions, modules and navigation in the sidebar, with tree-sitter highlighting, folding and outline.
- Link following for xrefs, includes, images, attachments and attributes, across components and versions, with hover and completion.
- Diagnostics for unresolved references, unknown modules and components, duplicate anchors and invalid descriptors, in a Problems panel.
- Workspace search and replace, and page rename that rewrites the xrefs, nav entries and includes that name the page, each one undo step.

### Preview (Phase 2)

- A native rendered preview, docked or in its own window, pinned or following the active page, with scroll sync and click-to-source.
- Diagrams rendered in process (Mermaid) or through optional tools on `PATH` (Graphviz, PlantUML, D2), cached by checksum.

### Visual editing (Phase 3)

- WYSIWYG editing of paragraphs, headings, lists, tables and inline formatting, writing the smallest source edits, with read-only blocks for constructs it cannot edit safely.
### Git

- Changed-line markers in both editors, a Changes panel with revert hunk, branch-aware Antora versions, blame on hover, open on the remote, and stage, commit and push (#2).

### PDF export (Phase 4)

- Pages as articles and component versions as books, typeset in process by Typst, styled by asciidoctor-pdf themes loaded as asciidoctor-pdf loads them.
- PDF/A-2a and PDF/UA-1 on request.

### Phase 5

- STEM typeset from AsciiMath and LaTeX in the PDF, the preview (block formulas as images, inline formulas in a tooltip) and the HTML backend, with the source as each formula's alternative text; a formula that cannot be converted shows as its source with a warning naming its line.
- `adoc-ls` runs on the engine: the same diagnostics as the app, references, file and anchor renames, `adoc.checkWorkspace` and `adoc.exportPdf`. Existing clients keep working: the binary, `--stdio` and the preview command ids are unchanged. The default build has neither Typst nor Git; `--features typst,git` adds them.
- `adoc-mcp`: an MCP server over stdio for assistants and tools, read-only unless started with `--allow-write`.
- Fixes: the status bar no longer shows Indexing… on every keystroke (#19); the palette lists only commands that apply (#17); the active tab stays in view (#13); the status bar follows the visual caret (#15); long diagnostics show in full on hover (#18); word movement and double-click selection in the visual editor (#14); code blocks highlighted in the visual editor (#16); description lists tagged as lists in PDF/UA (#31); tag directives dropped from tagged includes and callouts (#33); pages with `subs=` on an include or a tab after a section title's `=` no longer show as source (#32); footnotes placed as asciidoctor-pdf places them (#35); a 1,833-page book exports in about half the memory and a quarter of the time (#34).
- Found before the release: an image that cannot be read is shown as its alt text with a warning, as a missing one is, instead of failing the export; special sections (preface, glossary, bibliography and the like) are not numbered and appendices are lettered (`Appendix A:`), in the preview, HTML and PDF; a PDF viewer's page labels match the printed page numbers, with the front matter in roman numerals; a single page's references to other pages link to their full address on the site, which can come from the playbook's `site.url`; `normalize_path` keeps leading `..` components; and spans in files with CRLF line endings, as Windows writes them, cover the right text.
- Diagrams and STEM render locally, in Rust or through tools on `PATH`; `cargo xtask layers` checks that no crate but the app's can reach an HTTP client (#3).
- CI on Linux, macOS and Windows, with the asciidoctor-pdf comparison and veraPDF validation (#27).
- Packages for macOS (DMG, signed ad hoc), Windows (MSI and zip, unsigned) and Linux (AppImage, deb, rpm), each with the app and the three command-line tools, smoke-tested on each platform. Developer ID signing and notarisation follow in a later release.
